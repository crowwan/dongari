# 동아리 회계 디자인

디자인 의도를 적는 문서. **값은 토큰 파일에만 둔다** (macOS `DesignSystem/Tokens.swift`, Web `tokens.css`).
실제 모습은 디자인 카탈로그(개발 모드)에서 확인한다.

## 컨셉

> 2026-10-07 디자인 개편 확정 — 기준 시안: https://claude.ai/artifact/MSDNF1M41QotjmG49VXvYh , 결정: `docs/decisions/004-design-renewal.md`. 아래 토큰·컴포넌트 표는 개편 이슈에서 이 시안대로 갱신한다.

어머니가 돋보기 없이 쓰는 큰 글씨 가계부. "맑은 은행 앱" — 옅은 회청 바탕 위 흰 카드, 크고 굵은 숫자, 테두리 대신 면과 여백. 강조색은 차분한 짙은 청록 하나이고, 꾸밈 없이 "지금 잔액"이 먼저 보인다.

## 원칙

- 글자는 크게: 본문 18px 이상, 금액 24px 이상, 잔액 32px 이상(지금 34). 14px 미만 금지(가장 작은 글자 16).
- 글자 위계는 세 단계, 크기와 두께만으로 나눈다: 화면 제목 > 질문·카드 제목 > 보조 이름·안내. 아래 "타이포 위계와 간격 규칙".
- 묶음은 여백으로: 묶음 사이 간격이 묶음 안 간격보다 확실히 넓다 (`--group-gap` > `--stack` > `--stack-tight`).
- 누르는 곳은 56px 이상, 기호만 있는 버튼 금지(항상 글자 포함). 예외: 월 넘기기 ‹ › 는 ADR 003 시안대로 기호를 보이되 화면 읽기 이름은 "이전 달"/"다음 달", 가운데 달 글자와 한 줄로 읽힌다.
- 한 화면에 주 버튼 하나. 위에서 아래로 한 방향 흐름.
- 익숙한 말: 회계 담당자가 쓰는 "수입/지출", "잔액", "작년 이월금", "내역". "보고서" 대신 "월 정리"·"올해 결산".
- 차분한 색: 강조색은 짙은 청록 하나(주 버튼 채움, 보조 버튼은 옅은 청록 면). 수입 금액은 차분한 초록 + `+`, 지출 금액은 본문색 + `−`. 원색 파랑·빨강 채움은 쓰지 않는다 (2026-10-06 결정, #25 에서 토큰 반영).
- 위험(지우기)·오류만 차분한 빨강 하나를 따로 쓴다. 금액에는 쓰지 않는다.
- 면으로 묶는다: 카드·버튼·입력칸은 테두리 대신 면 색으로 구분하고, 그림자는 쓰지 않는다. 선은 카드 안 줄 구분과 아래 고정 영역 위쪽에만.
- 색만으로 구분하지 않는다: 수입/지출은 부호(+/−), 선택은 채움 + 굵기, 비활성은 점선·면 없음, 오류는 테두리 + 문장.
- 시안: https://claude.ai/artifact/7ueYA5NyqE5TkLEpk6DDPg · 시제품: https://claude.ai/artifact/KfbCpZBE6H42ZUdBJSLRvE

## 토큰 역할

값은 `src/styles/tokens.css` 에만 있다.

### 색

| 토큰 | 역할 | 이유 |
|---|---|---|
| `--bg` | 화면 바탕 | 옅은 회청. 흰 카드가 떠 보이고 순백 바탕보다 눈부심이 적다 |
| `--surface` | 카드, 잔액 카드, 확인 창, 위쪽 글자 버튼, 월 넘기기 버튼, 아래 고정 영역 | 읽을 덩어리를 바탕과 면으로만 구분 (선·그림자 없음) |
| `--fill` | 안 고른 칩, 입력칸, 비활성 버튼의 면 | 바탕 위에서도 흰 카드 안에서도 "여기를 누르거나 적는다"가 보이는 회색 면 |
| `--line` | 카드 안 줄 구분, 아래 고정 영역 위쪽 선, 비활성 점선 | 묶음은 여백으로 나누고 선은 꼭 필요한 곳에만 아주 옅게 |
| `--ink` | 본문 글자, 큰 숫자 | 순검정 대신 짙은 회청 검정 |
| `--muted` | 보조 글자(설명, 단위 "원", 위쪽 글자 버튼, 화살표) | 투명도 대신 단색으로 정해 어느 면에서도 대비가 일정 |
| `--faint` | 가장 옅은 글자(잔액 보조 줄, 예시 글자, 비활성 글자) | 세 번째 단계. 그래도 모든 면에서 AA |
| `--primary` | 주 버튼·고른 칩 채움, 보조 버튼 글자, 포커스 링, 입력칸 포커스 테두리 | 앱의 단 하나의 포인트 색(짙은 청록). 한 화면에 주 버튼 하나 |
| `--primary-soft` | 보조 버튼 면([N월 정리 보기]) | 주 버튼과 같은 계열이라 위계만 낮추고 색이 늘지 않는다 |
| `--on-accent` | 청록 채움 위 글자 | 채움 색이 테마마다 바뀌어도 대비를 맞추는 짝 |
| `--income-amount` | 수입 금액 글자 | 차분한 초록. 부호 `+` 와 같이 쓴다. 버튼 채움에는 쓰지 않는다 |
| `--expense-amount` | 지출 금액 글자 | 본문색과 같다. 지출은 일상이라 경고처럼 보이지 않게, 부호 `−` 로 구분 |
| `--danger` / `--on-danger` | 위험 버튼 채움과 그 글자, 위험 글자형, 오류 문장·테두리, [설정] 점 표시(#9) | 지우기·오류·"할 일 있음"만의 차분한 빨강. 금액 색과 겹치지 않는다 |
| `--warn-bg` | 안내 띠 바탕(저장 실패, 시작 안내) | 노란 면으로 "알아 둘 것"을 구분하되 글자는 `--ink` 그대로 |
| `--scrim` | 확인 창 뒤 어둡게 가리기 | 확인 창에만 집중하게. 이미지 위 딤드에는 쓰지 않는다 |
| `--pressed` | 눌린 동안의 면(안 고른 칩, 위험 글자형, 위쪽 글자 버튼, 월 넘기기, 장부 줄) | 폰엔 hover 가 없어 눌림 색이 "눌렸다"는 유일한 신호. 위 글자 대비 AA 유지 |
| `--primary-pressed` / `--primary-soft-pressed` / `--danger-pressed` | 눌린 동안의 채움(주 버튼·고른 칩 / 보조 버튼 / 위험 버튼) | 같은 색 계열에서 한 단계 진하게(다크는 밝게). 글자 대비가 유지되거나 커진다 |

이전 `--income`/`--expense`(원색 파랑·빨강 채움)와 그 눌림 토큰은 #25 에서 지웠다. 금액 글자는 `--income-amount`/`--expense-amount`, 위험·오류는 `--danger` 로 나눴다.

## 타이포 위계와 간격 규칙

#42(2026-10-07) 사용자 피드백 "항목 이름의 크기와 굵기로 구분되게"에서 정했다. 기준은 개인 디자인 시스템(`~/Works/personal/design-system/CONCEPT.md` §4-2·§4-3)의 역할 구조이고, 토큰 파일을 가져오지 않고 역할과 이름만 `tokens.css` 에 옮겼다.

**글자 위계 3단** — 크기와 두께만으로 나눈다 (색은 보조 이름에만 `--muted`)

| 단계 | 역할 토큰 | 쓰는 곳 |
|---|---|---|
| 1 화면 제목 | `--text-title-*` (Bold) | 화면마다 하나 |
| 2 질문·카드 제목 | `--text-heading-*` (Bold) | 내역 적기 질문 넷("얼마인가요?" 금액 칸 이름 포함), 시작 화면 "동아리 이름"·"작년 이월금", 설정 카드 제목, 월 정리 "수입"/"지출" |
| 3 보조 이름·안내 | `--text-label-*` (Medium, `--muted`) / `--text-caption-*` (Regular, `--muted`) | "직접 적기", 설정 카드 안 입력칸 이름 / 보조 설명 |

- 입력칸 이름(`TextField`·`MoneyInput` `label`)은 기본이 2단계(질문 제목 급)이고, 질문 아래 딸린 칸이나 카드 제목 아래 칸은 `labelRole="label"` 로 3단계로 낮춘다. 화면 읽기 이름은 그대로다.
- "직접 적기"는 placeholder 로 옮기지 않고 보이는 보조 이름으로 남겼다: 큰 글씨 사용자는 적기 시작하면 사라지는 placeholder 를 놓치기 쉽고(`--faint` 색), 칸 이름이 늘 보여야 "여기에 적는다"가 남는다. 대신 질문처럼 보이지 않게 한 단계 작고 Medium·회색으로 낮췄다.

**간격 — 묶음 사이 > 묶음 안** (선은 쓰지 않는다)

`--stack-tight`(질문 제목 ↔ 답) < `--stack`(답 안 요소 사이) < `--group-gap`(질문 묶음·카드 사이) < `--section-gap`(큰 구획). 묶음이 여럿인 화면은 `.screen--groups` 로 묶음 사이를 `--group-gap` 으로 둔다. 질문 제목 ↔ 답을 DS 와 같은 8px 로 둔 것은 22px 굵은 제목이 56px 버튼 바로 위에 붙어야 "이 질문의 답"으로 읽히기 때문이다.

### 토큰 예외: 올해 결산 양식

`src/features/report/sheet/*` 는 색·글자 크기를 토큰 대신 **인라인 hex·px** 로 쓴다 (`sheetStyles.ts`). 앱 화면이 아니라 사진으로 저장해 단톡방에 올리는 v1 종이 양식이라 테마·토큰이 바뀌어도 v1 과 똑같이 흰 종이·검정 글자·회색 선이어야 하고(SPEC-003 AC-7), 사진을 만드는 html2canvas 1.4 가 oklch() 같은 최신 색 문법을 읽지 못해 v1 때부터 평범한 hex 로 그렸다. 글자(11~14px)도 v1 양식 크기라 14px 미만 금지 기준의 예외이고, 대신 화면에서는 두 손가락으로 확대해 본다.

### 사진으로 저장할 때의 모양

- 월 정리 사진은 화면 모양(토큰)을 그대로 쓰되, 사진으로 그리는 복사본에만 `data-theme="light"` + `data-capturing` 을 단다. 그래서 다크 모드에서 저장해도 흰 바탕·검정 글자다. 흰 바탕 위에서는 흰 카드가 면으로 구분되지 않으므로 사진에서만 카드 둘레에 `--line` 선을 두른다 (`report.css`).
- 올해 결산 사진은 화면에서 줄여 보이던 양식을 줄이지 않은 360px 그대로 2배로 그린다.

공통 규칙: 누르는 곳 `--touch-min` 이상, 포커스 링 보임, 그림자 없음, 컴포넌트는 토큰 변수만 쓰고 `className`·`style` 을 받지 않는다. 루트에 `data-testid`, 상태가 있으면 `data-state`/`data-variant`/`data-kind`.

## 접근성

- 다크 모드: 시스템 설정을 따른다. `data-theme="light" | "dark"` 를 단 요소 안에서는 그 테마로 고정(카탈로그 전환 토글이 이 방식). 다크는 같은 역할을 유지한 채 채움 색을 밝게, 채움 위 글자를 어둡게 뒤집는다.
- 동작 줄이기: `prefers-reduced-motion` 이 켜져 있으면 나타남 효과와 색 전환을 쓰지 않는다 (눌림 색은 전환 없이 바로 바뀜).
- 대비: 라이트·다크 모두 글자는 쓰이는 모든 면(바탕·카드·회색 면·눌림)에서 WCAG AA(4.5:1) 이상, 포커스 링·오류 테두리는 3:1 이상. 측정 결과는 #25 PR 에 있다.
- 수입/지출은 색 + 부호(+/−), 선택된 칩은 색 + 굵기, 비활성은 점선·면 없음으로 구분한다.
