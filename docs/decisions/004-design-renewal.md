# 004. 개인 디자인 시스템 적용과 "하나씩 채우기" 입력

## 상황

v2.0 미리보기 QA 에서 사용자 피드백:
- 내역 적기의 질문 구분이 약하다(#42 에서 위계·간격만 먼저 고침).
- 색이 마음에 들지 않는다 — 푸른 회색, 다크 모드 민트가 튐.
- 선택 버튼(월 12칸·수입/지출·항목)이 "블록 같고 단조롭다".
- 아이콘이 보기만 해도 뜻이 통했으면 한다.
- 글씨가 좀 크다.

조사(토스 TDS Mobile, 토스 큰 글씨 모드 사례, M3/HIG 세그먼트 2~5개 원칙, W3C WAI 고령 사용자, NN/g 시니어 사용성)와 개인 디자인 시스템(`~/Works/personal/design-system/CONCEPT.md`) 규칙을 대조했더니, dongari 는 디자인 시스템의 색·글자 역할·여백 의미 규칙을 따르지 않고 있었다.

## 결정

- 개인 디자인 시스템 규칙을 따른다: 순수 회색 계층, 브랜드(짙은 청록)는 화면마다 주 버튼 하나에만, 글자 크기 기본값(짝수, 본문 16·보조 14, 제목 24·질문 20·잔액 30), 여백 의미 토큰, 좌우 여백 24. 글꼴 Pretendard. 폰 글자 크기 설정을 따르게 rem.
- 컴포넌트는 토스 TDS 패턴을 참고: 원형 아이콘 + 두 줄 + 오른쪽 금액 줄(ListRow), 둘 중 하나는 한 몸통 스위치(세그먼트), 많은 것 중 하나는 아래에서 올라오는 선택 창(바텀시트) 또는 아이콘 목록, 아래 고정 주 버튼.
- 아이콘은 Lucide 계열 보편 모양, 항목 아이콘은 이름으로 자동.
- 내역 적기는 **하나씩 채우기**(점진적 노출): 무엇 → 얼마, 답은 위쪽 알약으로 쌓이고 누르면 고침. 고치기는 펼친 모양.
- 시안: https://claude.ai/artifact/MSDNF1M41QotjmG49VXvYh

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 한 화면 네 질문 (지금) | 전체가 한눈에, 순서 자유 | 무엇부터 할지 판단 필요, 키패드가 아래 칸을 가림, 블록 격자 |
| **하나씩 채우기 (채택)** | 지금 할 일 하나, 금액 칸이 늘 키패드 위, 자주 쓰는 항목이면 누름 횟수 감소 | 자주 쓰는 사람에겐 단계가 보임(기본값·자동 선택으로 상쇄), 고치기는 별도 모양 |
| 본문 18 유지 | 더 크게 읽힘 | 사용자 "크다" 피드백, 디자인 시스템과 다름 → rem 으로 폰 설정 확대에 맡김 |

## 결과

- 쉬워지는 것: 화면마다 같은 부품(줄·스위치·선택 창·주 버튼)만 조합. 디자인 시스템과 dongari 토큰이 한 체계.
- 어려워지는 것: 내역 적기 화면과 테스트를 다시 짠다. 기존 `ChoiceChip` 격자 사용처를 바꾼다. 글자 크기를 줄여 AC-11(14px 미만 금지)은 유지하지만 SPEC-001 "본문 18" 기준을 바꿨다.
- 다시 볼 조건: 사용성 테스트(AC-13)에서 어머니가 하나씩 채우기를 어려워하거나 글자가 작다고 하면 다시 본다.
