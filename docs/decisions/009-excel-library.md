# ADR 009: 엑셀 읽고 쓰기 — SheetJS CE 를 필요할 때만 불러온다

- 상태: accepted
- 날짜: 2026-11-23
- 관련: [SPEC-010](../specs/SPEC-010-dues-and-excel.md), [ADR 001](001-storage.md)

## 맥락

이모가 엑셀(.xlsx, 2011~2026년, 시트 37개)로 써 온 회비 장부를 앱으로 옮기고(불러오기), 앱 장부를 같은 모양의 엑셀로 내보내야 한다(SPEC-010). 앱은 서버 없이 폰 브라우저에서만 돈다. 그래서 브라우저 안에서 .xlsx 를 읽고 써야 한다.

필요한 것:

- 읽기: 시트 이름, 셀 값(숫자·글자), 병합 셀(월 칸이 병합돼 있다). .xls(옛 형식)도 읽히면 좋다.
- 쓰기: 시트 여러 장, 병합(제목 줄), 열 너비, 잔액 칸에 **수식과 계산한 값을 함께**(카톡·파일 앱 미리보기는 수식을 계산하지 않아 값이 없으면 빈칸으로 보인다).
- 번들: 어머니 폰(갤럭시 A 계열)에서 첫 화면이 느려지면 안 된다. 엑셀은 1년에 몇 번 쓰는 기능이다.

## 고려한 안

| 안 | 읽기 | 쓰기 | .xls | 크기 | 메모 |
|---|---|---|---|---|---|
| **SheetJS CE** (`xlsx`, SheetJS CDN 배포본) | ✅ 병합 `!merges` | ✅ 수식+값(`{f, v}`), 병합, 열 너비 | ✅ | 큼(수백 KB) | 셀 서식(굵게·테두리)은 CE 에 없다. npm 레지스트리의 `xlsx@0.18.5` 는 알려진 취약점(CVE-2023-30533 프로토타입 오염, CVE-2024-22363 ReDoS)이 고쳐지지 않은 옛 판이라 쓰지 않는다 |
| ExcelJS | ✅ | ✅ 서식까지 | ❌ | 더 큼 | 테두리·굵게를 넣을 수 있지만 .xls 를 못 읽고 무겁다 |
| 직접 구현(zip + XML) | 손이 많이 듦 | 손이 많이 듦 | ❌ | 작음 | 병합·공유 문자열·날짜 형식 처리를 다 만들어야 한다 |

## 결정

- **SheetJS CE** 를 쓴다. 설치는 SheetJS CDN 의 tgz(`https://cdn.sheetjs.com/xlsx-<버전>/xlsx-<버전>.tgz`, 작성 시 최신 안정판 — 0.20.3 이상)로 하고 `package-lock.json` 에 주소와 무결성 해시를 남긴다. npm 레지스트리의 `xlsx` 는 쓰지 않는다.
- **필요할 때만 불러온다**(`import('xlsx')` 동적 import). 엑셀 불러오기·내보내기를 누른 순간에 받아서 첫 화면 번들에는 들어가지 않는다. 서비스 워커가 이 조각도 미리 받아 두어(precache) 오프라인에서도 동작한다.
- 앱 코드는 SheetJS 를 한 곳(`features/excel/sheetjs.ts` 같은 얇은 어댑터)에서만 부른다. 엑셀 내용을 장부로 바꾸는 규칙(SPEC-010 "읽는 규칙")은 **SheetJS 를 모르는 순수 함수**가 "시트 이름 + 셀 값 2차원 배열 + 병합 범위"만 받아 처리한다. 테스트는 이 순수 함수에 지어낸 표를 넣어 돌린다(실제 이모 파일은 연락처·계좌가 있어 레포에 넣지 않는다).
- 내보내기는 서식 없이 값·수식·병합·열 너비만 쓴다(테두리·굵게는 범위 밖). 이모 엑셀과 칸 배치가 같으면 충분하다.

## 결과

- 좋음: .xls 까지 읽는다. 수식과 값을 같이 써서 미리보기에서도 숫자가 보인다. 첫 화면 크기는 그대로다.
- 나쁨: 처음 엑셀을 열 때 수백 KB 를 받는다(서비스 워커가 미리 받아 두면 오프라인·두 번째부터는 바로). 내보낸 파일에 테두리가 없다.
- 위험: SheetJS 를 레지스트리 밖에서 받으므로 버전 올리기를 사람이 챙겨야 한다. 받은 파일(신뢰할 수 없는 입력)을 읽으므로 최신 판을 쓴다.
