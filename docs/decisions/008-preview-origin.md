# 008. 미리보기는 다른 출처(Cloudflare Pages)로, 보관 서버 저장 자리도 나눈다

## 상황

본 주소(`crowwan.github.io/dongari/`)·미리보기(`/dongari/preview/`)·실험(`/dongari/lab/`)이 같은 출처라 localStorage(`dongari:v2`·`dongari:keep`·`dongari:guide`)를 같이 썼다. 미리보기에서 QA 로 적거나 지운 것이 어머니 실제 장부에 들어가고, 미리보기 자동 보관(SPEC-006)도 같은 복구 코드로 서버 사본을 덮어쓸 수 있었다. 서비스 워커 범위 간섭(#54)도 같은 출처라 생긴 일이다. (#128, 사용자 결정 2026-10-16 "A가 좋긴하네")

## 결정

미리보기를 Cloudflare Pages 프로젝트 `uri-jangbu-preview`(`https://uri-jangbu-preview.pages.dev/`, 빌드 경로 `/`)로 옮긴다. main 머지 때 `deploy.yml` 이 올리고, 본 주소는 그대로 GitHub Pages 태그 배포다. 보관 서버는 미리보기 출처도 받되 KV 키 앞에 `preview:` 를 붙여(`preview:keep:<id>`, `preview:status:<id>`) 본 자리와 나누고, 지켜보기 요약은 본 자리(`status:`)만 본다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 미리보기를 다른 출처(Cloudflare Pages)로 + 서버 자리 나누기 (택함) | 브라우저가 저장 공간·서비스 워커를 알아서 나눈다. 이미 쓰는 Cloudflare 계정·토큰 재사용 | 토큰에 Pages 권한 추가 필요. 미리보기에서 복구 코드로 본 사본을 가져와 볼 수 없음(기록 파일로) |
| B. 같은 출처에 두고 미리보기 빌드만 저장 키를 바꾸기 | 배포 그대로 | 키를 빠뜨리면 바로 본 장부가 섞인다. 서비스 워커 간섭(#54)은 남는다 |
| C. 미리보기 출처를 받지 않기(미리보기는 자동 보관 꺼짐) | 서버 그대로 | 미리보기에서 자동 보관·복구 코드 흐름을 QA 할 수 없다 |
| 미리보기 배포별 주소(`<hash>.uri-jangbu-preview.pages.dev`)도 받기 | 배포마다 따로 QA 가능 | 받는 주소가 넓어진다. QA 는 고정 주소 하나로 충분 — 받지 않는다 |

## 결과

- 쉬워지는 것: 미리보기 QA 를 어머니 장부 걱정 없이 같은 폰에서 할 수 있다. 릴리스 때 미리보기가 지워지거나 본 주소 캐시 정리가 미리보기 캐시를 지우던 일(#54)이 없어진다.
- 어려워지는 것: 미리보기에서 본 장부 내용으로 QA 하려면 기록 파일로 옮긴다. 미리보기 배포는 Cloudflare 토큰 권한(Pages 편집)에 기댄다.
- 다시 볼 조건: 실험 페이지(`lab/`)도 본 주소와 나눠야 할 일이 생기거나, 배포별 주소로 QA 할 일이 생기면.
