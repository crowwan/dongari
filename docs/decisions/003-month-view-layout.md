# 003. 탭 없이 한 달씩 보는 장부 화면, 입력은 버튼 하나

## 상황

첫 설계(SPEC-001 초안)는 장부·보고서·설정 3탭, 장부 화면 위쪽에 [돈 들어옴] [돈 나감] 버튼, 그 아래 모든 달 기록을 최신 달부터 쌓는 구조였다. 시안을 본 사용자 피드백:

- 버튼이 위에 있어 목록을 내리면 사라지고 엄지로 누르기 멀다.
- "돈 들어옴/돈 나감" 같은 문구가 어색하다. 회계 담당자에겐 "수입/지출"이 자연스럽다.
- 파랑·빨강 강조가 너무 강하다.
- "보고서" 라는 말과 별도 탭이 어색하다. 달마다 그 달 정리를 보는 게 낫다.
- 수입/지출 버튼을 따로 둘 필요가 있는지 의문.

## 결정

- 탭 없음. 장부 한 화면에서 ‹ 9월 › 로 한 달씩 넘겨 본다. [올해 결산]·[설정] 은 위쪽 글자 버튼.
- 화면 아래 고정 [+ 내역 적기] 하나. 수입/지출은 입력 화면에서 고른다(기본값 없음, 자주 쓴 항목 버튼을 누르면 자동 선택).
- "보고서" → 달마다 [N월 정리 보기] + 1년은 [올해 결산](v1 연말 양식 그대로).
- 스타일은 "맑은 은행 앱", 강조색은 짙은 청록 하나, 수입 금액은 차분한 초록 + `+`, 지출 금액은 본문색 + `−`.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 3탭 + 위쪽 버튼 (초안) | 한눈에 다 보임 | 버튼이 스크롤로 사라짐, 탭 이동이 헷갈림 |
| 3탭 + 아래 고정 버튼 | 버튼이 늘 보임 | 아래쪽이 버튼 줄 + 탭 줄로 두꺼움 |
| **탭 없음 + 한 달씩 + 아래 버튼 하나 (채택)** | 화면 이동 최소, 스크롤 거의 없음, 주 버튼 하나 | 다른 달은 화살표로 넘겨야 함, 입력에서 한 번 더 고름 |
| 수입/지출 버튼 두 개 | 입력 단계 하나 줄어듦 | 주 버튼 두 개, 고치기 화면과 모양이 다름, 잘못 누르면 되돌리기 어려움 |

## 결과

- 쉬워지는 것: 어머니가 기억할 화면이 장부 하나. 적기·고치기 화면이 같은 모양.
- 어려워지는 것: 이미 만든 `TabBar`, `BigActionButton`(#5) 은 쓰지 않게 된다. #12 의 3탭 뼈대를 한 달 보기로 바꾸는 작업이 생긴다. 1년 전체 흐름은 [올해 결산] 에서만 본다.
- 다시 볼 조건: 사용성 테스트(SPEC-001 AC-13)에서 다른 달 찾기를 어려워하면 월 목록 보기를 추가 검토.
