# 002. 수기 장부 사진 인식은 직접 만든 작은 모델을 기기 안에서 실행

## 상황

SPEC-004 는 손으로 쓴 한글 장부 사진에서 `월·구분·항목·금액` 을 뽑아야 한다. 손글씨 인식에는 사실상 딥러닝이 필요하지만, 이 앱에서 정확해야 하는 것은 대부분 **숫자**(금액·월)이고, 항목 이름은 장부에서 반복되는 수십 개 안에 있다.

앱은 정적 호스팅(GitHub Pages)이고 데이터는 기기에만 둔다([ADR 001](001-storage.md)).

## 결정

문제를 "한글 손글씨 전체 읽기" 대신 **숫자 분류 + 알려진 항목 이름 분류**로 좁혀, 작은 모델을 직접 학습하고 ONNX 로 바꿔 브라우저 안에서 실행한다. 줄 나누기와 정리 단계는 딥러닝 없이 일반 코드로 만든다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **직접 만든 작은 모델, 기기 내 실행 (채택)** | 비용·서버 0, 사진이 밖으로 안 나감, 오프라인, 어머니 글씨에 맞춰 개선 가능 | 학습 데이터 수집·라벨링 필요, 줄 나누기 구현, 정확도 보장 없음 |
| Claude API + Worker 프록시 | 구현 빠름, 구조화까지 한 번에 | 사진 외부 전송, 사용량 과금, 프록시 운영 |
| 공개 OCR(PaddleOCR 등) + 정리 규칙 | 범용 한글 인식 | 손글씨 정확도 낮아 파인튜닝 필요, 모델 큼 |
| 공개 비전-언어 모델 직접 호스팅 | 범용성 | GPU 서버 비용·운영 |
| TensorFlow.js 로 같은 모델 실행 (2026-10-07 검토) | 브라우저 실행 가능, 작은 숫자 모델은 중급 폰에서도 충분 | 4.22.0(2024-10) 이후 정식 릴리스 없음, 변환기가 Keras 3 에서 깨짐, 후속은 LiteRT.js → ONNX 경로 유지 |
| Tesseract.js (2026-10-07 검토) | 바로 쓸 수 있음, 약 4.5MB, 멀티스레드 불필요 | 공식 FAQ: 손글씨 비지원. 한글 이름은 기대 어려움, 금액 칸 숫자 전용이면 일부 가능 → **기준선 측정용** |
| 기기 텍스트 추출(갤럭시 갤러리 "텍스트 추출") + 글 붙여넣기·공유 받기 + 정리 규칙 (2026-10-07 검토) | 모델 0, 사진이 앱 밖 엔진을 거치지만 기기 안(One UI), 바로 만들 수 있음 | 어머니 손글씨 품질·줄 구조 유지 미확인, 단계가 늘어남(갤러리 → 추출 → 공유) → **SPEC-004 1단계로 채택** |

## 결과

- 쉬워지는 것: 운영 비용 없음, 개인정보 걱정 없음. 어머니가 확인 화면에서 고칠수록 학습 데이터가 쌓인다.
- 어려워지는 것: ML 학습 파이프라인(`ml/`)을 따로 관리. 장부 형식이 바뀌면 줄 나누기를 다시 손봐야 한다.
- 2026-10-07 기술 검토(TF.js·Tesseract.js·PaddleOCR·기기 기능 비교): 런타임 선택보다 줄·칸 나누기와 학습 데이터가 성패를 가른다. 순서를 바꿔 **SPEC-004 1단계는 글 → 정리 규칙 → 확인 화면**(모델 없음)으로 먼저 만들고, 직접 모델은 실제 장부 사진으로 엔진 비교 실험(`/lab`: 갤러리 텍스트 추출·Tesseract.js·PaddleOCR PP-OCRv5) 뒤 2단계로 정한다. 이 결정(직접 모델·ONNX)은 2단계 후보로 유지.
- 다시 볼 조건: 채점용 사진 묶음에서 금액 정확도 90% 를 넘지 못하면 Claude API 안을 다시 본다(`PhotoRecognizer` 구현 교체).
