# 005. 복구 코드로 서버에 암호화 사본을 자동 보관 (Cloudflare Workers + KV)

## 상황

[ADR 001](001-storage.md)은 "기기 저장 + 파일 백업, 서버 없음" 이었다. 파일 백업은 사람이 직접 해야 해서 잊기 쉽고, 폰을 바꾸거나 잃어버리면 마지막 백업 이후 기록이 사라진다. 사용자는 소수(어머니와 가족)이고 운영 부담·비용은 거의 없어야 한다(2026-10-12 사용자: "제일 간단하게 데이터 영속성 추가, 많은 유저 필요없으니까").

## 결정

1. 브라우저에 저장 공간 오래 보관을 요청한다(`navigator.storage.persist()`, #93).
2. 앱이 처음 만든 **복구 코드**(무작위 16자, 80비트)를 열쇠로, 저장할 때마다 **전체 데이터를 폰에서 암호화**해 작은 서버(Cloudflare Workers + KV)에 덮어쓴다. 새 폰에서는 복구 코드를 넣어 받아 온다. 로그인은 없다.

- 서버에 올라가는 것은 암호문과, 복구 코드에서 만든 이름(해시)뿐이다. 서버도 Cloudflare 도 내용과 복구 코드를 모른다.
- 앱은 계속 폰 안 데이터로 동작한다(오프라인 그대로). 서버 사본은 보관용이다. 동시에 여러 폰에서 쓰면 나중에 올린 쪽이 남는다(last write wins).

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| **복구 코드 + Workers KV (채택)** | 서버 코드 두 동작(올리기·받기)뿐, 무료 한도 안, 로그인 없음, 암호화로 내용 비공개 | 복구 코드를 잃으면 복구 불가, 동시 사용 시 마지막 쓰기만 남음, KV 무료 쓰기 하루 1,000회 |
| Supabase / Firebase (로그인 + DB) | 계정 복구·여러 기기 동기화 | 로그인 화면·인증 설정, 어머니에게 번거로움, 설정량 큼 |
| Google Drive 자동 백업 (appData) | 사용자 드라이브에 저장, 서버 없음 | 브라우저 토큰이 1시간마다 만료 — 자동 저장에 매번 다시 로그인, OAuth 동의 화면 설정 |
| 파일 백업만 (현행) | 서버 없음 | 사람이 잊음, 폰 분실 시 마지막 백업 이후 손실 |

## 결과

- 쉬워지는 것: 폰을 바꾸거나 잃어도 복구 코드만 있으면 마지막 저장까지 돌아온다. 파일 백업을 잊어도 된다.
- 어려워지는 것: 서버(Worker) 하나를 배포·관리한다(같은 레포 `worker/`, GitHub Actions 배포, Cloudflare 개인 계정·API 토큰). 복구 코드를 잃지 않게 안내가 필요하다.
- 파일 백업은 그대로 둔다(서버가 없어져도 빠져나갈 길).
- 다시 볼 조건: 여러 기기 동시 사용이 생기거나, KV 쓰기 한도(하루 1,000회)에 닿으면 D1·R2 또는 로그인 방식(Supabase)을 다시 본다.

## 구현 (2026-10-13, #97)

- 서버는 `worker/`(Worker 이름 `uri-jangbu-keep`, KV 바인딩 `KEEP`). 동작은 올리기(`PUT`)·받기(`GET`)·지우기(`DELETE`, 자동 보관을 끌 때 서버 사본 지우기용) 셋이다. API 는 SPEC-006 기술 메모 "서버 API".
- 서버는 형식(이름 64자 16진수, `{ v, savedAt, iv, data }`, 1MB 상한)과 출처(`https://crowwan.github.io`, #128 부터 미리보기 출처도 — 저장 자리를 나눔, ADR 008)만 본다. 받은 JSON 을 그대로 저장하므로 내용·복구 코드는 여전히 모른다.
- 배포는 `.github/workflows/worker.yml`(main 에 `worker/**` 변경 또는 수동 실행 → 테스트 → `wrangler deploy`). 계정 id·API 토큰은 레포 Secrets 에만 둔다. 주소 확인·수동 배포는 CLAUDE.md "자동 보관 서버 배포".
