# SPEC-009 홈 화면 추가 쉽게 · 카톡 안에서 열렸을 때

## 배경과 목표

v2.6 에서 홈 화면에 추가하는 길은 두 곳이다. 설정 맨 아래 [홈 화면에 추가] 줄과, 첫 장부를 만든 직후 장부 위에 뜨는 권하기 카드다(SPEC-002, #135). 그런데 둘 다 끝까지 따라 하기 어렵다.

- 설치 창을 바로 띄울 수 없는 브라우저에서는 "홈 화면에 추가하는 방법" 창이 글 세 줄로만 알려 준다. ⋮·≡ 가 화면 어디에 있는지 글만 보고 찾아야 한다.
- 권하기 카드는 연습(SPEC-008)이 끝나고 새 장부를 만든 뒤에 뜬다. 버튼을 따라 누르던 흐름이 끊긴 뒤라 지나치기 쉽다.
- 이모는 어머니가 카톡으로 보낸 링크를 눌러 시작할 가능성이 크다. 그러면 **카톡 안 브라우저**에서 장부를 만들게 된다. 갤럭시에서는 크롬·삼성 인터넷·카톡 안 브라우저가 저장 공간을 따로 쓴다. 그래서 나중에 홈 화면 앱이나 크롬에서 열면 장부가 비어 보인다. 게다가 카톡 안 브라우저에서는 홈 화면에 추가할 수도 없다.

이 기능이 끝나면 다음이 된다.

- 설치 방법 안내를 브라우저 화면 그림으로 한 장씩 넘겨 보며 따라 한다(A).
- 첫 실행 연습이 끝나면 "홈 화면에 추가하시겠어요?" 를 한 번 묻는다. [추가할게요] 를 누르면 그 자리에서 설치를 따라 하고, 홈 화면 아이콘이 생긴 것까지 확인한 뒤 진짜 장부를 만든다(B).
- 카톡 안에서 열렸으면 첫 화면보다 먼저 알려 주고, 폰의 인터넷 앱으로 옮겨 준다. 이미 카톡 안에서 장부를 쓰고 있었으면 복구 코드로 장부째 옮긴다(C).

- 시안: 위 링크 "우리 장부 v2.7 시안". A·B·C·D 네 결정 묶음이다.
- 사용자 결정 2026-10-16: "좋은데? 연습에도 있으면 좋겠는데 이건 바로 시작하기 보다 한번 물어보자. 홈화면에 추가하시겠어요? 추가하면 어떻게 되고 편하다 뭐 이런 안내 메시지랑 추가하겠다고 하면 추가 연습을 시작하는거지 연습 단계가 많으면 피로도가 고민이라 그래. 나머지는 추천하는 걸로"
  - A·C 는 시안의 "(추천)" 값 그대로다. D(옛 이름 아이콘 안내)는 추천대로 넣지 않는다(범위 밖).
  - B 는 사용자 말대로 바꿨다. 시안은 연습 끝 화면 다음에 설치 단계 "홈 화면에 추가해 볼까요?" 를 바로 이어 붙였다. 이 스펙은 그 자리에서 **먼저 묻는다**. [추가할게요] 를 고른 분만 설치를 따라 하고, [다음에 할게요] 를 고르면 바로 진짜 새 장부로 간다. 연습 단계는 늘지 않는다.
  - 사용자 추가(같은 날): "홈화면추가했을 때 어떻게 보이는지도 같이 안내에 있으면 더 좋겠네". 그래서 추가하면 홈 화면이 어떻게 보이는지 그림(아래 "홈 화면 모습 그림")을 묻는 화면, A 그림 안내 마지막 장, 설치 확인 화면에 같이 넣는다.
- 실기기에서 아직 확인하지 못한 사실(브라우저 메뉴 문구, 카톡 동작 등)이 있다. 아래 "기술 확인" 에 모았고, 첫 이슈(개발 확인 화면)로 확인한다. 본문에 **(확인 필요)** 라고 적은 문구·동작은 그 결과로 확정한다.
- 선행
  - SPEC-002 "홈 화면 추가": 설정 줄, `useInstallAction`, 방법 안내 선택 창 `InstallGuideSheet`, 권하기 카드 `dongari:install-offer`.
  - SPEC-008: 첫 실행 물음, 연습 끝 화면(컷 6), 첫 실행 새 장부 만들기(컷 7).
  - SPEC-006: 복구 코드, 자동으로 지키기, 복구 코드로 불러오기.

## 동작 정의

### 홈 화면 모습 그림 (A·B 공통)

추가하면 홈 화면이 어떻게 보이는지 보여 주는 그림 하나를 세 곳에서 같이 쓴다.

- 쓰는 곳: B 묻는 화면, A 그림 안내 마지막 장(설치 끝), B 설치 확인 화면.

```
┌───────────────────────────────┐
│  ▢     ▢     ▢     ▢          │  ← 다른 앱: 흐린 둥근 네모 + 흐린 이름 막대
│  ▬     ▬     ▬     ▬          │
│                               │
│  ▢     ▢    ┏━━━┓    ▢        │
│  ▬     ▬    ┃ 📒┃    ▬        │  ← 우리 장부 아이콘 (실제 icon-192)
│             ┗━━━┛             │     청록 둘레로 강조
│            우리 장부            │  ← 이름 진하게 (SemiBold)
└───────────────────────────────┘
  누르면 바로 장부가 열려요
```

- 폰 홈 화면 모형이다. 바탕은 `--fill` 면, 반경 16, 위아래로 길지 않게(두 줄, 한 줄에 네 칸).
- 다른 앱 아이콘 일곱 개는 흐린 도형으로만 그린다. `--line-strong` 면 둥근 네모와 그 아래 이름 자리 막대이고, 로고·글자는 넣지 않는다. 실제 앱처럼 보이면 무엇을 누르라는 건지 헷갈린다.
- 아랫줄 셋째 칸에 **실제 앱 아이콘**을 둔다. `public/icons/icon-192.png` 를 같은 모양(둥근 네모)으로 잘라 쓴다. 3px `--accent-ink` 둘레로 강조하고, 아래 이름 "우리 장부" 는 `--strong` SemiBold 다. 이름은 manifest `short_name` 과 같은 값이다.
- 그림 아래 한 줄: **"누르면 바로 장부가 열려요"** (Body 16).
- 그림은 HTML·CSS 와 앱 아이콘 파일로 그린다. 아이콘은 이미 미리 저장해 두므로(SPEC-002) 인터넷 없이도 보인다. 다크 모드·큰 글씨에서도 같이 바뀐다.
- 화면 읽기에는 그림 대신 글 한 줄 "홈 화면에 '우리 장부' 아이콘이 생겨요" 로 읽힌다. 흐린 도형은 읽지 않는다. 아래 줄 "누르면 바로 장부가 열려요" 는 보이는 글 그대로 읽힌다.
- 폰마다 홈 화면 배치와 아이콘 모양(둥근 네모·동그라미)은 다르다. 그림은 "이런 아이콘이 이런 이름으로 생긴다" 만 보여 준다.

### A 그림으로 따라 하는 설치 안내

[홈 화면에 추가] 를 눌렀을 때 설치 창을 바로 띄울 수 없으면, 지금 뜨는 "홈 화면에 추가하는 방법" 선택 창 안의 글 세 줄(`InstallGuide`)을 **그림 넘기기**로 바꾼다.

- 창을 여는 조건과 누름 동작(`useInstallAction`)은 그대로다(시안 결정 "지금 방법 안내 창 안"). 설정 줄, 장부 위 권하기 카드, B 설치 따라 하기가 같은 창을 같이 쓴다.
  - 브라우저가 설치를 제안해 두었으면(`beforeinstallprompt`) 지금처럼 브라우저 설치 창이 바로 뜨고, 그림 안내는 나오지 않는다.
  - 설치 창에서 [취소] 하면 다음에 누를 때부터 그림 안내가 뜬다. 설치 제안은 한 번만 쓸 수 있어서다(지금 그대로).
- 창 모양: 제목 "홈 화면에 추가하는 방법" 은 그대로다. 그 아래에 그림 한 장, 큰 글씨 한 줄("1 화면 위 오른쪽 ⋮ 를 누르세요"), 아래 [이전]·[다음] 이 있다.
  - 첫 장에서는 [이전] 을 누를 수 없다.
  - 마지막 장에서 [다음] 이 [다 했어요] 로 바뀐다. 누르면 창이 닫힌다.
  - 창 바깥·뒤로 버튼으로 닫는 규칙은 그대로다(뒤로 버튼은 창만 닫는다, SPEC-001 선택 창 규칙).
  - 창을 닫았다 다시 열면 1장부터 본다.
- **손으로만 넘긴다**(시안 결정). 따라 하는 동안 브라우저 메뉴를 열고 닫아야 한다. 자동으로 넘어가면 돌아왔을 때 어디까지 봤는지 놓친다.
- 그림 속 누를 곳에는 청록 화살표와 동그라미를 그린다. 화살표와 동그라미만 천천히 깜빡인다(시안 결정). 폰에서 "동작 줄이기"(`prefers-reduced-motion`)를 켰으면 멈춘 채로 보인다. 작은 그림 속 ⋮ 는 깜빡임 없이는 눈에 잘 안 띈다.

#### 그림 장 (브라우저마다 네 장)

그림 속 브라우저 화면은 로고 없이 회색 면으로 그린다. 메뉴 줄은 위치만 맞추고, 나머지 줄은 흐리게, 누를 줄만 진하게 쓴다. 문구가 실제와 다르면 고칠 곳은 진하게 쓴 한 줄뿐이다.

| 장 | 크롬 | 삼성 인터넷 |
|---|---|---|
| 1 | 그림: 주소창 오른쪽 ⋮ 에 동그라미 / 글 "화면 위 오른쪽 [⋮] 메뉴를 누르세요" | 그림: 화면 아래 오른쪽 ≡ 에 동그라미 / 글 "화면 아래 오른쪽 [≡] 메뉴를 누르세요" |
| 2 | 그림: 메뉴 목록 중 "홈 화면에 추가" 줄 / 글 "[홈 화면에 추가] 또는 [앱 설치] 를 누르세요" **(확인 필요 T-1)** | 그림: 메뉴 중 "현재 페이지 추가" → 다음 목록 "홈 화면" / 글 "[현재 페이지 추가] 를 누르고 [홈 화면] 을 고르세요" **(확인 필요 T-2)** |
| 3 | 그림: 확인 창 "앱 설치" + [취소] [설치] / 글 "[설치] 를 누르세요" **(확인 필요 T-1)** | 그림: 확인 창 "홈 화면에 추가" + [취소] [추가] / 글 "[추가] 를 누르세요" **(확인 필요 T-2)** |
| 4 (설치 끝) | 홈 화면 모습 그림 / 글 "홈 화면에 '우리 장부' 가 생겨요" + 그림 아래 줄 "누르면 바로 장부가 열려요" | 같음 |

- 크롬 2장 문구는 크롬 버전과 사이트에 따라 "홈 화면에 추가" 또는 "앱 설치" 로 보인다. 그래서 글 줄에 둘 다 적는다.
- 삼성 인터넷 2·3장은 v2.6 글("[현재 페이지 추가] → [홈 화면]")에 마지막 확인 창 [추가] 를 한 장 더한 것이다.
- 장 번호는 "1 / 4" 처럼 글 줄 앞에 둔다.

#### 모르는 브라우저일 때

- 크롬도 삼성 인터넷도 아니면(`browserKind` 가 `other`) 그림 대신 맨 위에 **"지금 쓰는 앱을 골라 주세요"** 와 칩 [인터넷(삼성)] [크롬] 을 먼저 보여 준다(시안 결정).
  - 고르면 그 브라우저의 네 장이 1장부터 나온다. 고른 칩은 그림 위에 남아 있어 다시 바꿀 수 있다.
  - 갤럭시 기본 인터넷 앱의 앱 서랍 이름이 "인터넷" 이라 칩에 그 이름을 같이 적는다.
  - 여섯 장(삼성 셋 + 크롬 셋)을 이어 보이는 안은 고르지 않았다. 길어서다.

#### 화면 읽기

- 그림마다 글 한 줄로 읽는다(위 표의 글 줄, v2.6 의 세 줄과 같은 글 + 4장). 그림 자체는 읽지 않는다.
- 장이 바뀌면 새 글 줄을 읽어 준다(장 번호 포함, 예: "2 / 4, [홈 화면에 추가] 또는 [앱 설치] 를 누르세요").
- [이전]·[다음]·[다 했어요] 는 56 이상이다.

### B 연습 끝에 "홈 화면에 추가하시겠어요?"

#### 흐름

```
연습 끝 화면 (잘 보냈어요! / 연습 끝!)  ─[다음]→  ② 홈 화면에 추가하시겠어요?
                                                │
                     ┌──────────────────────────┴───────────────┐
               [추가할게요]                                 [다음에 할게요]
                     │                                           │
     설치 창 바로 / 없으면 A 그림 안내                              │
                     │                                           │
     ③ 홈 화면에 추가했어요  (신호 없으면 "홈 화면에 생겼나요?")         │
                     │                                           │
                     └───────────[새 장부 만들기]──→ 첫 실행 새 장부 만들기 (진짜 장부) ←┘
```

- **언제 묻나**: 첫 실행 물음에서 [연습해 보기] 로 연 연습이 끝 화면까지 왔고, 아래가 모두 맞을 때.
  - 홈 화면 앱(`display-mode: standalone`)으로 열지 않았다.
  - 이 화면에서 이미 설치를 마치지 않았다(`appinstalled`).
  - 카톡 안 브라우저가 아니다(C). 카톡 안에서는 설치할 수 없다.
- **묻지 않는 경우**는 v2.6 끝 화면 그대로다("이제 진짜 장부를 만들어요…" + [새 장부 만들기]).
  - 위 조건이 하나라도 틀린 경우.
  - 설정 [연습해 보기] 로 연 연습. 이미 장부가 있고, 설정에 [홈 화면에 추가] 줄이 있다.
  - 연습 중 [그만하기] 로 끝낸 경우. 그만두고 싶어 한 분께 하나 더 묻지 않는다. 이때 첫 장부 뒤 권하기 카드는 [바로 시작] 과 같이 v2.6 그대로 뜬다.
- 연습 단계(연습 N / 4)는 그대로 넷이다. 묻는 화면에는 연습 띠·"연습 N / 4"·말풍선이 없다. 진짜 설치라서 연습이 아니다.

#### ① 연습 끝 화면 (바뀌는 곳)

- 묻는 경우에만 글과 버튼이 바뀐다. 나머지(제목, 체크 동그라미, 배운 것 네 줄, "다시 해 보고 싶으면 설정 → 연습해 보기")는 SPEC-008 그대로다.
  - 글: "연습으로 적은 내역은 지웠어요. 진짜 장부를 만들기 전에 하나만 물어볼게요."
  - 주 버튼: [다음] → ②.
- 뒤로 버튼은 [다음] 과 같다(끝 화면의 뒤로 버튼 = 주 버튼, SPEC-008 규칙 그대로).

#### ② 묻는 화면 "홈 화면에 추가하시겠어요?"

```
┌───────────────────────────────┐
│ 홈 화면에 추가하시겠어요?        │  ← 화면 제목 (24)
│                               │
│ ┌───────────────────────────┐ │
│ │   (홈 화면 모습 그림)        │ │
│ └───────────────────────────┘ │
│   누르면 바로 장부가 열려요      │
│                               │
│ ┌───────────────────────────┐ │
│ │ 추가하면 좋은 점              │ │  ← 카드 제목 (20)
│ │ ✓ 카톡에서 링크를 찾지 않아도  │ │
│ │   아이콘을 눌러 바로 열려요     │ │
│ │ ✓ 기록이 더 안전하게           │ │
│ │   지켜져요                   │ │
│ └───────────────────────────┘ │
│                               │
│ [      추가할게요       ]       │  ← 주 버튼
│ [     다음에 할게요      ]       │  ← 보조 버튼
└───────────────────────────────┘
```

- 제목: **"홈 화면에 추가하시겠어요?"**
- 홈 화면 모습 그림 + "누르면 바로 장부가 열려요".
- 카드 "추가하면 좋은 점" 두 줄. 앞에 청록 체크가 있고, 끝 화면 "배운 것" 카드와 같은 모양이다.
  - "카톡에서 링크를 찾지 않아도 아이콘을 눌러 바로 열려요"
  - "기록이 더 안전하게 지켜져요". 홈 화면 앱은 브라우저가 공간이 모자랄 때 기록을 먼저 지우지 않는다(SPEC-002 오래 보관 요청).
- 버튼은 화면 흐름 맨 아래에 둔다(SPEC-008 #132 첫 실행 물음·끝 화면과 같이, 글자 200% 에서 글을 가리지 않게). 주 [추가할게요], 보조 [다음에 할게요].
- 뒤로 버튼 → ①.
- **[다음에 할게요]** → 첫 실행 새 장부 만들기(진짜 장부). 설치 단계 없이 바로 간다.
  - 이 폰의 권하기 상태를 `done` 으로 적는다. 첫 장부를 만든 뒤 장부 위 권하기 카드는 뜨지 않는다(시안 결정 B4: 방금 거절한 걸 첫 화면에서 또 물으면 같은 질문이 두 번이다). 다시 하는 길은 설정 [홈 화면에 추가] 줄이다.
- **[추가할게요]** → 설치 따라 하기(아래).

#### 설치 따라 하기 ([추가할게요])

- 설치 제안이 있으면(`beforeinstallprompt`) **브라우저 설치 창이 바로 뜬다** **(창 모양·문구는 브라우저가 그린다, 확인 필요 T-1)**.
  - [설치] → 설치를 마친 신호(`userChoice` accepted 또는 `appinstalled`)가 오면 ③ "홈 화면에 추가했어요".
  - [취소] → ② 에 그대로 남는다. 다시 [추가할게요] 를 누르면 A 그림 안내 창이 뜬다(설치 제안은 한 번만 쓸 수 있다).
- 설치 제안이 없으면 **A 그림 안내 창**이 ② 위에 올라온다. 따라 하는 동안 창은 떠 있고, 그 위로 브라우저 메뉴를 열어 설치한다.
  - 설치를 마친 신호(`appinstalled`)가 오면 창을 닫고 ③ "홈 화면에 추가했어요" 로 간다.
  - [다 했어요] 로 닫았는데 신호가 없으면 ③ 을 "홈 화면에 생겼나요?" 모양으로 보여 준다. 메뉴로 설치하면 신호가 오지 않는 브라우저가 있을 수 있다 **(확인 필요 T-6)**.
  - 바깥·뒤로 버튼으로 창을 닫으면 ② 에 그대로 남는다.

#### ③ 설치 확인 화면

| | 설치 신호가 왔을 때 | [다 했어요] 인데 신호가 없을 때 |
|---|---|---|
| 제목 | 홈 화면에 추가했어요 | 홈 화면에 생겼나요? |
| 그림 | 홈 화면 모습 그림 + "누르면 바로 장부가 열려요" | 같음 |
| 글 | "다음부터는 홈 화면의 '우리 장부' 아이콘으로 열어요. 카톡에서 링크를 찾지 않아도 돼요." | "생겼으면 다음부터는 홈 화면의 '우리 장부' 아이콘으로 열어요." |
| 주 버튼 | [새 장부 만들기] | [새 장부 만들기] |
| 보조 버튼 | — | [다시 따라 하기] (A 그림 안내 창을 1장부터 다시 연다) |

- [새 장부 만들기] → **이 화면(이 브라우저)에서 바로** 첫 실행 새 장부 만들기로 간다(시안 결정 B2). 같은 브라우저에서 설치한 홈 화면 앱은 저장 공간이 같다. 그래서 여기서 만든 장부가 아이콘으로 열어도 그대로 보인다. 앱을 나갔다 아이콘으로 다시 들어오는 단계가 하나 줄어든다.
- ③ 에 오면(어느 모양이든) 이 폰의 권하기 상태를 `done` 으로 적는다. 첫 장부 뒤 권하기 카드는 뜨지 않는다. 신호가 없는 모양에서 실제로는 설치하지 못했으면 설정 [홈 화면에 추가] 줄이 남아 있다.
- 뒤로 버튼은 [새 장부 만들기] 와 같다. 설치는 이미 끝났으니 ② 로 돌아가 다시 묻지 않는다.
- 새 장부 만들기에서 뒤로 버튼은 SPEC-008 그대로 첫 실행 물음으로 간다.

#### 연습을 마쳤다는 표시

- 첫 실행 연습이 끝 화면에 닿으면 **이 폰에 "첫 실행 연습을 마쳤다" 를 적는다**: localStorage `dongari:practice` = `{ v: 1, done: true }`.
  - 이유: ③ 에서 장부를 만들기 전에 홈 화면 아이콘으로 먼저 열 수 있다. 그때 "처음이세요?" 를 다시 물으면 연습을 또 하라는 말이 된다.
- 장부가 없는 폰에서 앱을 열 때 이 표시가 있으면 첫 실행 물음 없이 **바로 첫 실행 새 장부 만들기**를 연다. 표시가 없으면 지금처럼 물음부터 시작한다(SPEC-008).
  - 새 장부 만들기에서 뒤로 버튼은 이때도 물음으로 간다(SPEC-008 규칙 그대로). 연습을 다시 하고 싶은 분의 길이다.
- 장부가 생긴 뒤에는 이 표시를 보지 않는다. 지우지 않아도 된다.
- 장부 데이터(`dongari:v2`)·기록 파일·자동으로 지키기 보관본과 따로다. 폰마다 다른 값이다(`dongari:guide`·`dongari:install-offer` 와 같은 방식). 값이 없거나 깨졌으면 표시가 없는 것으로 본다(물음부터).
- ② 를 띄운 채 앱을 닫으면 다음에 열 때는 위 규칙대로 새 장부 만들기다. ② 를 다시 묻지 않는다. 대답하지 않았으므로 권하기 상태는 적지 않는다. 첫 장부를 만들면 v2.6 처럼 카드가 뜬다.
- 연습 기록 자체는 여전히 남기지 않는다(SPEC-008, 메모리).

#### 장부 위 권하기 카드와의 관계

| 어떻게 시작했나 | ② 묻는 화면 | 첫 장부 뒤 장부 위 카드 (SPEC-002 #135) |
|---|---|---|
| 연습 → [추가할게요] → 설치 (③ 어느 모양이든) | 나옴 | 안 나옴 |
| 연습 → [다음에 할게요] | 나옴 | 안 나옴 (설정 줄만) |
| 연습 → ② 에서 대답 없이 앱 닫음 | 나옴 | 나옴 (v2.6 그대로) |
| 연습 중 [그만하기] | 안 나옴 | 나옴 (v2.6 그대로) |
| 홈 화면 앱으로 열고 연습 | 안 나옴 | 안 나옴 (지금 규칙) |
| [바로 시작] | 없음 | 나옴 (v2.6 그대로) |
| 설정 [연습해 보기] 로 연 연습 | 없음 | 해당 없음 |
| 카톡 안 브라우저에서 [그냥 여기서 쓸게요] (C) | 안 나옴 | 안 나옴 (설치가 안 되는 곳) |

- 권하기 상태 `dongari:install-offer` 는 지금 첫 장부를 만들 때 `waiting` 으로 적는다. **이미 `done` 이면 그대로 둔다**(② 에서 정한 대답을 덮지 않게).

### C 카톡 안에서 열렸을 때

카톡 채팅방의 링크를 누르면 카톡 안 브라우저가 열린다. 이곳의 저장 공간은 크롬·삼성 인터넷과 따로다. 그래서 여기서 만든 장부는 나중에 홈 화면 앱에서 보이지 않는다. 앱을 열 때 카톡 안이면 첫 화면보다 먼저 알려 준다.

#### 언제 보이나

- 판단은 앱을 열 때, 화면을 그리기 전에 한 번 한다.
  - user agent 에 `KAKAOTALK` 이 들어 있으면 카톡 안 브라우저로 본다 **(확인 필요 T-4)**.
  - 안드로이드면 아래 ①·② 를 보여 준다.
  - 아이폰이면 대상 기기가 아니라서(SPEC-002) 주 버튼 없이 메뉴 그림 안내만 보여 준다(아래 "아이폰").
- 이 카톡 안 저장 공간에 "그냥 여기서 쓰기" 표시가 있으면 보이지 않는다(아래).
- 장부가 없으면 ①, 있으면 ② 가 된다. 둘 다 첫 실행 물음·장부 화면보다 먼저 한 화면 전체로 뜬다(시안 결정 "첫 화면 전체"). 띠는 "처음이세요?" 의 큰 버튼에 밀려 지나치기 쉽다. 여기서 시작하면 나중에 장부가 사라진 것처럼 보이니 한 번은 멈춰 세운다.
- 이 화면에서 뒤로 버튼은 앱을 닫는다(첫 실행 물음과 같다).

#### ① 장부가 없을 때 (처음 연 이모 폰)

```
┌───────────────────────────────┐
│ 카톡 안에서 열렸어요              │  ← 화면 제목
│ 여기서 적으면 나중에 홈 화면 앱에서 │
│ 안 보여요. 인터넷 앱에서 열어      │
│ 주세요.                        │
│                               │
│ [     인터넷 앱으로 열기     ]    │  ← 주 버튼
│                               │
│ 안 열리면 오른쪽 아래 ⋮ →         │
│ '다른 브라우저로 열기'            │
│ ┌───────────────────────────┐ │
│ │ (카톡 브라우저 메뉴 그림)      │ │  ← A 와 같은 방식, ⋮·줄에 동그라미
│ └───────────────────────────┘ │
│                               │
│        그냥 여기서 쓸게요         │  ← 작은 글자 버튼
└───────────────────────────────┘
```

- 제목 "카톡 안에서 열렸어요", 글 "여기서 적으면 나중에 홈 화면 앱에서 안 보여요. 인터넷 앱에서 열어 주세요."
- 주 버튼 **[인터넷 앱으로 열기]** → `kakaotalk://web/openExternal?url=<지금 주소, URL 인코딩>` 으로 간다. 카톡이 폰의 기본 인터넷 앱으로 이 주소를 연다 **(동작 확인 필요 T-3)**.
  - 이름은 시안 결정대로 "인터넷 앱" 이다. openExternal 이 여는 앱은 크롬이 아니라 폰의 기본 인터넷 앱이고, 갤럭시는 대개 삼성 인터넷("인터넷")이다. [크롬으로 열기] 라고 쓰면 다른 앱이 열려 헷갈리고, 크롬이 없는 폰에서는 열리지 않는다.
- 그 아래 보조 글 "안 열리면 오른쪽 아래 ⋮ → '다른 브라우저로 열기'" 와 카톡 브라우저 메뉴 그림이 있다 **(메뉴 위치·문구 확인 필요 T-5)**. 그림은 A 와 같은 방식이다. 회색 면 브라우저에 ⋮ 와 "다른 브라우저로 열기" 줄 동그라미를 그리고, 깜빡임과 동작 줄이기 규칙도 A 와 같다. 넘기지 않는 한 장이다.
- 맨 아래 작은 글자 버튼 **[그냥 여기서 쓸게요]** (시안 결정 "허용, 작게"). 누르는 곳은 56 이상이지만 면 없는 글자 버튼(Label 16, `--ink`)이라 주 버튼보다 훨씬 작게 보인다. 열기도 안 되고 메뉴도 못 찾으면 앱을 아예 못 쓰니 빠져나갈 길은 둔다.
  - 누르면 "그냥 여기서 쓰기" 표시를 남기고 지금처럼 첫 실행 물음("처음이세요?")으로 간다.

#### ② 이미 여기서 장부를 쓰고 있었을 때

```
┌───────────────────────────────┐
│ 카톡 안에서 열렸어요              │
│ 여기에 쓰던 장부가 있어요. 인터넷   │
│ 앱으로 옮겨서 쓰면 홈 화면에도     │
│ 추가할 수 있어요.                │
│ ┌───────────────────────────┐ │
│ │ 복구 코드                    │ │
│ │ HK7M-29QF-MX4P-8R2D        │ │  ← 크게, 고정폭
│ │ 방금 자동으로 지켜 두었어요     │ │  ← 상태 줄
│ └───────────────────────────┘ │
│ [ 코드 복사하고 인터넷 앱으로 열기 ] │
│ 열린 곳에서 [카톡에서 쓰던 장부    │
│ 가져오기]를 누르면 코드가 들어가    │
│ 있어요. 코드를 적어 두면 더 안전해요.│
│ (안 열리면 ⋮ 메뉴 그림, ① 과 같음)  │
│        그냥 여기서 쓸게요         │
└───────────────────────────────┘
```

- 복구 코드로 옮긴다(시안 결정 C4). 복구 코드는 자동으로 지키기로 이미 서버에 올라가 있어 붙여 넣기 한 번이면 된다. 기록 파일은 보내고, 파일을 찾아 불러오는 길이 길다.
- 화면을 열면 **자동으로 지키기로 지금 기록을 바로 올린다**(10초 모으기를 기다리지 않는다, SPEC-006 보관기).
  - 올리는 동안: 상태 줄 "지켜 두는 중이에요", 주 버튼은 누를 수 없다.
  - 다 올라가면: "방금 자동으로 지켜 두었어요", 주 버튼이 눌린다.
  - 올리지 못하면(인터넷 없음·서버 오류): 상태 줄 "인터넷에 연결되면 지켜 두고 버튼이 눌려요". 연결이 돌아오면(`online`) 다시 올린다.
- 주 버튼 **[코드 복사하고 인터넷 앱으로 열기]**:
  1. 복구 코드를 클립보드에 쓴다 **(카톡 안 복사 확인 필요 T-7)**.
  2. `kakaotalk://web/openExternal?url=<지금 주소 + ?from=kakao>` 로 연다.
  - 복사하지 못하면 코드 카드 아래에 "복사하지 못했어요. 코드를 적어 두세요" 를 보이고, 코드를 크게 보여 준 채로 그대로 연다.
  - **복구 코드는 주소에 넣지 않는다.** 기록을 여는 열쇠라서 브라우저 방문 기록·카톡 서버에 남으면 안 된다.
- 자동으로 지키기를 쓸 수 없으면 기록 파일로 옮기는 순서로 바꿔 보인다. 서버 주소 없는 빌드, 자동으로 지키기 꺼짐, 읽기 전용이라 복구 코드 없음이 그런 경우다.
  - 글 "기록 파일을 먼저 보내 두고, 인터넷 앱에서 불러와요."
  - 주 [↗ 기록 파일 보내기](설정과 같은 동작, SPEC-002). 보내기에 성공하면 주 버튼이 [인터넷 앱으로 열기](`?from=kakao` 없이)로 바뀐다.
  - 안내 "열린 곳에서 [바로 시작] → 위쪽 [기록 파일 불러오기]".
- 아래 메뉴 그림·[그냥 여기서 쓸게요] 는 ① 과 같다. [그냥 여기서 쓸게요] 는 표시를 남기고 장부 화면으로 간다.

#### ③ 인터넷 앱에서 열린 첫 화면 (`?from=kakao`)

- 주소에 `from=kakao` 가 있고, 카톡 안이 아니고, 이 브라우저에 장부가 없으면 첫 실행 물음 위에 카드를 둔다.
  - 카드: "카톡에서 쓰던 장부가 있나요? 방금 복사한 복구 코드로 그대로 가져와요." + 주 [카톡에서 쓰던 장부 가져오기].
  - 누르면 지금 있는 "복구 코드로 불러오기" 화면이 열린다(SPEC-006). 그 뒤 확인 창·불러오기는 지금 그대로다.
    - 클립보드를 읽을 수 있고 그 안이 복구 코드 모양(16자, SPEC-006 규칙)이면 글 칸에 미리 넣어 둔다 **(클립보드 읽기 확인 필요 T-8)**.
    - 읽을 수 없으면 빈 칸이다. 안내에 "길게 눌러 붙여 넣어 주세요" 를 한 줄 더한다.
  - 그 화면에서 뒤로 버튼은 물음으로 돌아온다.
  - 이 카드가 있을 때 물음의 주 버튼은 카드의 [카톡에서 쓰던 장부 가져오기] 하나다. 물음의 [연습해 보기] 는 보조 버튼 모양으로 내린다(한 화면에 주 버튼 하나, design.md).
- 앱을 열 때 `from` 을 읽은 뒤 주소에서 지운다(`history.replaceState`). 새로고침하거나 이 화면에서 홈 화면에 추가해도 카드가 다시 생기지 않게 하려는 것이다.
- 이 브라우저에 이미 장부가 있으면 카드 없이 지금처럼 장부를 연다. 가져오면 지금 장부가 바뀌니, 원하는 분은 설정의 [복구 코드로 불러오기] 로 한다.
- ① 에서 연 경우(`from` 없음)는 카드 없이 지금 첫 화면 그대로다.

#### 그냥 여기서 쓰기 표시

- [그냥 여기서 쓸게요] 를 누르면 카톡 안 저장 공간 localStorage 에 `dongari:in-app` = `{ v: 1, stay: true }` 를 적는다. 다시 열어도 ①·② 를 묻지 않는다.
  - 장부 데이터·기록 파일·보관본과 따로다(폰·브라우저마다 다른 값). 깨졌거나 없으면 표시가 없는 것으로 본다(다시 묻는다). 적지 못해도 화면은 막지 않는다.
- 카톡 안에서 표시가 있으면:
  - 설정 "앱" 묶음의 [홈 화면에 추가] 줄 자리에 **[인터넷 앱으로 열기]** 줄(보조 줄 "홈 화면에 추가하려면")을 둔다. 카톡 안에서는 설치가 안 된다. 누르면 ①(장부 없음)·②(장부 있음) 화면이 설정 위 화면으로 열린다([‹ 설정] 으로 돌아온다). 이때 [그냥 여기서 쓸게요] 는 [‹ 설정] 과 같다.
  - B 의 묻는 화면과 장부 위 권하기 카드는 띄우지 않는다.

#### 아이폰 카톡

- user agent 에 `KAKAOTALK` 이 있고 아이폰이면 ① 과 같은 제목·글에, 주 버튼 없이 카톡 메뉴 그림 한 장("오른쪽 아래 ⋯ → 'Safari로 열기'", 문구는 시안 범위 밖이라 실기기 확인 없이 둔다)과 [그냥 여기서 쓸게요] 를 둔다. ② 도 같은 방식이다(복사만 하는 [코드 복사하기] + 메뉴 그림).
- 대상 기기가 아니므로 수동 QA 는 하지 않는다.

### 예외와 경계 상황

- 홈 화면 모습 그림의 아이콘 파일을 읽지 못하면 그 칸은 청록 면 둥근 네모로 둔다. 이름 "우리 장부" 는 그대로 보인다.
- A 그림 안내 창이 떠 있는 동안 `appinstalled` 가 오면(설정 줄·카드에서 연 경우 포함) 창을 닫는다. 설정 줄·카드는 지금처럼 사라진다. B 에서 연 경우만 ③ 으로 간다.
- B ② 에서 설치 창·그림 안내를 거치지 않고 브라우저 메뉴로 바로 설치해도 `appinstalled` 가 오면 ③ "홈 화면에 추가했어요" 로 간다.
- B 중에 이미 설치된 브라우저로 판정되면(`appinstalled` 가 ① 전에 왔음) ② 를 묻지 않는다.
- C ② 에서 복구 코드가 없거나(읽기 전용) 저장 막힘 상태면 기록 파일 순서로 보인다. 저장 막힘(`read-only`)에서도 기록 파일 보내기는 된다(SPEC-002).
- C 판단은 user agent 만 본다. 카톡 안 브라우저가 user agent 를 바꾸면 C 는 뜨지 않고 지금처럼 동작한다(안전한 쪽).
- `?from=kakao` 가 있어도 카톡 안이면 무시한다(카톡에서 다시 연 경우).
- 카톡이 아닌 앱 안 브라우저(네이버·인스타그램 등)는 이번 범위가 아니다. 지금처럼 동작한다.

## 기술 확인 (실기기 먼저)

시안의 "확인 필요" 모음이다. 문구·동작을 갤럭시 실기기에서 아직 보지 못했다. **첫 이슈로 미리보기 앱 안에 개발 확인 화면을 만들어 확인한다.** 그 결과로 본문의 (확인 필요) 문구를 확정하고, 다른 결과가 나오면 스펙을 고친 뒤 A·B·C 기능 이슈를 나눈다.

### 개발 확인 화면 `/#/dev/env`

- 주소: 미리보기 `https://uri-jangbu-preview.pages.dev/#/dev/env`, 개발 서버 `http://localhost:7777/dongari/#/dev/env`. 크롬 intent 로 넘어온 주소는 해시를 못 넘겨 `?dev=env` 로도 연다(#141).
- **개발 모드와 미리보기 빌드에서만** 연다. 본 주소 빌드 번들에는 들어가지 않는다(지금 `/#/dev/catalog` 처럼 빌드 때 빠지게). 미리보기 빌드 = 빌드 경로 `APP_BASE=/` 인 빌드(`npm run build:preview`·배포 워크플로 미리보기 단계 둘 다, #141 에서 확정 — 기술 메모 "개발 확인 화면").
- 미리보기 주소(`https://uri-jangbu-preview.pages.dev/#/dev/env`)를 카톡 나와의 채팅에 보내 눌러 카톡 안 브라우저로도 연다. 해시가 카톡 안에서 그대로 넘어오는지도 이때 본다.
- 화면에 보여 주는 것(위에서 아래로, 개발용 화면이지만 폰에서 읽기 쉽게 큰 글씨):
  - user agent 전체 문자열, `browserKind` 결과, 카톡 안 판단 결과(`KAKAOTALK` 포함 여부), 안드로이드·아이폰 구분.
  - `display-mode: standalone` 여부.
  - `beforeinstallprompt` 를 받았는지와 받은 시각(화면을 열기 전에 받았으면 "받음 (화면 열기 전)"). 받았으면 [설치 창 띄우기] 버튼과 `userChoice` 결과.
  - `appinstalled` 를 받았는지와 받은 시각. 메뉴로 설치하는 동안 이 화면을 열어 둔다.
  - `navigator.share` 있음, `canShare({ files })` 결과.
  - [복사 시험] 버튼(시험 글자를 쓰고 성공/실패와 오류 이름), [붙여넣기 시험] 버튼(읽은 글자 또는 오류 이름).
  - [kakaotalk openExternal 로 열기] 링크(`kakaotalk://web/openExternal?url=<이 화면 주소 + ?from=kakao>`), [크롬 intent 로 열기] 링크(`intent://<주소>?from=intent&dev=env#Intent;scheme=https;package=com.android.chrome;end`). 열린 쪽에서 이 화면이 `from` 을 읽었는지 "들어온 길" 로 보여 준다.
  - 참고값: `navigator.storage.persisted()`, 지금 출처(origin), 앱 버전 줄 값, 지금 주소.
- 결과 기록: 시험·이벤트·링크 누름마다 한 줄(시각, 이름, 성공/실패/받음/누름, 오류 이름)을 목록에 쌓는다. sessionStorage(`dongari-dev:env-log`)에 두어 새로고침해도 남고, 탭을 닫으면 사라진다.
- [결과 복사] 버튼: 위 값과 결과 기록을 글로 묶어 클립보드에 쓴다. 복사가 안 되는 곳(카톡 안 등)을 위해 [결과 보내기](폰 공유 창으로 글 보내기, 공유 창이 있을 때만)와 고를 수 있는 글 상자도 둔다.
- 이 화면은 localStorage 를 읽지도 쓰지도 않는다. 장부·자동으로 지키기와 상관없다(장부 저장소를 읽기 전에 이 화면으로 갈린다).
- 결과는 이슈 댓글에 브라우저마다 붙이고, 이 절의 표에 결과 칸을 채워 둔다. 그 뒤 본문의 (확인 필요) 를 지우고 변경 이력에 한 줄 남긴다.

## 기술 메모

### 홈 화면 모습 그림

- 부품 하나 `features/install/HomeScreenPreview`(#142, `decorative` 면 그림을 화면 읽기에서 숨기고 아래 줄만 읽힌다 — A 4장처럼 옆에 같은 뜻의 글 줄이 있을 때). 이름은 manifest 와 같은 값을 한 곳에서 가져온다. `src/pwa/appName.ts` 의 `APP_SHORT_NAME` 을 manifest(`pwaOptions.ts`)와 이 부품이 같이 쓴다. AC-1 은 그 상수와 그림 글이 같은지, manifest 옵션의 `short_name` 이 그 상수인지 본다.
- 아이콘은 `import.meta.env.BASE_URL + 'icons/icon-192.png'`(빌드 경로 `APP_BASE` 를 따라감). 이미 workbox 프리캐시에 들어 있다.
- 카탈로그(`/#/dev/catalog`)에 그림·그림 안내 네 장(브라우저별)·B 화면·C 화면을 상태별로 올린다.

### A 그림 안내

- `InstallGuide`(지금 글 세 줄)를 장 넘기기 부품으로 바꾼다. 장 데이터는 브라우저별 배열 한 곳에 둔다(글 줄 + 그림 종류 + 누를 곳). 그림은 장마다 작은 부품(회색 면 브라우저 틀 + 메뉴 줄)이다.
  - #142 구현: 문구·순서 `features/install/installGuideSteps.ts`(`INSTALL_GUIDE_WORDS` 그림 속 글자, `INSTALL_GUIDE_STEPS` 브라우저별 네 장), 장 그림 `InstallGuidePicture`, 브라우저 화면 모형 부품 `features/install/BrowserPicture`(`BrowserPicture`·`BrowserBar`·`BrowserPage`·`BrowserMenu`·`BrowserDialog`·누를 곳 표시 `TapMark` — C 카톡 메뉴 그림도 같은 부품으로 그린다), 넘겨 보는 안내 틀 `ui/SlideGuide`(B 에서도 쓸 수 있다). 모르는 브라우저 칩은 `SegmentedControl`.
- `InstallGuideSheet`·`useInstallAction` 의 열기 조건은 그대로 두고, 창 안 내용과 [확인] 버튼이 [이전]·[다음]/[다 했어요] 로 바뀐다. 창을 닫았다 열면 1장부터라 장 번호는 창 안 상태로 충분하다.
- 깜빡임은 CSS 애니메이션(투명도), 동작 줄이기면 멈춤. 값은 `tokens.css` 모션 토큰에서 고른다. #142: `--motion-blink`(1.6s), 애니메이션은 `@media (prefers-reduced-motion: no-preference)` 안에만 둔다(AC-8 은 CSS 파일을 읽어 본다).
- 창이 열려 있는 동안 `appinstalled` 를 듣고 닫는다(`installPrompt` 스토어의 `installed` 가 true 로 바뀌면).

### B

- `AppRoot` 의 `Mode` 에 두 상태를 더한다: `{ name: 'ask-install', sent }`(②), `{ name: 'installed', confirmed: boolean }`(③). 끝 화면(`PracticeEnd`)은 묻는 경우 `next` 버튼으로 ② 로 간다. 방문 기록은 지금 끝 화면 칸 위에 ② 칸 하나를 쌓는다(②에서 뒤로 버튼 → ①). ③ 은 ② 칸을 바꿔 끼운다(③ 에서 뒤로 버튼 = [새 장부 만들기]).
- 묻는 조건은 순수 함수로(가칭 `asksInstallAfterPractice({ firstRun, stopped, standalone, installed, inApp })`) 단위 테스트한다.
- ② 의 [추가할게요] 는 `useInstallAction` 의 `start` 를 그대로 쓰고, 설치 결과를 받으려고 `installPrompt` 스토어의 `installed` 를 지켜본다. 그림 안내 창의 [다 했어요] 는 B 에서만 콜백(가칭 `onFinished`)을 받아 ③ "생겼나요?" 로 간다.
- 연습을 마쳤다는 표시: `features/practice` 에 작은 저장소(가칭 `practiceMark`, `dongari:practice` `{ v: 1, done: true }`, `installOffer.ts` 와 같은 방식 — 깨졌으면 없는 것으로, 쓰기 실패는 조용히). `AppRoot` 가 첫 화면을 고를 때 `books.length === 0 && 표시 있음` 이면 `ask` 대신 `app`(첫 실행 새 장부 만들기, 물음 칸 위에 표시 칸 쌓기)로 시작한다.
- 권하기 상태: `App` 이 첫 장부를 만들 때 `installOfferStore.load()` 가 `done` 이면 `waiting` 을 적지 않는다. ② [다음에 할게요]·③ 도착 때 `AppRoot` 가 `installOfferStore.save('done')` 를 부른다(지금 `main.tsx` 에서 `AppRoot` 로 넘기는 저장소 그대로).

### C

- 판단 순수 함수(가칭 `features/install/inAppBrowser.ts` `inAppKind(userAgent)` → `'kakao-android' | 'kakao-ios' | undefined`)와 표시 저장소(`dongari:in-app`). `main.tsx` 가 저장소를 읽은 뒤 `AppRoot` 에 넘기고, `AppRoot` 의 `Mode` 에 `{ name: 'in-app' }` 을 더해 물음·장부보다 먼저 그린다.
- openExternal 주소 만들기도 순수 함수(가칭 `openExternalUrl(location.href, { fromKakao })`)로. 링크는 `<a href>` 로 둔다(누름 처리 안 `location.href` 대입보다 카톡 안에서 막힐 일이 적다 — T-3 에서 둘 다 확인).
- ② 의 바로 올리기는 SPEC-006 보관기(`AutoKeeper`)에 "지금 올리기"(10초 모으기 건너뛰기)와 결과 알림을 더한다. 지금 보관기는 실패하면 혼자 다시 시도하지 않는다. ② 는 `online` 때 다시 부른다.
- 클립보드 쓰기는 누름 처리 안에서 `navigator.clipboard.writeText`. 실패하면 옛 방식(`document.execCommand('copy')`)을 한 번 더 써 볼지, 바로 실패 안내를 할지는 T-7 결과로 정한다. 읽기는 ③ 카드를 누를 때 `navigator.clipboard.readText`(누름 처리 안), 실패·거절은 조용히 빈 칸.
- `?from=kakao` 는 `main.tsx` 가 앱을 열 때 `URLSearchParams` 로 읽고 `history.replaceState` 로 지운다. manifest `start_url` 에는 영향이 없다(검색어 없는 주소).
- 설정 "앱" 묶음: `SettingsScreen` 의 홈 화면에 추가 줄 자리에 카톡 안 + 표시 있음이면 [인터넷 앱으로 열기] 줄. 홈 화면 앱(standalone)은 카톡 안일 수 없으니 겹치지 않는다.

### 개발 확인 화면

- `src/devtools/` (#141): `route.ts`(`isDevEnvRoute`·`isPreviewBase`), `envChecks.ts`(카톡 판단·openExternal/intent 주소·결과 기록·결과 글, 순수 함수), `DevEnvScreen.tsx`(화면), `devEnvironment.ts`(브라우저 값 모으기, 테스트는 바꿔 넣는다).
- `src/catalog/route.ts` 처럼 `main.tsx` 가 해시 `#/dev/env`(또는 `?dev=env`)를 보고 동적 import 로 연다. 열리는 조건은 `import.meta.env.DEV || __PREVIEW_BUILD__` 다.
  - `__PREVIEW_BUILD__` 는 `vite.config.ts` 의 `define` 이 `isPreviewBase(APP_BASE)`(= 빌드 경로가 `/`)로 넣는 빌드 때 값이다. 본 주소 태그 빌드(`/dongari/`)는 둘 다 false 라 동적 import 가 번들에서 빠진다.
  - 이 기준을 고른 이유: 미리보기 빌드의 정의가 이미 `APP_BASE=/` 하나다(#128). 로컬 `npm run build:preview` 와 배포 워크플로 미리보기 단계가 같은 값으로 빌드돼 워크플로를 바꿀 일이 없다. `VITE_BUILD_SHA` 는 워크플로만 넘겨 로컬 미리보기 빌드에는 없고, 따로 `VITE_DEV_TOOLS` 를 두면 미리보기를 정하는 값이 둘로 갈린다.
  - 개발 모드·미리보기 빌드는 주소창에서 해시만 바꿔도(`hashchange`) 새로 열어 화면을 다시 고른다. 앱 화면 이동은 해시를 쓰지 않는다.
- `beforeinstallprompt`·`appinstalled` 는 지금 `browserInstallPrompt` 가 모듈을 읽을 때부터 듣는다. 확인 화면은 같은 스토어를 보고(화면을 열기 전에 온 제안도 보인다), 화면이 열린 뒤 받은 시각만 따로 `window` 에서 듣는다. [설치 창 띄우기] 는 스토어의 `install()` 이 돌려주는 `userChoice` 결과(`accepted`·`dismissed`)를 적는다.
- AC-35 는 라우트 함수 단위 테스트(`route.test.ts`, 켬/끔·`isPreviewBase`)로 보고, 빌드 결과물 확인(본 주소 빌드 `dist` 에 확인 화면 글자 없음, 미리보기 빌드에는 `DevEnvScreen-*.js` 조각 있음)은 PR 에서 손으로 한다.
