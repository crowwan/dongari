# SPEC-011 보관본 날짜별 사본과 서버 밖 사본

## 배경과 목표

자동으로 지키기(SPEC-006)는 서버에 최신본 한 벌만 덮어쓴다. 잘못 지우거나 망가진 상태가 보관되면 좋은 사본이 사라지고, 모든 보관본이 한 Cloudflare 계정에만 있다. 엑셀 불러오기(SPEC-010)로 데이터가 커지고 중요해져서 두 구멍을 메운다. 결정과 이유: [ADR 010](../decisions/010-keep-history-offsite.md).

사용자 결정(2026-11-24): 시안 결정 셋 "추천대로", 다만 "지금 당장 사용자에게 복구하는 기능을 제공하진 않아도 되지만, 복구 코드를 나한테 알려주면 내가 복구해줄 수 있는 방법 정도만 있어도 돼" → **앱 화면은 바꾸지 않고**, 서버 사본 + 서버 밖 사본 + 개발자 꺼내기 도구만.

선행: SPEC-006(보관 서버·꺼내기 스크립트), SPEC-007(보관 지켜보기).

## 동작 정의

### 1. 서버 날짜별 사본 (Worker)

- 날짜는 **한국 시간(UTC+9)** 의 날. 최신본을 저장할 때 KV metadata 에 `savedAt`(서버 받은 시각, ISO)을 함께 둔다. 이 기능 전에 저장된 최신본은 metadata 가 없으니 보관본 겉봉투의 `savedAt` 으로 그 날을 정한다.
- `PUT /v1/keep/<id>`(출처별 자리 그대로: 본 `keep:` / 미리보기 `preview:keep:`)를 받으면, 새 값을 쓰기 전에:
  1. 기존 최신본이 있고 그 보관일이 오늘보다 앞이면(#186 전에는 ≠ 오늘) → 기존 값을 `{자리}snap:<id>:<보관일 YYYY-MM-DD>` 로 복사(metadata `savedAt`, `expirationTtl` 31일 = 2,678,400초). 이미 있으면 덮어쓴다.
  2. 기존 최신본의 보관 달 ≠ 오늘의 달이면 → 기존 값을 `{자리}month:<id>:<보관 달 YYYY-MM>` 로도 복사(`expirationTtl` 400일 = 34,560,000초).
  3. 새 값을 최신본으로 쓴다(metadata `savedAt` = 지금).
- 그래서 사본은 "그날(그달) 마지막으로 보관된 모습"이고, 기록을 고치지 않은 날은 사본이 없다.
- 복사 중 실패하면 새 값 쓰기를 하지 않고 5xx 로 답한다(최신본만 바뀌고 사본이 빠지는 일 없게). 폰은 지금처럼 다시 보낸다.
- `DELETE /v1/keep/<id>`(자동으로 지키기 끄기 [지우기])는 최신본·상태 신호와 함께 그 id 의 `snap:`·`month:` 사본을 모두 지운다.
- 개발자용 읽기(출처 검사는 지금 그대로 — 꺼내기 스크립트가 본 주소 출처를 붙인다):
  - `GET /v1/keep/<id>/history` → `{ latest?: { savedAt }, days: [{ date, savedAt }], months: [{ month, savedAt }] }`(최신 것부터). 없으면 빈 목록.
  - `GET /v1/keep/<id>?day=YYYY-MM-DD` / `?month=YYYY-MM` → 그 사본 본문(없으면 404). 쿼리 없으면 지금처럼 최신본.
- 쓰기 늘어남: 기기당 하루 최대 2번(날·달이 바뀐 첫 보관). 무료 한도(하루 1,000) 안.
- 구현에서 정한 것 (#185):
  - 달 사본에도 metadata `savedAt`(그 사본이 담은 보관 시각)을 둔다 — 목록이 본문을 읽지 않고 보관 시각을 주려고. 날짜 사본과 같은 값.
  - 날을 가르는 보관 시각은 최신본 metadata 의 **서버 시각**이고, 겉봉투 `savedAt`(폰 시계)은 metadata 없는 옛 최신본에만 쓴다.
  - 복사 실패(복사 전 최신본 읽기 실패 포함)는 503. 사본을 쓴 뒤 최신본 쓰기가 실패해도(KV 하루 쓰기 한도 등) CORS 헤더가 있는 503 — CORS 없는 500 이면 폰이 연결 실패로 본다(#186, #190 리뷰).
  - 보관일이 오늘보다 **앞일 때만** 복사한다(#186, #190 리뷰). metadata 없는 옛 최신본의 겉봉투 `savedAt`(폰 시계)이 미래면 미래 날짜 사본·400일짜리 미래 달 사본이 생기던 것을 막는다. 그 경우는 사본 없이 최신본만 바뀐다(옛 최신본이 있는 동안 한 번뿐).
  - `?day=`(YYYY-MM-DD)·`?month=`(YYYY-MM) 형식이 틀리거나 둘을 함께 주면 400. `/history` 는 GET 만(그 밖 405), 출처·이름 형식 검사는 보관본 경로와 같다(미리 요청 OPTIONS 204).
  - `/history` 는 KV list 의 metadata 로 만든다. metadata 가 없거나 키 끝이 날·달 모양이 아닌 키는 빼고 준다(서버가 쓴 사본에는 늘 있다). 최신본이 없으면 `latest` 칸이 없다.

### 2. 서버 밖 주간 사본 (비공개 레포)

- Worker `GET /v1/export`: `Authorization: Bearer <EXPORT_TOKEN>`(Worker 비밀값, 요약 토큰과 별개). 출처 검사 없음(서버끼리). 토큰이 없거나 틀리면 401. 본 자리(`keep:`)의 **최신본만**(미리보기·사본 제외) `{ exportedAt, items: [{ id, savedAt, envelope }] }` 로 준다. 주고 나서 `export:last` 에 `{ at, count }` 를 쓴다.
- `GET /v1/report`(SPEC-007) 응답에 `export: { lastAt, count } | null` 을 더한다.
- 보관 지켜보기(SPEC-007 판정 표)에 줄 추가: `export` 가 있고 8일 넘음 → **실패**("서버 밖 사본이 N일째 없어요"). `export` 가 없음 → 경고("아직 서버 밖 사본이 없어요")(첫 주).
- 비공개 레포 `crowwan/dongari-keep-backup`:
  - 워크플로 `backup.yml`: 매주 일요일 23:00 UTC(월요일 08:00 KST, 보관 지켜보기 09:00 앞) + 손으로 실행(workflow_dispatch).
  - `GET $KEEP_URL/v1/export` → `keep/<id>.json`(겉봉투 그대로)로 쓰고, 이번 목록에 없는 id 파일은 지운다. `index.json`(id·savedAt·크기)도 쓴다. 바뀐 게 있으면 `GITHUB_TOKEN`(권한 `contents: write`)으로 커밋 "주간 보관본 YYYY-MM-DD".
  - 비밀값 `EXPORT_TOKEN`, 변수 `KEEP_URL`. 실패하면 GitHub 가 실패 메일을 보낸다.
  - README: 무엇인지, 암호문이라는 것, 되살리는 법(꺼내기 스크립트 `--file`), 지워 달라는 요청 때 이력 지우는 법.
- `EXPORT_TOKEN` 은 dongari 레포 비밀값 `KEEP_EXPORT_TOKEN` 에도 넣고, 보관 서버 배포 워크플로(`worker.yml`)가 배포 때 Worker 비밀값으로 넣는다(값은 로그에 찍지 않음).
- 구현에서 정한 것 (#186):
  - `/v1/export` 는 `/v1/report` 처럼 라우팅에서 출처 검사보다 먼저 처리하고 CORS 헤더가 없다. GET 말고는 405, 401·405 는 본문 없음. 비교는 요약과 같은 시간 일정 비교(`isAuthorized`). `REPORT_TOKEN` 으로는 열리지 않는다.
  - `items` 는 KV list 이름순(= id 순). `savedAt` 은 최신본 metadata 의 서버 시각, 없으면(옛 최신본) 겉봉투 `savedAt`(1절 `keptAtOf` 와 같음). `envelope` 은 저장된 JSON 을 파싱한 객체. 이름이 64자 16진수가 아니거나 본문이 JSON 객체가 아니거나 그사이 지워진 키는 뺀다(서버가 쓴 값이라 생길 일은 없다).
  - `export:last` 를 쓰지 못하면 503(본문 없음): 요약(보관 지켜보기)이 모르는 내보내기가 성공으로 끝나면 백업은 됐는데 지켜보기가 8일 뒤 틀린 실패를 낸다. 503 이면 백업 레포 워크플로가 그날 바로 실패 메일을 보낸다.
  - 최신본 목록은 KV list 한 장(최대 1,000개)만 읽는다. `list_complete` 가 false(잘림)면 잘린 목록을 주지 않고 503, `export:last` 도 쓰지 않는다(#194 리뷰): 잘린 목록이 나가면 백업 레포가 빠진 id 의 파일을 지운다. 이어 받기(cursor)는 하지 않는다(가족 몇 명이라 1,000개에 닿을 일이 없고, 닿으면 그때 나눠 받기를 만든다). `KeepStore.list` 결과에 `list_complete` 를 더했다(Cloudflare KV 그대로).
  - `/v1/report` 의 `export` 는 `export:last` 가 없거나 모양이 틀리면 null.
  - **알림의 나눔** (#194 리뷰): `export:last` 는 서버가 답을 줄 때 쓰인다. 그래서 보관 지켜보기의 8일 규칙은 **워크플로가 서버를 부르지 못한 경우**(예약 실행이 멈춤·꺼짐, 토큰 틀림 401, 서버 오류)를 잡고, **답을 받은 뒤의 실패**(응답 모양 거절·지우기 상한·0개 멈춤·커밋·push 실패)는 지켜보기가 모르고 백업 레포 워크플로의 실패 메일만 알린다.
  - 보관 지켜보기: `export` 칸이 **없는** 예전 서버 답도 받아 null(경고 "아직 서버 밖 사본이 없어요")로 본다. 그 서버는 내보내기 경로도 없어 백업 레포 워크플로가 404 로 실패 메일을 보내므로 지켜보기에서 따로 실패로 만들지 않는다(배포 사이 잠깐뿐). `export` 칸 모양이 틀리면(시각이 아님, 개수가 음수·소수) "요약 형식이 틀림" 실패. 8일은 경계를 넣지 않는다(정확히 8일은 아직 문제 아님). N 은 지난 날수의 내림. 문구 뒤에 "(마지막 내보내기 YYYY-MM-DD HH:MM KST)". 신호가 하나도 없어도 내보내기는 따로 판정한다. 실행 요약에 "서버 밖 사본 — 마지막 내보내기: … KST · 보관본 N개" 한 줄.
  - `worker.yml`: `wrangler deploy` 뒤 "내보내기 토큰 넣기" 단계가 `printf %s "$KEEP_EXPORT_TOKEN" | npx wrangler secret put EXPORT_TOKEN`(표준 입력). 배포마다 넣는다(레포 비밀값을 바꾸면 다음 배포에 따라감). 레포 비밀값이 없으면 **경고 후 건너뛴다**(배포는 성공): Cloudflare 비밀값은 배포 자체에 필요해 없으면 실패지만, 내보내기 토큰은 폰의 자동 보관과 상관없어 그 때문에 보관 서버 배포를 막지 않는다. 이미 넣은 Worker 비밀값은 배포해도 남고, 토큰이 없으면 백업 레포 워크플로가 401 로 실패 메일을 보낸다.
  - 백업 레포 파일의 원본은 dongari `ops/keep-backup/`(`.github/workflows/backup.yml`·`README.md`·`scripts/backup.mjs`·`scripts/backupPlan.ts`). 리뷰·테스트(`scripts/keepBackupPlan.test.ts`)는 dongari PR 에서 하고, 머지 뒤 개발자가 백업 레포에 옮긴다. 변환 규칙은 순수 함수 `planBackup`(Node 24 타입 지우기로 실행, `keepWatch.ts` 와 같은 제약).
  - `keep/<id>.json` 은 겉봉투 JSON 한 줄 + 줄바꿈(서버가 받은 바이트와 같다). `index.json` 은 id 순 `[{ id, savedAt, bytes }]`(줄 맞춤). 내보낸 때(`exportedAt`)는 넣지 않는다 — 넣으면 매주 바뀌어 아무도 고치지 않은 주에도 커밋이 생긴다. 커밋 날짜는 한국 날짜.
  - 안전장치: 보관본 하나라도 id 가 `^[0-9a-f]{64}$` 가 아니거나(경로 조작 막기), 응답·겉봉투 모양이 틀리거나(`{ v: 1, savedAt, iv, data }`), 같은 id 가 두 번이면 **아무것도 쓰지 않고** 실패. 실패 문구에 받은 값은 넣지 않는다(몇 번째인지만).
  - **지우기 안전장치 — 아무것도 지우지 않고 실패**하는 두 경우: (1) items 가 0개인데 레포에 `keep/<id>.json` 이 있음(1개라도), (2) 이번 목록에 없어 지울 파일이 **2개 이상**(한 번에 1개까지, `MAX_REMOVALS_PER_RUN`, #194 리뷰). 서버(KV)를 잃은 뒤 폰 한 대만 다시 보관하면 다음 내보내기가 1개라 (1)만으로는 나머지가 HEAD 에서 모두 지워진다 — 이 레포가 막으려는 바로 그 사고다. 보관본이 사라지는 길은 앱 [지우기]뿐이고 가족 몇 명이 한 주에 둘 이상 지우는 일은 드물어서 비율 대신 개수 상한을 골랐다(작은 가족에서도 같게 동작하고 문구로 설명하기 쉽다). (2)의 실패 문구에 지울 id 앞 8자를 적는다(이 레포의 파일 이름이라 찍어도 된다). 정말 지울 일이면 README "지우지 않고 멈췄을 때" 대로 그 파일을 손으로 `git rm` 하고 push 한 뒤 다시 실행한다(`index.json` 은 워크플로가 맞춘다). 레포에 파일이 없으면(처음) 0개라도 빈 `index.json` 을 쓴다. `keep/` 의 id 모양이 아닌 파일은 건드리지 않는다.
  - 손 실행과 예약 실행이 겹치지 않게 `concurrency`(끊지 않음). 서버 실패는 401(토큰 — 고칠 곳 안내)·404(예전 서버)·그 밖 HTTP·연결 실패로 나눠 `::error` 를 찍는다. 토큰·서버 주소·오류 내용은 스크립트가 찍지 않는다. 다만 `KEEP_URL` 은 변수라 GitHub 가 단계 머리(env)에 보여 준다 — 앱 화면 파일에도 들어 있는 공개 주소라 그대로 둔다(dongari 보관 지켜보기와 같음).

### 3. 개발자 꺼내기 (`scripts/keep-rescue.mjs`)

지금(최신본 → 기록 파일)에 더해:

- `--list`: 코드를 물은 뒤 있는 사본을 보여 준다: 최신본(보관 시각, KST) / 날짜별(날짜·보관 시각) / 달별(달·보관 시각). 각 줄에 풀었을 때 장부 이름·기록 건수를 같이 보인다(풀어 보고 세기).
- `--day YYYY-MM-DD` / `--month YYYY-MM`: 그 사본으로 기록 파일을 만든다. 파일 이름에 그 날·달(`우리장부-기록-2026-11-21.txt`).
- `--file <겉봉투 JSON 경로>`: 서버 대신 백업 레포 파일(`keep/<id>.json`)을 푼다. 파일 이름의 id 와 코드에서 만든 id 가 다르면 "이 코드의 파일이 아니에요"로 멈춘다.
- 출력에 코드를 찍지 않고, 기록 파일은 레포 밖(`~/Downloads`)에 만드는 규칙은 그대로.
- `scripts/keepRescue.ts` 의 제약(타입 지우기 문법만, src 불러오기 없음) 그대로.
- 구현에서 정한 것 (#185, `--file` 은 #186):
  - `--list`·`--day`·`--month`(#186 부터 `--file` 도) 는 하나만 쓴다. 날·달 형식이 틀리거나(달 01~12, 날 01~31, #186 부터 달력에 없는 날도), 옵션을 함께 주거나, 모르는 옵션·남는 인자가 있으면 쓰는 법을 찍고 종료 코드 1(코드를 묻기 전, 서버를 부르기 전).
  - `--list` 는 목록 하나 + 사본마다 GET 하나로 풀어 본다. 줄의 보관 시각은 서버 목록의 시각(한국 시간). 못 푼 사본은 그 줄에 "풀지 못했어요 (이유)" 를 적고 나머지는 보인다. 사본이 하나도 없으면 최신본 없음과 같은 안내, 목록 경로가 없는(이 기능 전) 서버면 "예전 버전이에요 (404). 보관 서버 배포를 확인하세요". 파일은 만들지 않는다.
  - 출력 모양: "최신본: 2026-11-24 09:30 보관 · 꽃동아리 · 기록 3건", 그 아래 "날짜별 사본"·"달별 사본" 묶음에 `  2026-11-21: …` 줄(없으면 "(없어요)"), 묶음 머리에 남는 기간과 꺼내는 옵션.
  - `--month` 파일 이름은 `우리장부-기록-2026-10.txt`. 고른 날·달 사본이 없으면 "2026-11-19 날짜별 사본이 서버에 없어요 (404). --list 로 있는 날·달을 보세요".
  - 꺼낸 뒤 요약 첫 줄에 "꺼낸 사본: 최신본 / 2026-11-21 날짜별 사본 / 2026-10 달별 사본 / 서버 밖 주간 사본 (백업 레포 파일)".
  - (#186, #190 리뷰) 최신본 파일 이름은 `우리장부-기록-2026-11-24-최신.txt`: 날짜는 겉봉투 `savedAt`(폰 시계)의 한국 날이라 서버 시각으로 정하는 `--day` 사본 날과 같을 수 있고, 그때 이름이 겹쳐 같은 이름 멈춤(`wx`)에 걸렸다. 서버 시각을 쓰려면 목록 요청이 하나 더 필요해 표시를 붙이는 쪽으로 했다. `--file` 은 `우리장부-기록-<겉봉투 날>-주간사본.txt`. 셋 다 앱이 보는 `.txt` 그대로라 [기록 파일 불러오기]로 열린다(앱은 이름을 보지 않는다).
  - (#186, #190 리뷰) `--list` 중 목록에는 있는데 받으려니 404 인 사본(남는 기간이 막 지났거나 그사이 지워짐)은 그 줄에 "풀지 못했어요 (목록을 받은 사이 서버에서 사라졌어요 — 남는 기간이 막 지났을 수 있어요 (404))". `--day` 는 달력에 없는 날(2026-02-30·2026-04-31)도 쓰는 법으로 멈춘다(윤년 2월 29일은 받음).
  - `--file <경로>`: `--list`·`--day`·`--month` 와 함께 못 쓰고, 경로가 없거나 `-` 로 시작하면 쓰는 법. 파일은 코드를 묻기 전에 읽어(못 읽으면 "… 를 읽지 못했어요 (ENOENT)") 바로 멈추고, 서버를 부르지 않아 `KEEP_URL` 이 필요 없다. 파일 읽기는 `keep-rescue.mjs`, 판정·풀기는 `keepRescue.ts` `rescueFile(code, 파일 이름, 글자)`.
  - `--file` 의 "다른 코드" 판정은 **파일 이름**으로 한다: 경로를 뺀 이름이 `<이 코드에서 만든 id>.json` 이 아니면(다른 사람 파일, 이름을 바꾼 파일 모두) 풀어 보기 전에 "이 코드의 파일이 아니에요. 이 코드의 파일은 백업 레포의 keep/1a2b3c4d….json 이에요"(id 앞 8자 — 코드가 아니라 해시라 찍어도 된다, 보관 지켜보기의 기기 표시와 같음)로 멈춘다. 그래서 어느 파일인지 모를 때 아무 파일로 한 번 돌리면 찾을 수 있다. 지난 주 커밋에서 꺼낸 파일도 이름은 `<id>.json` 그대로 둔다. 파일 모양이 틀리면 "파일이 보관본 모양이 아니에요", 이름은 맞는데 풀리지 않으면 지금과 같은 풀기 실패 문구.

바뀌지 않는다. (사용자 화면 "예전 날 기록 보기"는 범위 밖 — 시안 A-2 는 나중에 필요해지면.)

### 예외와 경계 상황

- 여러 기기가 같은 코드: 그날 마지막으로 보관한 기기의 모습이 사본. 자정 근처 KV 지연(최대 60초)으로 하루 어긋날 수 있음(허용).
- [지우기]는 사본을 KV list 로 찾는데, list 도 최대 60초 늦게 보인다. 사본이 생기고 1분 안에 지우면 그 사본은 TTL(31일·400일)까지 남을 수 있음(허용, #185).
- 미리보기 출처의 보관은 `preview:snap:`·`preview:month:` 로 나뉘어 본 사본과 섞이지 않는다. 내보내기는 본 자리만.
- 보관본이 1MB 를 넘으면 지금처럼 받지 않는다(사본도 안 생김).
- `/v1/export` 응답 크기: 가족 몇 명 × 수백 KB. 10MB 를 넘기 전에 나눠 받기를 생각한다(지금은 범위 밖, 기술 메모).
- 백업 레포 워크플로가 실패해도 Worker·앱은 영향 없음. 서버를 부르지 못하면 보관 지켜보기가 8일 뒤 알리고, 답을 받은 뒤 실패하면 백업 레포 실패 메일만 알린다(2절 "알림의 나눔").

## 수용 기준

- [ ] AC-1 날(KST)이 바뀐 뒤 첫 PUT 은 기존 최신본을 그 보관일 사본(31일 TTL)으로, 달이 바뀐 첫 PUT 은 달 사본(400일 TTL)으로도 남기고, 같은 날 두 번째 PUT 은 사본을 만들지 않는다 (자동)
- [ ] AC-2 metadata 없는 옛 최신본은 겉봉투 `savedAt` 으로 날을 정한다. 사본 복사가 실패하면 최신본을 바꾸지 않고 5xx (자동)
- [ ] AC-3 `GET …/history` 가 최신본·날짜·달 목록을 최신 것부터, `?day=`·`?month=` 가 그 사본을(없으면 404) 준다. 미리보기 출처는 미리보기 자리만 본다 (자동)
- [ ] AC-4 `DELETE` 가 그 id 의 사본까지 지운다 (자동)
- [ ] AC-5 `GET /v1/export` 는 토큰이 맞을 때만 본 자리 최신본 전부를 주고 `export:last` 를 남기며, `/v1/report` 에 `export` 가 실린다 (자동)
- [ ] AC-6 보관 지켜보기가 내보내기 8일 넘음을 실패, 없음을 경고로 판정한다 (자동)
- [ ] AC-7 꺼내기 스크립트 `--list`·`--day`·`--month`·`--file` 이 각각 목록·기록 파일을 만들고, 다른 코드의 파일이면 멈춘다 (자동)

## 기술 메모

- `KeepStore` 에 `put(key, value, { metadata, expirationTtl })`, `list` 의 metadata, `getWithMetadata` 를 더한다(Cloudflare KV 그대로).
- KST 날: `new Date(ms + 9h).toISOString().slice(0, 10)`. 시각 주입(테스트).
- 사본 키 모양 `snap:<id>:<YYYY-MM-DD>`·`month:<id>:<YYYY-MM>`, 자리 접두사는 `ORIGIN_KEY_PREFIXES` 그대로.
- 백업 레포는 공개 dongari 레포와 따로. 그 레포에는 암호문만 들어간다.
- 내보내기 CPU (#194 리뷰): 최신본마다 `JSON.parse` 하고 응답에서 다시 `JSON.stringify` 한다. 겉봉투는 큰 base64 문자열 하나라 빠르다 — Node 24(같은 V8)에서 잰 값: 5개 × 350KB 약 1.4ms, 10개 × 500KB 약 4ms, 20개 × 1MB 약 17ms(KV 를 기다리는 시간은 CPU 시간에 들지 않는다). 가족 몇 명 × 수백 KB 면 Workers 무료 요금제 CPU 10ms 안이다. 10ms 에 가까워지면(대략 10명 × 500KB 넘음) 저장된 글을 파싱하지 않고 그대로 이어 붙여 응답을 만들거나 나눠 받기를 만든다.
- 운영 문서: CLAUDE.md "자동 보관 서버 배포"·"보관 지켜보기"·"보관본 꺼내기" 절에 새 비밀값·워크플로·옵션을 적는다.
- 자리(#185):
  - `worker/src/keep.ts`: `KeepStore`(Cloudflare KV 의 `put(key, value, { metadata, expirationTtl })`·`getWithMetadata`·`list` 의 `metadata` 와 같은 모양 — `@cloudflare/workers-types` 의 `KVNamespace` 가 `KeepStore` 자리에 들어가는지 레포 밖에서 타입 검사로 확인), 사본 남기기 `copyBeforeOverwrite`, 목록 `getHistory`, 지우기 `deleteKeep`, 키 모양 `keepKeysOf`. 서버 시각은 `handleKeepRequest(request, env, clock)` 의 `clock`(기본 `new Date()`, 상태 신호 `seenAt`·요약 `now` 도 같은 시계). 테스트 `worker/src/index.test.ts` "SPEC-011"(가짜 KV 가 metadata·TTL·쓰기 실패를 흉내).
  - `scripts/keepRescue.ts`: 명령줄 `parseRescueArgs`, 목록 `listKeep`·`describeList`, 사본 받기 `rescueKeep(code, keepUrl, fetchFn, target)`. 테스트 `scripts/keepRescue.test.ts` "SPEC-011"(가짜 서버, 앱의 `sealKeep` 으로 잠근 사본).

  - `scripts/keepWatch.ts`: `parseReport` 의 `export`, `judgeExport`(`EXPORT_LIMIT_MS` 8일, `NO_EXPORT`). 테스트 `scripts/keepWatch.test.ts` "SPEC-011 AC-6".
