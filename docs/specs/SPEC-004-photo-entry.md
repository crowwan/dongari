# SPEC-004 사진으로 한 번에 적기

## 배경과 목표

어머니는 수입·지출을 먼저 공책(수기 장부)에 적어 둔다. 이걸 폰에서 한 줄씩 다시 치는 게 가장 큰 일이다.

목표: **손으로 쓴 장부를 사진 찍어 올리면 앱이 글씨를 읽어 기록 초안을 만들고, 어머니는 이상한 값만 고친 뒤 한 번에 장부에 넣는다.** 확인하기 전에는 아무것도 장부에 들어가지 않는다.

선행: SPEC-001 (기록 모델·수정 화면), SPEC-002 (저장).

## 동작 정의

### 기본 흐름

1. 장부 화면 [돈 들어옴] [돈 나감] 아래에 **[📷 사진으로 한 번에 적기]** 버튼(보조 버튼, 높이 56px).
2. 누르면 "사진 찍기 / 앨범에서 고르기" 선택. 사진 1장.
3. 업로드 전 미리보기 + "글씨가 잘 보이나요?" + [이 사진으로 읽기] [다시 찍기].
4. "글씨를 읽고 있어요…" 진행 화면 (목표 10초 이내, 폰 안에서 처리). 취소 가능.
5. **확인 화면**으로 이동한다.

### 확인 화면

```
┌───────────────────────────────┐
│ 사진에서 7건을 찾았어요         │
│ 노란 줄은 꼭 확인해 주세요      │
│ [사진 크게 보기]               │
├───────────────────────────────┤
│ ☑ 3월  나간 돈  대관료  40,000 │
│ ☑ 3월  나간 돈  간식비  28,340 │  ← 노란 배경 + "금액 확인" 표시
│ ☑ ?월  들어온 돈 회비 140,000  │  ← 노란 배경 + "몇 월인지 확인"
│ ☐ 3월  나간 돈  대관료  40,000 │  ← 회색 + "이미 있는 기록 같아요"
├───────────────────────────────┤
│ [ 6건 장부에 넣기 ]            │  ← 하단 고정 주 버튼
│  모두 버리기                   │
└───────────────────────────────┘
```

- 각 줄: 체크(넣을지 말지) · 월 · 들어온 돈/나간 돈 · 항목 · 금액.
- 줄을 누르면 SPEC-001 과 같은 수정 화면이 뜨고, **화면 위쪽에 원본 사진이 함께 보인다**(확대 가능). 저장하면 확인 화면으로 돌아오고 노란 표시가 사라진다.
- **노란 표시(확인 필요)** 조건:
  - 인식 모델의 확신도가 기준값보다 낮은 칸
  - 월을 찾지 못함 (기본값: 이번 달)
  - 수입/지출 구분을 찾지 못함 (기본값: 나간 돈)
  - 금액이 0 이하이거나 1,000,000원 초과
- **이미 있는 기록**: 같은 해, 같은 월·구분·금액·항목 이름의 기록이 장부에 있으면 체크 해제 + "이미 있는 기록 같아요".
- 노란 줄이 남아 있어도 넣을 수 있다. 다만 [N건 장부에 넣기] 를 누르면 "확인 안 한 줄이 2개 있어요. 그래도 넣을까요?" 를 묻는다.
- 줄 추가: 목록 맨 아래 [+ 빠진 줄 직접 추가].
- 넣은 뒤 장부 화면으로 돌아가 "6건을 넣었어요 [되돌리기]" 알림을 5초 보여준다. 되돌리기는 방금 넣은 묶음 전체를 지운다.

### 인식 규칙 (정리 단계 규칙)

- 사진 속 표·목록의 각 줄을 기록 하나로: `{ month, type, name, amount, uncertainFields[] }`.
- 날짜가 `3/15`, `3월 15일`, `3.15` 형태면 월만 쓴다. 날짜 없이 줄 위에 "3월" 같은 머리글이 있으면 그 아래 줄들에 적용한다.
- 금액의 `,` `.` `원` `₩` 은 무시. 합계·소계·잔액 줄은 기록으로 만들지 않는다.
- 항목 이름은 한글을 글자 단위로 읽지 않고, **장부에 이미 있는 항목 이름 중 하나로 분류**한다. 확신도가 낮으면 이름을 비우고 uncertain 에 넣는다.
- 이름 분류 결과가 수입 항목(회비, 지원금, 이자 등 장부에서 수입으로 쓴 이름)이거나 `+` 표시가 있으면 수입, 판단 불가는 `type` 을 비우고 uncertain 에 넣는다.
- 읽을 수 없는 줄은 만들지 않는다(지어내지 않는다).

### 예외와 경계 상황

- 모델 파일을 아직 받지 않았는데 인터넷이 없으면 "처음 한 번은 인터넷이 필요해요". 받은 뒤에는 오프라인에서도 동작한다.
- 기록을 하나도 못 찾으면 "글씨를 읽지 못했어요. 밝은 곳에서 장부가 화면에 꽉 차게 다시 찍어 주세요" + [다시 찍기] [직접 적기].
- 인식 실패·시간 초과(40초) 시 같은 안내 + [다시 시도].
- 확인 화면에서 뒤로가기 → "읽은 내용을 버릴까요?" 확인.
- 사진은 기기에 저장하지 않는다. 확인 화면을 떠나면 메모리에서도 버린다.

## 수용 기준

- [ ] AC-1 인식 결과는 확인 화면에만 보이고, [장부에 넣기] 전에는 장부·잔액이 바뀌지 않는다 (자동)
- [ ] AC-2 체크된 줄만 장부에 들어가고, 넣은 건수가 버튼 문구와 같다 (자동)
- [ ] AC-3 인식기가 uncertain 으로 준 칸, 월·구분 없음, 금액 범위 밖인 줄이 노란 표시된다 (자동)
- [ ] AC-4 장부에 같은 월·구분·이름·금액 기록이 있으면 그 줄은 체크 해제 + "이미 있는 기록 같아요" 로 보인다 (자동)
- [ ] AC-5 줄을 눌러 고치면 값이 반영되고 노란 표시가 사라진다 (자동)
- [ ] AC-6 노란 줄이 남은 채 넣으려 하면 확인을 묻는다 (자동)
- [ ] AC-7 [되돌리기] 를 누르면 방금 넣은 묶음만 지워진다 (자동)
- [ ] AC-8 인식이 실패하거나 결과가 형식에 맞지 않으면 장부를 바꾸지 않고 다시 시도 안내를 보여준다 (자동)
- [ ] AC-9 사진이 기기 밖으로 전송되지 않는다 (인식 중 네트워크 요청 없음, 모델 파일 최초 다운로드 제외) (자동)
- [ ] AC-10 "3월" 머리글 아래 줄들에 월 3 이 적용되고, 합계·소계 줄은 기록이 되지 않는다 (정리 단계 단위 테스트) (자동)
- [ ] AC-11 어머니 실제 수기 장부 사진 5장에서 금액 인식 정확도 90% 이상 (기술 검증 기준) (수동 QA)
- [ ] AC-12 어머니가 사진 1장을 올리고 이상한 줄을 고쳐 장부에 넣을 수 있다 (수동 QA — 사용성 테스트)

## 범위 밖

- 여러 장 한 번에 올리기 (사용 후 결정)
- 영수증·카드 내역 캡처 인식 (수기 장부 우선)
- 사진을 기록에 첨부해 보관

## 기술 메모

직접 만든 작은 모델을 **폰(브라우저) 안에서** 돌린다. 서버·API 비용 없음, 사진이 기기 밖으로 나가지 않음. 근거는 [ADR 002](../decisions/002-photo-recognition.md).

파이프라인:

| 단계 | 방식 | 딥러닝 |
|---|---|---|
| ① 보정 | 기울기 보정, 흑백 변환, 크기 정규화 | ✕ (canvas / OpenCV.js) |
| ② 줄·칸 나누기 | 공책 가로줄 검출 또는 행별 잉크 투영 | ✕ |
| ③-a 금액·월 숫자 | 숫자 조각 분류 (작은 CNN, 0~9 + 구분기호) | ○ |
| ③-b 항목 이름 | 이름 칸 이미지를 **알려진 이름 목록 중 하나로 분류** (작은 CNN 또는 임베딩 유사도) | ○ |
| ④ 정리 | 월 머리글 적용, 합계 줄 제외, 수입/지출 판단 (위 인식 규칙) | ✕ (순수 함수) |

- 학습: Python(PyTorch)으로 학습 → ONNX 변환 → `onnxruntime-web` 으로 실행. 모델 파일은 수 MB 이내 목표, 처음 사용 시 받아 캐시(service worker).
- 학습 데이터: 숫자는 공개 손글씨 숫자 데이터로 시작하고, **어머니 장부 사진 + 확인 화면에서 고친 정답**으로 보정한다. 이름 분류는 장부의 항목 이름 목록이 곧 클래스.
- 이름 클래스가 늘어나는 문제(새 항목): 분류 대신 임베딩 유사도 방식이면 재학습 없이 추가 가능 — 결정: 기술 검증 후.
- 인식 계층은 `PhotoRecognizer` 인터페이스로 분리 → 앱 테스트는 가짜 구현, 모델 성능은 **채점용 사진 묶음**(사진 + 정답 JSON)으로 따로 측정.
- 모델 학습 코드는 앱과 분리(`ml/` 디렉토리, 앱 빌드에 포함 안 함).
- 갤럭시 카메라 HEIF 설정 사진이 들어올 때 디코딩되는지 확인 필요.

## 열린 질문

- 어머니 수기 장부 실제 형식(줄 공책? 표? 날짜별 메모?) — 결정: 기술 검증 전 (사진 수집 후). 형식에 따라 ② 난이도가 크게 달라진다.
- 정확도 90% 에 필요한 학습 사진 수 — 결정: 기술 검증 후
- 확인 화면에서 고친 정답을 학습 데이터로 모으려면 사진을 남겨야 하는데, 현재 규칙은 "사진을 저장하지 않는다" 이다. 설정에서 켜는 "학습용 사진 모으기"(사진 + 정답을 백업 파일처럼 내보내기)로 할지 — 결정: 기술 검증 후
- 정확도가 끝내 미달하면 외부 AI(Claude 등)로 대체할지 — 결정: 기술 검증 후
