# SPEC-012 지켜보기 비공개로 옮기기와 앱 오류 알기

## 배경과 목표

2026-11-25 모니터링 점검(사용자: "모니터링이 필요한지, 지금은 어떤 작업이 되어있는지, 어떤 것까지 모니터링 할 수 있을지")에서 SPEC-007 "보관 지켜보기"의 구멍 넷을 찾았다.

1. **결과가 공개돼 있다.** dongari 는 공개 레포라 Actions 실행 요약도 누구나 볼 수 있다. 그 요약에 기기별 마지막 신호·마지막 보관 시각·앱 버전이 남는다(어머니·이모가 언제 앱을 열었는지). ADR 006 은 "Cloudflare 와 토큰을 가진 사람만 본다"고 적었다.
2. **아침 9시가 아니다.** `0 0 * * *` 예약이 실제로는 KST 오후 1~5시에 돈다. GitHub 문서: 정각은 부하가 높아 늦어지고, 심하면 빠질 수도 있다.
3. **누구 폰인지 모른다.** 기기가 해시 앞 8자로만 보인다.
4. **앱 오류는 아무도 모른다.** 오류 경계가 없어 화면을 그리다 오류가 나면 흰 화면이 되고, 개발자는 전화로만 안다. SPEC-007 은 앱 오류 수집을 범위 밖에 뒀지만, 그 뒤 이모가 쓰기 시작했고(14년 치 엑셀을 넣음) v2.8 에서 엑셀·회비 표처럼 큰 기능이 들어왔다.

이 기능이 끝나면:
- 지켜보기 결과는 **개발자만** 본다(비공개 백업 레포). 메일은 아침에 오고, 기기는 `엄마 폰 (aaa97843)` 처럼 이름으로 보인다.
- 앱에서 오류가 나면 사용자는 흰 화면 대신 **"다시 열기" 화면**을 보고, 개발자는 다음 아침 메일로 어느 기기·어느 화면·어떤 오류인지 안다.
- 장부 내용·복구 코드는 여전히 서버에 가지 않는다. 근거: [ADR 011](../decisions/011-private-watch-and-app-errors.md).

## 동작 정의

### 1절 지켜보기를 비공개 레포로

#### 기본 흐름

1. "보관 지켜보기" 워크플로는 비공개 백업 레포(`crowwan/dongari-keep-backup`, SPEC-011 2절의 주간 사본과 같은 곳)에서 돈다. dongari 레포에서는 지운다. 판정(SPEC-007 "판정" 표)은 그대로다.
2. 매일 KST 07:17(UTC 22:17)에 돈다. 정각을 피한다. 손으로도 돌린다(Run workflow).
3. 비공개 레포의 `devices.json` 에 기기 이름을 적어 두면(`{ "aaa97843": "엄마 폰" }`) 실패·경고 문구와 기기별 표에 `엄마 폰 (aaa97843)` 으로 보인다.
4. 기기의 앞 8자는 개발자가 그 폰의 복구 코드로 안다: `node scripts/keep-rescue.mjs --which` 가 복구 코드를 물어 앞 8자만 보여 준다. 서버를 부르지 않는다.

#### 판정에 더하는 것

| 상황 | 결과 | 요약에 쓰는 말 |
|---|---|---|
| 요약에 있는 기기가 이름표에 없음 | 경고(성공) | 이름 없는 기기 `aaa97843` 가 있어요. `devices.json` 에 이름을 붙여 주세요 |
| 이름표에 있는 기기가 요약에 없음 | 경고(성공) | 이름표의 `엄마 폰 (aaa97843)` 이 요약에 없어요 (보관을 지웠거나 복구 코드가 바뀜) |
| `devices.json` 모양이 틀림(JSON 아님, 값이 문자열 아님, 키가 8자 16진수 아님) | 실패 | 기기 이름 파일(`devices.json`) 모양이 틀려요 |

- `devices.json` 이 없으면 모든 기기가 "이름 없는 기기" 경고다(실패 아님).

#### 예외와 경계 상황

- 실패 메일은 워크플로의 cron 을 마지막으로 고친 사람에게 간다(GitHub 문서). 비공개 레포에 워크플로를 올리는 커밋은 개발자 계정으로 한다.
- GitHub 의 "60일 활동 없으면 예약 실행 멈춤"은 문서상 공개 레포 규칙이다. 옮기면 dongari CLAUDE.md 의 60일 안내는 지운다.
- 비공개 레포라 Actions 시간이 든다. 한 번에 1분 안쪽이라 한 달 30분쯤이다(무료 2,000분).
- 옮긴 뒤 dongari 의 지난 "보관 지켜보기" 실행 기록(공개)은 지운다. 영구 삭제라 개발자에게 확인받은 뒤 한다.

### 2절 앱 오류 알기

#### 기본 흐름

1. 화면을 그리다 오류가 나면, 흰 화면 대신 **"다시 열기" 화면**을 보인다.
   - 제목 "화면에 문제가 생겼어요"
   - 본문 "적어 둔 기록은 폰에 그대로 있어요."
   - 큰 버튼 [다시 열기]: 앱을 처음부터 다시 연다.
   - 버튼은 [다시 열기] 하나다. [기록 파일 보내기]는 두지 않는다(아래 열린 질문, #203).
   - 화면 읽기(TalkBack)가 제목부터 읽게 제목에 포커스를 준다.
2. 다음 넷을 **앱 오류**로 센다.

   | 종류 | 언제 |
   |---|---|
   | `render` | 화면 그리기 오류 (1번 화면이 뜰 때) |
   | `uncaught` | 어디서도 잡지 않은 오류 |
   | `rejection` | 어디서도 잡지 않은 Promise 거절 |
   | `save` | 기록 저장 실패: 저장 실패 띠(SPEC-002 "저장하지 못했어요", 가드에 어긋난 "앱에 문제가 있어")가 뜰 때. 이름은 실패 이유(`quota-exceeded` 등). 띠가 떠 있는 동안 다시 실패해도 한 번 |

3. 폰은 오류를 기록해 둔다. 같은 오류(종류·이름·정리한 글·화면이 같음)는 한 줄로 묶어 횟수와 처음·마지막 때만 올린다. 최근 7일만, 최대 5줄 둔다. 넘으면 마지막 때가 오래된 줄부터 버린다.
4. 오류가 생기면 상태 신호(SPEC-007)를 바로 한 번 더 보낸다. 오류 목록이 함께 실린다. 앱을 한 번 연 동안 오류 때문에 보내는 신호는 3번까지다. 못 보낸 오류는 다음 앱 열기 때의 상태 신호에 실린다(폰은 7일 동안 목록을 갖고 있으므로).
   - 보내기 전에 본문이 4KB(서버 상한)를 넘으면 마지막 때가 오래된 오류 줄부터 뺀다. 그래도 넘으면 오류 없이 보낸다. 보관 상태는 꼭 닿게 한다.
5. 서버는 상태 신호와 함께 오류 목록을 덮어쓰고, 요약(`/v1/report`)의 기기마다 싣는다.
6. 지켜보기 판정에 한 줄을 더한다.

   | 상황 | 결과 | 요약에 쓰는 말 |
   |---|---|---|
   | 어떤 기기든 오류 줄의 마지막 때가 요약 `now` 기준 36시간 안 | 실패 | `엄마 폰 (aaa97843)` 에서 앱 오류가 났어요: 회비 표(`dues`) · render · TypeError "Cannot read properties of undefined (reading '…')" · 3번 · 마지막 2026-11-25 14:02 KST |

   - 36시간은 예약 실행이 늦거나 하루 빠져도 놓치지 않게 잡은 값이다. 대신 같은 오류로 메일이 두 번 올 수 있다.
   - 36시간이 지난 오류는 실패가 아니고, 실행 요약 표에만 남는다(폰이 7일 동안 보내므로).
   - 폰 시계가 앞서 마지막 때가 `now` 보다 뒤면, 그쪽도 36시간 안일 때만 실패다(#203).
7. 실행 요약에 "앱 오류" 표를 더한다. 칸: 기기·화면·종류·이름·글·횟수·처음·마지막(KST)·위치. 위치는 소스맵으로 찾을 때 쓰고, 실패 문구에는 넣지 않는다(#203).

#### 서버에 평문으로 남는 것

| 칸 | 내용 |
|---|---|
| 종류 | `render`·`uncaught`·`rejection`·`save` |
| 이름 | `TypeError` 등 오류 이름, 40자까지 |
| 글 | **정리한** 오류 글, 120자까지 |
| 화면 | 앱 안 화면 이름(`ledger`·`dues`·`excel-import` 등). 모르면 `unknown` |
| 위치 | 앱 번들 파일 이름:줄:칸 (`index-abc123.js:1:23456`). 주소·경로는 뺀다. 없으면 뺀다 |
| 횟수, 처음 때, 마지막 때 | 폰 시각 |

- 글 정리: 숫자 덩어리는 `#`, 영문·숫자·기호가 아닌 글자 덩어리(한글 등)는 `…` 로 바꾼다. 이름·금액·메모가 오류 글에 섞여 있어도 나가지 않게 하려는 것이다. 브라우저가 만드는 오류 글은 영어라 뜻은 남는다.
  - (#203) 글 안의 주소는 파일 이름만 남기고(`…/assets/ExcelImportScreen-B2x.js?v=3` → `ExcelImportScreen-B#x.js`), 복구 코드 모양(4자 × 4 묶음)은 `…` 로 바꾼다. 줄바꿈·빈칸 여럿은 빈칸 하나다.
  - (#203) 한글 낱말 사이 빈칸은 한 덩어리로 본다(`김 민 지` → `…`, 낱말 수가 드러나지 않게).
  - (#203) 각 칸은 서버 상한(이름 1~40, 글 0~120, 화면 1~32, 위치 0~80)에 맞춰 자르고, 넘쳐 자른 칸은 끝을 `…` 로 한다. 이름이 비면 `Error`, 화면을 모르면 `unknown`.
- 장부 내용, 복구 코드, 주소(URL), 기기 정보(user agent)는 넣지 않는다.

#### 예외와 경계 상황

- **세지 않는 것**
  - 사용자 동작으로 생긴 것: 공유를 취소했을 때(`AbortError`) 등. 목록은 구현 때 정한다. → (#203) 이름이 `AbortError` 인 오류 하나. 저장 실패(`save`)는 이름이 실패 이유라 해당 없음.
  - 앱 파일이 아닌 곳에서 난 오류: 브라우저 확장, 카톡 안 브라우저가 넣은 스크립트, 내용 없는 `Script error.`.
    - (#203) `uncaught`·`rejection` 만 본다. 오류 이벤트의 파일 이름이나 스택에 주소가 있는데 그중 앱 출처(`location.origin` + `/`) 파일이 하나도 없으면 세지 않는다. 위치를 전혀 알 수 없으면(문자열 거절 등) 센다.
    - (#203) window `error` 중 오류 이벤트(`ErrorEvent`)가 아닌 것(이미지 등 파일 읽기 실패)은 오류가 아니다.
- **오류가 서버로 가지 않는 경우**
  - 읽기 전용, 복구 코드 없음, 서버 주소 없는 빌드: 상태 신호를 보내지 않으므로 오류도 서버로 가지 않는다(SPEC-007). "다시 열기" 화면은 그래도 보인다.
  - 미리보기 주소: 오류는 미리보기 자리(`preview:status:`)에 남고 요약·메일에는 나오지 않는다(SPEC-007 #128).
- **실패해도 조용히 넘어가는 경우**
  - 오류를 기록하다 또 오류가 나면(폰 저장 공간이 모자람 등) 그냥 넘어간다. 기록하다 생긴 오류는 세지 않는다.
  - "다시 열기" 화면은 앱 상태·저장소에 기대지 않는 단순한 화면이다. 이 화면이 다시 오류를 내지 않게 한다.
- **서버와 크기**
  - 예전 앱이 보내는 상태 신호(v1, 오류 칸 없음)도 서버는 계속 받는다.
  - 크기: 5줄 × 약 300바이트라 상태 신호 상한 4KB 안이다. 다만 칸 상한을 꽉 채운 줄(`…` 는 UTF-8 3바이트, `"` 는 JSON 에서 2바이트)은 한 줄 800바이트를 넘을 수 있어, 앱이 보내기 전에 잰다(기본 흐름 4번, #209 리뷰).
  - KV 쓰기: 오류 신호는 앱을 한 번 열 때 3번까지라, 하루 1,000회 한도와 거리가 멀다.
- **판정의 한계**: 판정은 폰 시각 기준이다. 폰 시계가 크게 틀리면 실패로 잡히지 않을 수 있다(표에는 남는다).

## 수용 기준

1절 지켜보기 옮기기
- [ ] AC-1 판정: `devices.json` 에 이름이 있는 기기는 실패·경고 문구와 표에 `이름 (앞 8자)` 로 보인다 (자동)
- [ ] AC-2 판정: 이름 없는 기기와 요약에 없는 이름표 기기는 경고, 이름 파일 모양이 틀리면 실패, 파일이 없으면 모두 이름 없음 경고다 (자동)
- [ ] AC-3 `keep-rescue --which` 는 복구 코드를 물어 앞 8자만 보여 주고 서버를 부르지 않는다. 형식이 틀린 코드는 거절한다 (자동)
- [ ] AC-4 비공개 레포에서 워크플로를 손으로 돌리면 요약 표가 나온다. dongari 에는 이 워크플로가 없다. 다음 날 예약 실행이 KST 오전에 돈다 (수동 QA)

2절 앱 오류 알기
- [ ] AC-5 화면 그리기 오류가 나면 "다시 열기" 화면이 보이고, [다시 열기] 는 앱을 다시 연다. 저장된 기록은 그대로다 (자동)
- [ ] AC-6 네 종류의 오류를 기록한다. 같은 오류는 묶어 횟수·때를 올리고, 7일 지난 줄은 버리고, 5줄을 넘지 않는다. 사용자 취소와 앱 밖 스크립트 오류는 세지 않는다 (자동)
- [ ] AC-7 글 정리: 숫자는 `#`, 영문·숫자·기호 밖 글자 덩어리는 `…`, 120자까지. 이름·금액이 든 오류 글을 넣어도 보내는 글에 남지 않는다 (자동)
- [ ] AC-8 오류가 생기면 상태 신호를 바로 보낸다. 앱 한 번 연 동안 3번까지이고, 못 보낸 오류는 다음 앱 열기 신호에 실린다 (자동, 가짜 서버)
- [ ] AC-9 Worker: 상태 신호 v2 의 오류 목록을 받아 요약에 싣고, v1 도 받는다. 오류 칸 모양이 틀리거나 정한 칸 밖이 있으면 400 이다 (자동, Worker 테스트)
- [ ] AC-10 판정: 36시간 안 오류는 실패와 문구, 그보다 오래된 오류는 표에만 남는다. 실행 요약에 "앱 오류" 표가 있다 (자동)
- [ ] AC-11 미리보기 개발 확인 화면(`#/dev/env`)에서 일부러 낸 오류가 다시 열기 화면을 띄우고, 서버 미리보기 자리에 오류 목록으로 남는다 (수동 QA)

## 범위 밖

- 외부 오류 수집 서비스(Sentry 등), 사용량 분석, 업타임 상시 감시
- 소스맵 올리기. 위치(파일:줄:칸)는 같은 태그를 소스맵과 함께 다시 빌드해서 찾는다.
- 지켜보기가 아예 돌지 않는 것을 알아채기(지켜보기의 지켜보기)
- 버전이 뒤처진 폰 경고, 보관본 크기 여유 경고 (다음에)
- 사용자 화면에 오류를 보냈다고 알리기

## 기술 메모

### 1절

- **원본 위치**: dongari `ops/keep-backup/` 에 둔다.
  - `.github/workflows/keep-watch.yml`, `scripts/keep-watch.mjs`, `scripts/keepWatch.ts` 를 dongari `scripts/` 에서 옮긴다.
  - 시험은 dongari `scripts/keepWatch.test.ts` 에 그대로 두고 경로만 바꾼다(backupPlan 과 같은 모양).
  - 비공개 레포에는 손으로 옮긴다(`ops/keep-backup/README.md`).
- **`devices.json`**: 비공개 레포에만 둔다. dongari(공개)에는 두지 않는다.
  - 판정은 이름표를 인자로 받는다: `judgeReport(응답, 이름표)`.
  - 이름표 읽기·모양 검사도 순수 함수로 두고 vitest 로 시험한다.
- **토큰**
  - 비공개 레포 Secrets 에 `REPORT_TOKEN` 을, Variables `KEEP_URL` 은 이미 있는 것을 쓴다.
  - dongari `worker.yml` 이 레포 비밀값 `KEEP_REPORT_TOKEN` 을 Worker 비밀값 `REPORT_TOKEN` 으로 넣게 한다. `EXPORT_TOKEN` 과 같은 모양이고, 비밀값이 없으면 경고만 한다.
  - 지금 값을 아는 곳이 없으면 새로 만들어 두 레포에 같은 값으로 넣고, "보관 서버" 배포를 다시 돌린다.
- **`keep-rescue --which`**: 이미 있는 복구 코드 → id 계산을 쓴다. 출력은 앞 8자 한 줄이고, 코드는 찍지 않는다.
- **옮긴 뒤 dongari 에서 할 일**
  - `.github/workflows/keep-watch.yml` 을 지운다.
  - CLAUDE.md "보관 지켜보기" 절을 비공개 레포 안내로 바꾸고 60일 안내를 지운다.
  - SPEC-007 기술 메모와 ADR 006 에 한 줄씩 남긴다.
  - 백업 레포 README 에서 "dongari 보관 지켜보기(매일 09:00 KST)" 부분을 고친다.

### 2절

- **오류 경계**
  - React class 부품(`componentDidCatch`)으로 `main.tsx` 의 `AppRoot` 를 감싼다.
  - "다시 열기" 화면은 토큰 CSS 만 쓰는 단순한 부품이다. 디자인 카탈로그에도 넣는다.
  - [다시 열기]는 `location.reload()`.
- **잡히지 않은 오류**: `window` 의 `error`·`unhandledrejection` 을 듣는다. 앱 파일 여부는 오류의 파일 이름·스택이 앱 출처(`location.origin`)의 파일인지로 본다.
- **저장 실패**: 저장 실패 띠를 띄우는 곳(`storageNotices`, SPEC-002)에서 `save` 로 기록한다.
- **화면 이름**: `useScreenHistory` 의 `screen.name`. 그리기 오류는 오류 경계가 마지막으로 알던 화면 이름을 쓴다.
- **폰 기록**: localStorage 에 장부와 다른 키로 둔다. 읽기·쓰기 실패는 삼킨다.
- **상태 신호 v2**
  - 모양: `{ v: 2, enabled, pendingSince?, lastKeptAt?, tooLarge, appVersion, errors?: [{ kind, name, message, screen, where?, count, firstAt, lastAt }] }`.
  - 서버는 v1·v2 를 모두 받는다. 칸 검사는 지금처럼 정한 칸만 허용한다.
  - 요약 기기 칸에 `errors` 를 더한다. 없으면 빈 목록이고, 판정 스크립트의 형식 검사에도 더한다.
  - (#202 구현) 서버 칸 검사 (`worker/src/keep.ts`)
    - `errors` 칸은 `v: 2` 에서만 받는다. v1 에 오면 빈 목록이어도 400, 모르는 버전(3 등)도 400.
    - 오류 목록은 0~5줄(빈 목록도 받음)이고 `null` 은 400. 오류 줄도 정한 칸만 받는다(`stack`·`url` 같은 칸이 있으면 400).
    - 길이는 JS 글자 수다. `count` 는 1 이상 정수(상한 없음). `firstAt ≤ lastAt` 은 보지 않는다.
  - (#202 구현) 저장과 요약
    - 받은 신호를 그대로 두고 `seenAt` 만 붙인다. `errors` 칸이 없으면 저장에도 없다.
    - 요약의 `errors` 는 폰이 보낸 순서 그대로다. v1 신호와 이 기능 전에 저장한 신호는 빈 목록이다.
  - (#202 구현) 판정 (`ops/keep-backup/scripts/keepWatch.ts`)
    - 형식 검사는 타입만 본다: 종류·이름·글·화면은 글자, 위치는 없거나 글자, 횟수는 1 이상 정수, 때는 ISO. 길이는 서버가 본다. `errors` 칸이 없는 예전 서버 답은 빈 목록이다.
    - 36시간: `now − lastAt < 36시간` 이면 실패이고, 오류 줄마다 한 줄씩 낸다. 정확히 36시간은 문제가 아니다. `lastAt` 이 `now` 보다 뒤(폰 시계가 앞섬)여도 실패로 본다. → #203 에서 고침: `|now − lastAt| < 36시간`(미래 쪽도 36시간 안일 때만, "판정의 한계"와 맞춤).
    - 문구: 글이 비었으면 이름만 쓴다(`TypeError "…"` 대신 `TypeError`). 기기 표시는 1절과 같다(이름표에 없으면 기기 `aaa97843`).
    - 화면 이름: 판정 안의 작은 표로 `Screen` 이름 10개를 사람 말로 바꾼다(장부·설정·월 정리·올해 결산·내역 적기·내역 고치기·새 장부 만들기·복구 코드로 불러오기·회비 표·엑셀 불러오기). 모르는 이름(`unknown` 등)은 `이름` 만 보인다. 앱 화면이 늘면 `scripts/keepWatch.test.ts` 의 타입 검사가 깨져 같이 고치게 했다.
    - 다듬기: 서버에서 온 글(종류·이름·글·화면)은 제어 문자(줄바꿈 등)를 빈칸으로, `|` 를 `¦` 로, 백틱을 `'` 로 바꿔 표와 문구에 넣는다. → #203: `<` `>` 는 `‹` `›`, `[` `]` 는 `［` `］`(요약 마크다운에서 HTML·링크로 읽히지 않게)도 바꾸고, 위치와 기기별 표의 앱 버전에도 쓴다.
    - "앱 오류" 표: 제목 "앱 오류 (폰 시각, KST)". 기기별 상태 표 뒤, 서버 밖 사본 앞에 둔다. 오류가 하나도 없으면 표 대신 "앱 오류가 없어요" 를 쓴다. 위치(`where`)는 칸대로 표·문구에 넣지 않는다(요약 JSON 에만 있다). → #203: 표 마지막 칸 "위치"로 넣는다(없으면 `-`, 결과는 비공개 레포에서만 보임). 실패 문구에는 여전히 넣지 않는다.
  - (#202 구현) 배포 순서
    - 이 서버가 먼저 나간다. 백업 레포에 옮기기 전의 판정은 `errors` 칸을 읽지 않으므로 그대로 돈다.
    - 새 판정은 예전 서버(`errors` 칸 없음)의 답도 받는다.
    - 앱이 v2 를 보내는 것은 #203 릴리스부터다.
- **보내기**: `AutoKeeper` 가 상태 신호를 보내는 길을 그대로 쓴다. 오류 기록기가 "보낼 일이 생김"을 알리면 보관기가 지금 상태와 오류 목록으로 신호를 보낸다.
- (#203 구현) 앱 (`src/features/errors/`, `main.tsx`)
  - **오류 경계**: `AppErrorBoundary`(class)가 `main.tsx` 의 고른 화면 전체(앱·개발 확인 화면)를 감싼다. 잡은 오류는 `componentDidCatch` 에서 기록기에 `render` 로 넘긴다(넘기다 난 오류는 삼킨다).
  - **다시 열기 화면**: `ReopenScreen`(제목·본문·`Button` 주 버튼 하나, 토큰 CSS `reopen.css` 만)을 `ReopenPage` 가 앱 화면 틀(`.app`·`.app__main`)에 그린다. 뜰 때 제목(h1, `tabIndex=-1`)에 포커스, 브라우저 제목 "화면에 문제가 생겼어요 · 우리 장부". 큰 글씨에서 낱말 단위 줄바꿈(`keep-all`). [다시 열기] = `location.reload()`.
  - **기록기**: `AppErrorRecorder` 하나를 `main.tsx` 가 화면을 고르기 전에 만들어 `window` 의 `error`·`unhandledrejection` 을 듣는다(앱을 여는 동안 난 오류도 센다). 오류 경계·App·자동 보관기가 같은 것을 쓴다.
    - 폰 기록은 localStorage `dongari:errors`(오류 줄 배열). 읽을 때 서버가 받지 않을 줄(칸 밖·길이 넘침)은 뺀다. 읽기·쓰기 실패는 삼키고, 쓰지 못해도 이번에 연 동안은 메모리의 목록으로 보낸다(저장 공간이 모자라 `save` 가 날 때).
    - 기록하는 동안 또 기록하지 않고, 기록·알리기에서 난 예외는 삼킨다.
  - **화면 이름**: App 이 `useScreenHistory` 의 `screen.name` 을 바뀔 때마다 기록기에 알린다(`setScreen`). 그리기 오류는 마지막으로 알린 이름이다. 앱이 그 전에 오류가 나면(첫 실행 물음 등) `unknown`.
  - **저장 실패**: `storageNotices.shownSaveFailure` 가 띠를 띄울 실패 이유(읽기 전용이면 없음)를 주고, App 이 그 값이 생기거나 바뀔 때 `recordSave(이유)` 한다. 띠 둘(저장하지 못했어요·앱에 문제가 있어) 다 센다. 실패마다가 아니라 띠가 뜰 때마다라, 띠가 떠 있는 동안 다시 실패해도 횟수는 그대로다.
  - **보내기**: 상태 신호는 늘 `v: 2`(오류가 없으면 `errors` 칸째 뺀다). `keepServer.statusBody` 가 본문 UTF-8 바이트를 재 4KB 를 넘으면 마지막 때가 가장 오래된 줄부터 빼고, 다 빼도 넘으면 `errors` 없이 보낸다.
    - `AutoKeeper.reportErrors()`: 기록기가 알릴 때마다(`main.tsx` 가 잇는다). 앱을 열 때 신호를 보내지 않는 경우(읽기 전용이라 `start` 를 부르지 않음, 복구 코드 없음, 서버 주소 없는 빌드)는 보내지 않고 3번에 세지도 않는다.
    - 상태 신호는 하나씩 차례로 보내고(앞 신호가 끝난 뒤), 보낼 차례에 지금 상태·오류 목록으로 만든다. 앱을 열자마자 난 오류에서 앱 열기 신호(오류 없음)가 오류 신호보다 늦게 닿아 덮지 않게.
  - **개발 확인 화면 [오류 내 보기]** (AC-11): 미리보기 빌드·개발 모드의 `#/dev/env` 에만. 누르면 그 탭 sessionStorage `dongari-dev:crash` 에 적고 앱 첫 주소로 새로 연다. `main.tsx` 가 그 표시를 읽고 지운 뒤 앱 옆에 `DevCrash` 를 그려, 앱이 한 번 그려진 뒤(화면 이름 `ledger` 를 안 뒤) 그리기 오류 `dev crash test 김민지 12,000원`(지어낸 이름·금액, 정리하면 `dev crash test … #,#…`)을 낸다. [다시 열기] 뒤에는 표시가 없어 나지 않는다. 본 주소 빌드는 `import.meta.env.DEV || __PREVIEW_BUILD__` 가 거짓이라 동적 import 째 빠진다(`npm run build` 결과에 `dongari-dev:crash` 없음).
- (#203 구현) 지켜보기 다듬기 (#209 리뷰, `ops/keep-backup/scripts/keepWatch.ts`)
  - 36시간: 미래 쪽도 36시간 안일 때만 실패(위 #202 판정 고침).
  - 다듬기: `<` `>` `[` `]` 도, 기기별 표 앱 버전과 위치에도.
  - "앱 오류" 표 마지막 칸 "위치"(없으면 `-`).
  - `devices.json` 읽기 실패: 문구 끝에 오류 코드 `(읽지 못함: EISDIR)`(코드가 없으면 오류 이름, 그것도 없으면 `(읽지 못함)`). `readDeviceNames` 결과 `{ ok: false, readError: { code? } }`.
- **이름표 읽기** (#202 에서 #207 리뷰 반영)
  - `devices.json` 을 읽다 실패하면(폴더·권한) 예외로 끝나지 않고 모양 틀림 실패로 본다. 요약은 그대로 남는다(`readDeviceNames`).
  - 맨 앞 UTF-8 BOM 은 지우고 읽는다.
  - 이름에 제어 문자(줄바꿈·탭 등)·`|`·백틱이 있으면 모양 틀림이다. 모양 틀림 문구에 이 글자들을 적었다.
  - dongari `.gitignore` 는 `/devices.json`·`/ops/keep-backup/devices.json` 만 막는다. → #203(#209 리뷰)에서 레포 전체 `devices.json` 으로 되돌렸다: 가족 이름이 든 파일이 하위 폴더에서 올라가지 않게. 시험에는 이 이름의 파일을 쓰지 않는다.
