# SPEC-006 복구 코드로 자동 보관

## 배경과 목표

폰을 바꾸거나 잃어버려도 기록이 돌아오게 한다. 로그인 없이, 앱이 만든 **복구 코드** 하나만 있으면 된다. 근거: [ADR 005](../decisions/005-cloud-keep.md).

- 저장할 때마다 전체 데이터를 폰에서 암호화해 서버에 자동으로 덮어쓴다(사람이 할 일 없음).
- 새 폰에서 복구 코드를 넣으면 마지막 보관본으로 돌아온다.
- 앱은 지금처럼 폰 안 데이터로 동작한다. 인터넷이 없으면 보관만 미뤘다가 연결되면 올린다.

선행: SPEC-002(저장·백업), SPEC-005(여러 장부, 백업 파일 형식).

## 동작 정의

### 복구 코드

- 첫 장부를 만들 때(또는 이 기능이 들어간 버전을 처음 열 때) 앱이 무작위로 만든다: 16자, 헷갈리는 글자(0/O, 1/I/L) 없는 대문자·숫자(31자 중에서), 4자씩 끊어 `HK7M-29QF-MX4P-8R2D`.
  - 이 버전을 처음 열 때: 장부가 있고 코드가 없으면 앱을 열자마자 만들어 저장한다(기록 변경이 아니라 30일 백업 안내의 변경 시각은 그대로). 읽기 전용(SPEC-002)이면 원본을 지키려고 만들지 않는다 — 설정에 코드 칸이 없다.
- 기기에 저장되고, 기록 파일(옛 이름 백업 파일)에도 들어간다(파일로 옮겨도 같은 보관 자리를 쓴다).
  - 백업 파일을 불러오면 파일의 코드를 쓴다. 코드가 없는 옛 백업 파일(이 기능 전)이면 이 폰의 코드를 그대로 쓰고, 이 폰에도 없으면(첫 실행) 새로 만든다.
- 바꿀 수 없다(이번 범위). 잃어버렸으면 새 폰에서 새 코드로 시작하고 파일 백업으로 옮긴다.

### 자동 보관 (화면 이름 "자동으로 지키기", v2.6)

- **기본 켜짐**(사용자 결정 2026-10-13). 처음에 묻지 않는다.

- 저장할 때마다 10초 모아서 한 번 올린다(연달아 적기 중 여러 번 올리지 않게). 10초는 그 묶음의 첫 저장부터 센다 — 계속 적어도 미뤄지지 않는다. 앱을 닫거나 화면을 떠날 때(`visibilitychange` hidden) 남은 것이 있으면 바로 올린다.
- 올리는 것은 지금 백업 파일 내용(모든 장부 + 복구 코드)을 암호화한 것이다. 그 안 마지막 백업 시각은 보관한 때(백업 파일과 같이 — 불러온 직후 30일 백업 안내가 뜨지 않게).
- 인터넷이 없거나 실패하면 조용히 기다렸다가 다음 저장·앱 열기·연결 회복(`online`) 때 다시 올린다. 실패했다고 혼자 다시 시도하지 않는다.
- 이 버전을 처음 연 폰(한 번도 보관하지 않음)은 장부가 있으면 앱을 열 때 바로 올린다.
- 7일 넘게 한 번도 보관하지 못했으면 장부 위에 안내 띠: "인터넷에 연결되면 기록을 자동으로 보관해요. 7일째 보관하지 못했어요" (백업 안내와 같은 자리, 같은 모양).
  - 7일은 올리지 못한 변경이 처음 생긴 때부터 7 × 24시간(정확히 7일부터). 올릴 것이 없으면(마지막 변경까지 보관함) 오래돼도 띄우지 않는다 — 잃을 것이 없다.
  - 띠에 버튼은 없다(할 일은 인터넷 연결뿐). 띠는 하나만: 저장 안내 > 보관 안내 > 30일 백업 안내.
  - 자동 보관을 껐으면 띄우지 않는다.
- 마지막 보관 시각·밀린 변경·켜짐은 이 폰에만 둔다(`dongari:keep`, 백업 파일에 넣지 않음).

### 설정 "기록 지키기" 묶음 (백업 묶음을 바꿈)

> v2.6 보강(아래, #120 구현)에서 이 묶음을 다시 짰다: 맨 위 카드 하나(복구 코드 + 주 버튼 + 상태 줄), 나머지는 "다른 방법으로 옮기기" 에 접기, "백업 파일" → "기록 파일", "자동 보관" → "자동으로 지키기". 이 절의 그림·줄 값("켜짐 · 3분 전", "준비 중")·알림 문구는 v2.5 모양이고, 지금 화면은 아래 "v2.6 보강" 이 기준이다.

```
기록 지키기
┌───────────────────────────────┐
│ 자동 보관        켜짐 · 3분 전 │  ← 마지막 보관 시각
│ 복구 코드                      │
│ HK7M-29QF-MX4P-8R2D            │  ← 크게, 고정폭 숫자, 한 줄
│ 새 폰에서 이 코드를 넣으면       │
│ 기록이 돌아와요. 가족에게도      │
│ 보내 두세요                    │
│ [↗ 복구 코드 보내기]            │  ← 보조 버튼 한 줄 (#98)
├───────────────────────────────┤
│ 백업 파일 보내기  /  불러오기    │  ← 지금 백업 그대로
│ 복구 코드로 불러오기             │
└───────────────────────────────┘
```

- [복구 코드 보내기] = 폰 공유 화면으로 "우리 장부 복구 코드: HK7M-29QF-MX4P-8R2D" 글을 보낸다(카톡 나에게·가족). 보내면 "복구 코드를 보냈어요", 공유가 안 되면 복사 + "복사했어요", 둘 다 안 되면 "보내지 못했어요. 코드를 종이에 적어 두세요". 공유 화면을 그냥 닫으면 알림 없음.
  - 시안은 코드 오른쪽 [보내기] 였지만 390 폭에서 코드가 두 줄로 갈려 버튼을 코드·안내 아래 한 줄로 내렸다(#98).
- 자동 보관 줄 값: "켜짐 · 3분 전"(방금 / N분 전 / N시간 전 / N일 전), 아직 보관한 적이 없으면 "켜짐", 끄면 "꺼짐". 보관본이 1MB 를 넘어 올리지 못했으면 보조 줄 "기록이 너무 많아 보관하지 못했어요. 백업 파일을 보내 두세요".
- 서버 주소가 정해지기 전 빌드(아래 기술 메모 `VITE_KEEP_URL` 없음): 자동 보관 줄은 누를 수 없는 "준비 중", 복구 코드 칸은 그대로 보이고, [복구 코드로 불러오기] 는 설정·첫 실행 모두 없다(받아 올 곳이 없다).
- 자동 보관 끄기: 줄을 누르면 [켜기 | 끄기] 선택 창. 끄면 서버 사본을 지울지 묻는다 "보관해 둔 기록도 지울까요?" / "남겨 두면 나중에 복구 코드로 다시 불러올 수 있어요" [남겨 두기] [지우기](위험). 어느 쪽이든 끈다(뒤로 버튼으로 창을 닫으면 [남겨 두기] 와 같다, #110. "자동 보관을 껐어요" / "자동 보관을 끄고 보관해 둔 기록을 지웠어요", 지우지 못하면 "자동 보관을 껐어요. 보관해 둔 기록은 지우지 못했어요"). 다시 켜면 지금 기록을 바로 올린다("자동 보관을 켰어요").

### 복구 코드로 불러오기

- 첫 실행(새 장부 만들기) 화면의 [기록 파일 불러오기] 옆에 **[복구 코드로 불러오기]**(위쪽 [‹ 뒤로] 로 새 장부 만들기에 돌아온다), 설정 "기록 지키기" 묶음에도 같은 줄(설정 위 화면, [‹ 설정] 으로 돌아온다).
- 화면: "복구 코드를 넣어 주세요" 글 칸(4자씩 자동 끊기, 소문자·띄어쓰기·하이픈 무시, 16자에서 자름) + 안내 "예전 폰 설정 맨 위에 있던 16자예요. 4자마다 줄표는 저절로 들어가요.(v2.5 까지 "예전 폰 설정 › 기록 지키기에 있던 16자예요")" + 아래 고정 [불러오기](16자 전에는 누를 수 없고 "16자를 모두 넣어 주세요", 받는 동안 "불러오는 중이에요").
- 받아 오면 확인 창(시안 KeepConfirm): "보관본으로 바꿀까요?" + 보관한 때("10월 12일 오후 3:20", 폰 시각)·장부("2개 (한랑드림, 우리집 가계부)")·기록("128건") + 이 폰에 기록이 있으면 "이 폰에 있던 기록은 지워져요" 와 위험 [바꾸기](백업 불러오기와 같은 규칙, 첫 실행이면 설명 없이 주 버튼). [아니요] [바꾸기]. 바꾸면 이 폰의 복구 코드도 그 코드로 바뀐다(이후 같은 자리에 보관). 백업 불러오기와 같이 올해 장부의 이번 달로 돌아가 "불러왔어요".
- 코드가 틀리거나 보관본이 없으면 "이 코드로 보관된 기록이 없어요. 코드를 다시 확인해 주세요". 인터넷이 없으면 "인터넷에 연결한 뒤 다시 눌러 주세요". 서버 오류·풀 수 없는 보관본은 "보관본을 받아 오지 못했어요. 잠시 뒤 다시 눌러 주세요". 모두 글 칸 아래 문장으로. 기기에 저장하지 못하면 "불러오지 못했어요. 기기에 저장하지 못했어요. 지금 기록은 그대로예요"(상위 버전이면 백업 불러오기와 같은 문구).

### 예외와 경계 상황

- 두 폰이 같은 코드로 보관하면 나중에 올린 쪽만 남는다. 불러오기 확인 문구에 보관 시각을 적는다("10월 12일 오후 3:20 보관본").
- 읽기 전용 상태(SPEC-002)에서는 올리지 않는다.
- 서버가 없어지거나 오래 실패해도 앱 사용과 파일 백업은 그대로다.
- 보관본 크기 상한 1MB(지금 데이터 수십 KB). 넘으면 올리지 않고 안내(설정 자동 보관 줄 보조 줄).
- 읽기 전용으로 시작했다가 백업·복구 코드로 불러와 저장 막힘이 풀리면 그 저장부터 올린다.

  - 아직 보관한 적 없음: "자동으로 지키기 켜짐".
  - 꺼짐: "자동으로 지키기 꺼짐".
  - 1MB 를 넘어 못 올림: 지금 보조 줄 문구를 상태 줄 다음 줄에 둔다. "기록이 너무 많아 보관하지 못했어요. 기록 파일을 보내 두세요".

**다른 방법으로 옮기기 (접기)**
- 흰 카드 머리 줄(높이 64, Row SemiBold + 오른쪽 ▾)을 누르면 펼쳐지고 ▾ 가 위로 돈다(220ms, 동작 줄이기면 바로). 설정을 열 때마다 처음엔 접혀 있다. 설정 위 화면(복구 코드로 불러오기·이름 고치기 등)에 다녀오면 펼친 채다(#120).
- 펼침 상태는 화면 읽기에 읽힌다(`details`/`summary` 또는 `aria-expanded`).
- 안의 네 줄(줄 72 이상, 지금 `ListRow` 모양)
  1. [↗ 기록 파일 보내기] — 보조 줄 "마지막: 2026년 10월 15일", 보낸 적 없으면 "아직 보내지 않았어요". 동작은 지금 [백업 파일 보내기].
  2. [📁 기록 파일 불러오기] — 보조 줄 "받아 둔 파일로 기록 되살리기". 동작은 지금 [백업 파일 불러오기].
  3. [🔑 복구 코드로 불러오기] — 보조 줄 "다른 폰의 코드를 넣기". 동작은 지금 그대로.
  4. [☁ 자동으로 지키기] — 값 "켜짐"/"꺼짐". 누르면 지금 [켜기 | 끄기] 선택 창(제목 "자동으로 지키기"), 끄기 확인 창 규칙 그대로.
- 30일 백업 안내 띠가 떠 있어도 접힌 채다. 띠에 [기록 파일 보내기] 버튼이 있다(SPEC-002).

**아래 묶음**
- "장부 정보" 묶음(SPEC-005)은 "다른 방법으로 옮기기" 아래로 내린다. 처음 만들 때 정한 값이라 자주 열지 않는다.
- 그 아래 "앱" 묶음, 맨 아래 [이 장부 지우기] 는 그대로다.

**코드가 없을 때 (서버 주소 없는 빌드, 읽기 전용 시작)**

### 기술 메모 (v2.6)

- `SettingsScreen`
  - 묶음 순서를 기록 지키기 카드 → 접기 → 장부 정보 → 앱으로 바꾼다.
  - 기록 지키기 카드는 `KeepCard`(`SettingsScreen.tsx`, 제목 `h2`·코드·주 `Button`·상태 줄, 카탈로그에도). 코드는 줄표 뒤 `<wbr>` 로 4자 묶음 사이에서만 줄을 바꾼다. 접기는 `aria-expanded`·`aria-controls` 버튼 + 흰 카드(접히면 안 줄은 그리지 않는다 — `details` 는 jsdom 에서 접힌 내용도 읽혀 테스트가 접힘을 확인하지 못해서). 펼침 상태는 `SettingsScreen` 의 `useState`.
  - 복구 코드가 없으면(`keep` 없음 = 서버 주소 없는 빌드, 또는 `recoveryCode` 없음 = 읽기 전용 시작) 카드·접기 대신 기록 파일 두 줄만 맨 위에(`settings-block-files`).
  - 상태 줄 글자는 `keepStatus.ts` `keepStatusText`("자동으로 지키기 켜짐 · N분 전에 보관했어요"). 예전 줄 값 함수 `keepRowText` 는 지웠다 — 접기 안 값 "켜짐"·"꺼짐" 은 `enabled` 로 바로 정한다.
  - `IconButton` 점 이름은 글자와 쉼표로 끊어 읽힌다("설정, 기록 파일 보내기 필요").
- 화면 문구는 한 곳씩 바꾸고, 테스트는 화면 글자로 찾으므로 같이 고친다. AC-15 는 `App.terms.test.tsx` 가 여러 상태(첫 실행·설정 두 빌드·접기·선택 창·확인 창·알림·안내 띠·불러오기 창)에서 화면 글자와 `aria-label` 등 화면 읽기 속성을 모두 훑는다.
- 파일 이름을 바꾸면 불러오기는 이름과 상관없이(확장자 `.txt`·`.json`) 그대로라 옛 파일도 열린다.

## 기술 메모

- 암호화: WebCrypto. 복구 코드 → HKDF(SHA-256)로 (a) 서버 이름용 해시, (b) AES-GCM 키를 따로 만든다. 서버는 이름과 암호문(+ 보관 시각)만 저장.
- 서버: 같은 레포 `worker/`(Cloudflare Workers + KV, TypeScript). `PUT /v1/keep/:id`(본문 암호문, 1MB 상한), `GET /v1/keep/:id`. CORS 는 앱 주소만(본 주소 `https://crowwan.github.io`, #128 부터 미리보기 `https://uri-jangbu-preview.pages.dev` 도). 배포는 GitHub Actions(`CLOUDFLARE_API_TOKEN` 비밀값, 사용자가 Cloudflare 개인 계정·토큰을 만들어 레포 Secrets 에 넣는다).
- 서버 API (확정, #97 `worker/src/keep.ts`). 이름(`:id`)은 64자 소문자 16진수(SHA-256), KV 키 `keep:<id>`
  - `PUT /v1/keep/:id` — 본문 JSON `{ "v": 1, "savedAt": ISO 시각, "iv": base64, "data": base64 }`, `Content-Type: application/json`. 저장(덮어쓰기) 204, 받은 JSON 그대로 저장. 1MB(1,048,576 바이트) 초과 413, 이름·본문·Content-Type 형식이 틀리면 400
  - `GET /v1/keep/:id` — 있으면 200 + 저장한 JSON, 없으면 404
  - `DELETE /v1/keep/:id` — 204 (없어도 204)
  - CORS: `Origin` 이 허용한 출처일 때만 받고 `Access-Control-Allow-Origin` 을 요청 출처 그대로(`Vary: Origin`, 메서드 GET·PUT·DELETE·OPTIONS, 헤더 Content-Type). OPTIONS 미리 요청 204. 다른 출처·출처 없음은 403
  - 출처와 KV 자리 (#128, ADR 008): 허용한 출처는 정확한 주소 둘 — 본 주소 `https://crowwan.github.io` → KV `keep:<id>`, 미리보기(Cloudflare Pages) `https://uri-jangbu-preview.pages.dev` → KV `preview:keep:<id>`. 같은 이름(같은 복구 코드)이라도 미리보기의 올리기·받기·지우기는 `preview:` 자리만 건드려, 미리보기에서 어머니 복구 코드로 불러오거나 기록 파일로 같은 코드를 갖게 돼도 본 사본을 읽거나 덮어쓰지 않는다. 미리보기 배포별 주소(`<hash>.uri-jangbu-preview.pages.dev`)·http·비슷한 주소는 403. 출처→자리 표는 `worker/src/keep.ts` `ORIGIN_KEY_PREFIXES`
  - 그 밖의 경로 404(출처와 상관없이), `/v1/keep/:id` 에 다른 메서드는 405
- KV 무료 한도: 쓰기 하루 1,000회. 10초 묶음으로 사용자 몇 명이면 한참 남는다.
- 앱 쪽 보관기는 `LedgerRepository` 저장 뒤 알림을 받아 동작(저장 계층과 분리, 테스트는 가짜 서버).
- 앱 쪽 구현 (#98, `src/features/keep/`)
  - `recoveryCode.ts`: 31자(`23456789ABCDEFGHJKMNPQRSTUVWXYZ`) 중 `crypto.getRandomValues`, 바이트 248 이상은 버려 고르게. 저장 모양은 줄표 넣은 19자. 읽을 때(`normalizeRecoveryCode`) 대문자로 바꾸고 영숫자 밖은 지운 뒤 16자·쓰는 글자인지 본다.
  - 저장 데이터: `settings.recoveryCode?`(선택 문자열, `schemaVersion` 3 그대로 — ADR 001 "스키마 버전을 올리는 기준": 옛 앱은 모르는 칸을 보지 않고 펼쳐 저장해 남긴다). 형식이 틀리면 깨진 데이터로 보지 않고 새 코드로 바꾼다. 처음 열 때 만들기는 진입점(`startKeep.withStartupRecoveryCode`), 첫 장부·불러오기는 `useLedger`.
  - `keepCrypto.ts`: 줄표 넣은 코드 글자를 원재료로 HKDF(SHA-256, 소금 `dongari-keep-v1`) — info `keep-id` 256비트 → 64자 소문자 16진수 이름, info `keep-key` → AES-GCM 256 키(꺼낼 수 없음). iv 12바이트를 매번 새로. 본문 `{ v: 1, savedAt, iv, data }`(base64).
  - `keepServer.ts`: `fetch` 클라이언트. 본문이 1MB 를 넘으면 보내지 않음, 413 도 "너무 큼". 받기는 서버에 닿지 못함(`offline`) / 404(`not-found`) / 그 밖(`failed`) 을 나눈다.
  - `AutoKeeper.ts`: `saved(data)`(저장 알림, 첫 저장부터 10초 타이머) / `start(data)`(앱 열기: 밀린 것이 있거나 한 번도 보관하지 않았으면 바로) / `flush()`(hidden·online) / `setEnabled` / `forget()`(DELETE). 상태 `{ enabled, lastKeptAt?, pendingSince?, tooLarge? }` 는 `localStorage` `dongari:keep`(`keepStateStore.ts`, 깨지면 처음 상태 = 켜짐). 올리는 중에 온 저장은 그 시각을 밀린 때로 남겨 다음 묶음에. 화면은 `useSyncExternalStore` 로 상태를 듣는다.
  - `storage/NotifyingRepository.ts`: 저장소를 감싸 `save`·`restore` 성공 때만 알린다(읽기 전용·실패는 알리지 않음).
  - `keepRestore.ts` `fetchKept`: 코드 → 이름 → GET → 풀기 → `readBackup`(백업 파일과 같은 검증·마이그레이션) → `settings.recoveryCode` 를 넣은 코드로.
  - `keepStatus.ts`: 7일 안내 판단·줄 값·보관한 때 글자(시각 주입 순수 함수). `shareCode.ts`: `navigator.share({ text })` → 안 되면(`AbortError` 빼고) `clipboard.writeText`.
  - 진입점(`main.tsx`): 빌드 환경변수 `VITE_KEEP_URL`(배포 워크플로 `deploy.yml` 이 저장소 변수 `vars.KEEP_URL` 을 넘긴다. 없으면 빈 글자 → 기능 꺼짐)이 있으면 보관기를 만들고 저장소를 `NotifyingRepository` 로 감싸 `App` 에 `keep` 으로 넘긴다. 읽기 전용이면 `start` 를 부르지 않는다.
