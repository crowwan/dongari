# SPEC-008 처음 쓰는 분 안내

## 배경과 목표

v2.6 은 "이모가 처음 쓰는 날"에 맞춰 묶었다. 장부를 처음 만들고, 한 줄 적고, 월말에 정리를 보고, 연말에 결산을 단톡방에 올리고, 폰을 바꿀 때까지 처음 쓰는 분이 막히는 곳이 있다(접근성 점검 04·06·07: 위쪽 작은 [결산] 을 찾기 어렵고, 줄을 누르면 고칠 수 있다는 걸 모르고, 복구 코드가 왜 필요한지 모른다).

이 기능이 끝나면 처음 쓰는 분은 **그 순간 눌러야 할 버튼을 가리키는 말풍선**을 네 번 본다. 한 번 지나간 말풍선은 다시 나오지 않고, 이미 쓰던 폰에서는 뜨지 않는다.

- 시안: 위 링크 "F 처음 쓰는 분 안내 말풍선" (사용자 결정 2026-10-16 "추천대로 진행" — 각 결정의 추천값).
- 선행: SPEC-001(장부 화면, v2.6 보강의 [N월 정리 보기] 자리), SPEC-003(v2.6 보강의 보내기 버튼), SPEC-006(복구 코드), #110 `useModalLayer`(창 뒤 화면 잠금).

## 동작 정의

### 말풍선 네 개

| 번호 | 뜨는 때 | 가리키는 곳 | 문구 |
|---|---|---|---|
| 1 | 장부 화면, 모든 장부 기록 0건 | 아래 고정 [+ 내역 적기] | 돈이 들어오거나 나가면 여기를 눌러 한 줄씩 적어요 |
| 2 | 장부 화면, 기록 1건 이상, 보는 달에 [N월 정리 보기] 가 보임 | [N월 정리 보기] (SPEC-001 v2.6 보강 — 달 넘기기 바로 아래) | 이번 달에 얼마 쓰고 남았는지 여기서 봐요 |
| 3 | 올해 결산 화면, 기록 1건 이상(보내기 버튼을 누를 수 있음) | 아래 고정 보내기 주 버튼 (SPEC-003 v2.6 보강, 가칭 [사진 보내기]). **보내기 버튼이 생기기 전(#122)에는 [사진으로 저장]** | 카톡·문자로 보낼 수 있어요 (#122 에서는 "사진으로 저장해 카톡·문자로 보낼 수 있어요") |
| 4 | 장부 화면, 기록 3건 이상, 자동으로 지키기를 쓸 수 있음(서버 주소 있는 빌드 + 켜짐 + 복구 코드 있음) | 위쪽 [설정] | 폰을 바꿔도 기록이 돌아오게 복구 코드를 보내 두세요 |

- 실제로 보이는 때(시안 그대로):
  - 1 = 첫 실행에서 장부를 처음 만든 직후.
  - 2 = 첫 기록을 저장하고 장부로 돌아온 직후(연달아 적기 [다 적었어요]·[← 장부로]·뒤로 버튼).
  - 3 = 기록이 있는 상태로 처음 결산을 열었을 때.
  - 4 = 3건째를 저장하고 장부로 돌아온 직후.
- 기록 수는 모든 장부를 합해 센다.
- **3번 대상(#122)**: 결산 보내기(SPEC-003 v2.6 보강)는 기술 검증 #114 결과를 기다리는 중이라 #122 에서는 지금 있는 결산 아래 [사진으로 저장] 을 가리키고, 문구는 "사진으로 저장해 카톡·문자로 보낼 수 있어요" 로 둔다. 대상과 문구는 `features/guide/guideMessages.ts` 의 `YEAR_GUIDE_TARGET`·`GUIDE_MESSAGES[3]` 한 곳에 있다. **결산 보내기 이슈에서 대상을 보내기 버튼으로 바꾸고 문구를 "카톡·문자로 보낼 수 있어요" 로 되돌린다.**
- 3번 문구는 보내기 버튼 이름(SPEC-003 열린 질문)에 맞춘다. 시안 문구는 "단톡방에 바로 보낼 수 있어요" 였는데, 버튼이 카톡 전용이 아니라 폰 공유 창을 열기 때문에 "카톡·문자로 보낼 수 있어요" 로 바꿨다(2026-10-16).
- **한 화면에 말풍선은 하나.** 둘이 같이 걸리면 번호가 작은 것만 띄운다(예: 연달아 적기로 3건을 한 번에 넣고 돌아오면 2만 띄운다). 남은 것은 다음에 그 화면이 보일 때 띄운다(장부로 돌아올 때, 앱을 열 때). 닫자마자 다음 말풍선을 잇따라 띄우지 않는다.
- 뜨는 때가 지나면 띄우지 않는다. 예를 들어 1을 보기 전에 기록이 생겼으면 1은 본 것으로 치고 넘어간다.
- 3번은 결산 화면이 [단톡방용 요약]·[결산표(제출용)] 어느 쪽이든 뜬다. 보내기 버튼은 두 쪽에 다 있다. (#122: 지금 결산 화면은 [결산표 | 항목별 합계] 이고 처음 열면 결산표라, 그 아래 [사진으로 저장] 을 가리킨다)
- 4번은 자동으로 지키기를 쓸 수 없으면(서버 주소 없는 빌드, 꺼짐, 읽기 전용이라 복구 코드 없음) 띄우지 않는다. 다음에 장부로 돌아올 때 다시 본다. 켜지면 그때 뜬다.

### 모양

```
┌───────────────────────────────┐
│ 한랑드림 2026년   [결산]  설정   │
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │  ← 뒤 화면 어둡게 (스크림)
│ ░ ┌─────────────────────────┐ │
│ ░ │ 돈이 들어오거나 나가면     ✕ │ │  ← 제목색 면 + 카드색 글자
│ ░ │ 여기를 눌러 한 줄씩 적어요   │ │
│ ░ │               [알겠어요] │ │
│ ░ └───────────▽─────────────┘ │  ← 꼬리가 가리키는 버튼 쪽
├───────────────────────────────┤
│  ┏━━━━━━ + 내역 적기 ━━━━━━┓  │  ← 가리키는 버튼: 스크림 위로, 청록 둘레
└───────────────────────────────┘
```

- 말풍선: 제목색 면(`--strong`) + 카드색 글자(`--surface`) — 알림(Toast)과 같은 짝이라 화면 위에 떠 있는 게 바로 보인다. 다크 모드에서는 이 짝이 그대로 뒤집힌다.
  - 화면 좌우 20px 안쪽 폭, 반경 16, 안쪽 여백 위 16·오른쪽 16·아래 12·왼쪽 18.
  - 글 Body 16 SemiBold, 줄 간격 1.45, 낱말 단위 줄바꿈.
  - 오른쪽 위 [✕](화면 읽기 이름 "안내 닫기"), 오른쪽 아래 [알겠어요](카드색 면 + 제목색 Bold 글자, 반경 12).
- 꼬리: 18px 마름모(45° 돌림, 반경 3)가 말풍선 위나 아래 가장자리에서 가리키는 버튼의 가운데 쪽으로 나온다.
  - 버튼이 화면 아래쪽 절반에 있으면 말풍선은 버튼 위(꼬리 아래), 위쪽 절반이면 버튼 아래(꼬리 위).
- 가리키는 버튼은 스크림 위로 올라오고 청록 둘레(3px `--accent-ink`, 바깥 3px 띄움)를 두른다.
- 뒤 화면은 스크림(`--scrim`, 라이트 60% / 다크 70%)으로 어둡게 한다.
- 나타날 때 220ms 동안 아래 6px 에서 제자리로 올라온다(`cubic-bezier(.2,.8,.2,1)`). 동작 줄이기(`prefers-reduced-motion`)가 켜져 있으면 바로 나타난다.
- 누르는 곳은 56px 이상(design.md 기준). 시안의 [알겠어요] 44px·[✕] 32px 는 이 기준에 맞춰 키운다.
- 가리키는 버튼이 화면 밖이면(목록을 내려 [N월 정리 보기] 가 위로 밀림 등) 먼저 그 버튼이 보이게 스크롤한 뒤 띄운다.
- 폰 글자를 키우면 말풍선 글도 같이 커진다(rem). 말풍선 높이는 글에 맞게 늘고, 가리키는 버튼을 덮지 않는다.

### 닫기

- 닫는 방법은 넷이다.
  - [알겠어요]
  - [✕]
  - 안드로이드 뒤로 버튼: 말풍선만 닫는다. 화면은 그대로, 장부 화면이어도 앱이 닫히지 않는다(#110 확인 창과 같은 규칙).
  - **가리키는 버튼**: 말풍선이 닫히고 그 버튼의 일을 바로 한다(내역 적기 열기, 월 정리 열기, 공유 창 열기, 설정 열기).
- 어떤 방법으로 닫든 그 말풍선은 **다시 나오지 않는다**(앱을 다시 열어도).
- 떠 있는 동안 앱을 닫으면 본 것으로 치지 않는다. 다음에 뜨는 때가 맞으면 다시 뜬다.

### 뒤 화면 잠금

- 말풍선이 떠 있는 동안 **말풍선과 가리키는 버튼만** 누를 수 있다. 나머지 화면은 어둡고, 누르기·Tab·화면 읽기가 닿지 않는다(점검 08, `inert`).
- 처음 쓰는 분이 엉뚱한 곳을 눌러 말풍선을 놓치는 일을 막는다(시안 추천 이유).
- 열리면 포커스는 가리키는 버튼으로 간다. 그 버튼은 말풍선 글을 설명으로 읽힌다(`aria-describedby`).
  - 화면 읽기 예: "내역 적기, 버튼, 돈이 들어오거나 나가면 여기를 눌러 한 줄씩 적어요".
  - Tab 순서는 가리키는 버튼 → [✕] → [알겠어요]. 닫으면 포커스는 가리키는 버튼에 남는다(가리키는 버튼을 눌렀으면 그 일이 연 화면의 규칙을 따른다).
- 화면이 바뀌어 제목에 포커스를 준 뒤(#110 `useScreenHeading`) 말풍선이 뜨면, 포커스는 말풍선 규칙대로 가리키는 버튼으로 옮긴다.

### 안내를 하는 폰, 안 하는 폰

- **안내는 이 폰에서 첫 실행 "새 장부 만들기"로 첫 장부를 만들었을 때만 켜진다.**
- 안내를 하지 않는 경우:
  - v2.6 을 처음 열 때 장부가 이미 있는 폰(v2.5 에서 넘어온 폰): 한 번도 뜨지 않는다.
  - 첫 실행에서 기록 파일(옛 백업 파일)이나 복구 코드로 불러와 시작한 폰: 이미 쓰던 분이다.
  - 장부 고르기 창의 [+ 새 장부 만들기] 로 두 번째 장부를 만들 때: 이미 쓰는 중이다.
- 설정에 "안내 다시 보기" 줄은 두지 않는다(시안 결정).

### 저장 위치

- 안내 상태는 **이 폰에만** 둔다. localStorage `dongari:guide` = `{ v: 1, active: boolean, seen: number[] }`.
  - `active`: 안내 켜짐.
  - `seen`: 닫은 말풍선 번호.
- 장부 데이터(`dongari:v2`)와 따로 두므로 저장 형식(`schemaVersion`)은 그대로다.
- **기록 파일(백업 파일)과 자동으로 지키기 보관본에는 넣지 않는다.**
  - 이유 1: 파일이나 복구 코드로 옮겨 온 폰은 위 규칙대로 안내를 하지 않으니, 옮길 값이 없다.
  - 이유 2: 기록 파일 형식을 바꾸지 않아도 된다.
  - 이유 3: 폰마다 다른 값이다(`dongari:keep` 과 같다).
- 값이 없거나 깨졌으면 안내를 끈 것으로 본다. 쓰던 분을 귀찮게 하지 않는 쪽으로 한다.
  - 예외: 장부가 없는 첫 실행이면 "아직 정하지 않음" 으로 두고, 첫 장부를 만들면 켠다.
- 저장(localStorage 쓰기)에 실패해도 화면은 막지 않는다. 그 경우 다음에 앱을 열면 같은 말풍선이 한 번 더 뜰 수 있다.

### 예외와 경계 상황

- 확인 창·선택 창이 떠 있으면 말풍선을 띄우지 않고 기다린다. 창이 닫힌 뒤 다음에 그 화면이 보일 때 띄운다.
- 저장 안내 띠(저장 실패·읽기 전용 시작)가 있으면 말풍선을 띄우지 않는다. 그 안내가 먼저다.
- 아이폰에서 키패드가 떠 있는 화면에는 말풍선이 없다(네 말풍선 모두 키패드가 없는 화면).
- 장부를 지워 기록이 줄어도 이미 본 말풍선은 다시 뜨지 않는다.

## 기술 메모

- 화면 부품 `ui/CoachMark`: 말풍선, 꼬리, 스크림, 가리키는 버튼 둘레.
  - 가리키는 버튼은 `ref` 로 받는다. 자리는 `getBoundingClientRect` 로 정하고, 화면 크기가 바뀌면(`resize`·`visualViewport`·스크롤·버튼 크기 `ResizeObserver`) 다시 잰다.
  - `body` 아래에 그린다(`createPortal`). 카탈로그 견본은 `inline`(ConfirmDialog 와 같음). 루트 `data-testid`, `data-state`(열림 번호).
- 뒤 화면 잠금은 #110 `ui/modalLayer` 의 `useModalLayer` 를 다시 쓴다.
  - 지금은 창(layer)의 조상 줄만 남기고 형제를 모두 `inert` 로 잠근다. 말풍선은 가리키는 버튼(앱 뿌리 `#root` 안)도 열어 둬야 한다.
  - 그래서 "열어 둘 요소"를 하나 더 받게 넓힌다: 창과 그 요소 각각의 조상 줄은 남기고, 그 줄의 형제만 잠근다. 확인 창·선택 창은 지금처럼 부른다(인자 없음).
  - 열 때 포커스 대상은 가리키는 버튼이다. 열 때 포커스는 화면 제목(h1)에 있었으므로(#110 `useScreenHeading`), 닫을 때는 "연 자리" 대신 열어 둔 요소(가리키는 버튼)로 돌려준다(#122: `useModalLayer(open, layer, focus, enabled, keepOpen)` 다섯째 인자. 그 버튼이 화면을 바꿔 없어졌으면 돌려주지 않는다).
- 뒤로 버튼은 `useScreenHistory().openDialog('guide-N', onBack)` 로 방문 기록 한 칸을 쌓는다(#110). `onBack` = 본 것으로 기록.
  - [알겠어요]·[✕] 는 `closeDialog()`.
  - 가리키는 버튼을 누르면 본 것으로 기록하고 그 버튼의 일을 한다. 화면을 여는 일(1·2·4)이면 `closeDialog()` 를 부르지 않고 `open()` 이 말풍선(확인 창) 칸을 그 화면 칸으로 바꿔 끼운다(`replaceState`, SPEC-005 "창에서 화면 열기"와 같은 방법 — `back()` 은 늦게 오는 popstate 라 바로 이어 쌓으면 새 화면 칸이 빠진다). 그 화면에서 뒤로 버튼 한 번에 장부로 온다. 화면을 열지 않는 일(3 사진으로 저장)은 `closeDialog()` 뒤 그 일을 한다.
- 규칙은 순수 함수 `features/guide/guideRules.ts`: `nextGuide({ state, screen, entryCount, monthHasEntries, yearHasEntries, keepUsable, blocked })` → 띄울 번호 또는 없음. 위 표와 "한 화면에 하나" 를 여기서 계산해 단위 테스트한다. `yearHasEntries` 는 결산 화면 장부에 기록이 있는지(3번). "지나면 건너뜀" 은 `withPassedGuides`: 기록이 생기면 1번을 본 것으로 적어 둔다(나중에 기록을 다 지워도 1번이 다시 뜨지 않게).
- 화면 쪽은 `features/guide/useFirstUseGuide`(상태·방문 기록, 가리키는 버튼 ref 넷) + `FirstUseGuideMark`(떠 있는 말풍선 하나). 문구·3번 대상·"가리키는 버튼이 화면을 여는지"는 `guideMessages.ts`. 모든 장부 기록 수는 `domain/book` `totalEntryCount`(기록 파일 요약과 같이 쓴다).
- `CoachMark` 의 자리는 React 상태가 아니라 틀의 CSS 변수(`--coach-anchor`·`--coach-tail-x`·`--coach-hole-*`)와 `data-side` 로 바로 그린다(스크롤·크기 바뀜마다 다시 그리지 않게, 자리 계산은 `ui/coachPlacement`). 스크림은 가리키는 버튼 자리 상자의 큰 `box-shadow` 라 버튼 자리만 밝게 남고, 틀은 `pointer-events: none` 이라 어두운 곳을 누르면 아래 `inert` 화면에 닿아 아무 일도 없다. 말풍선 층은 알림(Toast)보다 위(z-index 40)라 장부를 만든 직후 "새 장부를 만들었어요" 알림은 스크림 아래로 어둡게 보인다.
- 상태는 `features/guide/guideStore.ts`: `dongari:keep` 의 `keepStateStore` 와 같은 방식(깨지면 처음 값, 여기서는 "꺼짐").
  - 켜는 곳은 하나: App 의 첫 실행 장부 만들기 성공 직후. `requestPersistentStorage` 를 부르는 곳(SPEC-002 #93)과 같다.
  - 끄는 곳: 진입점에서 장부가 있는데 값이 없을 때(v2.5 폰), 첫 실행 불러오기(기록 파일·복구 코드) 성공 때.
- "같이 걸리면 다음 화면에" 를 위해 App 은 장부 화면이 새로 보일 때(장부로 돌아옴·앱 열기)만 `nextGuide` 를 다시 묻는다. 말풍선을 닫은 그리기에서는 묻지 않는다.
