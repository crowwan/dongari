# SPEC-002 안전한 저장과 백업

## 배경과 목표

v1 은 localStorage 에 형식 버전 없이 저장해서, 구조를 바꾸면 기존 데이터를 읽을 수 없고, 브라우저 데이터 삭제·폰 교체 시 기록이 사라진다. 브라우저는 저장 공간이 부족하면 홈 화면에 추가하지 않은 사이트의 저장소부터 지울 수 있다.

대상 기기: **갤럭시** (기본 브라우저 삼성 인터넷, 크롬도 지원). iOS 는 지원 대상이 아니다.

목표: 기록이 기기에 오래 남고, 기록 파일(옛 이름 백업 파일) 하나로 새 폰에 옮길 수 있다.

## 동작 정의

### 저장

- 모든 변경은 즉시 저장된다. "저장" 개념을 사용자에게 노출하지 않는다(입력창의 [저장] 은 기록 확정 의미).
- 저장 형식: `dongari:v2` 키 하나에 `{ schemaVersion: 3, books: Book[], settings }` — 장부마다 `ledgers: { [year]: Ledger }` (v2.4 여러 장부, SPEC-005). 키 이름은 그대로. 상세 근거는 [ADR 001](../decisions/001-storage.md). `settings.recoveryCode`(복구 코드, 선택 칸, v2.5 SPEC-006)는 버전을 올리지 않았다.
- 형식을 올릴 때(마이그레이션) 이전 버전 원본을 `dongari:v2:schema-<버전>` 키에 그대로 보관한 뒤 새 형식으로 읽는다. 보관하지 못하면 옮긴 기록은 보여 주되 저장을 막는다(아래 시작 상태 `old-version-unpreserved`).
- 기록 날짜(일, `Entry.day`, v2.2)는 선택 칸이다. 날짜 칸이 생기기 전에 적은 기록과 그때 만든 백업 파일은 날짜 없이 그대로 읽힌다. 칸을 더할 때는 `schemaVersion` 을 올리지 않았다(근거와 기준: ADR 001 "스키마 버전을 올리는 기준", #77).
- **오래 보관 요청**: 브라우저가 저장 공간이 모자랄 때 이 앱 기록을 먼저 지우지 않도록 `navigator.storage.persist()` 를 요청한다 (#93).
  - 언제: 앱을 열 때 장부가 하나라도 있으면, 그리고 첫 실행에서 첫 장부를 만든 직후(저장에 성공했을 때). 장부가 없는 첫 화면에서는 요청하지 않는다. 크롬은 사이트를 쓴 흔적·홈 화면 설치 여부로 허락을 정하므로 지킬 기록이 생긴 뒤에 묻는다. 첫 화면에서 백업을 불러와 시작한 경우는 다음에 열 때 요청한다.
  - 이미 오래 보관이면(`persisted()` 가 true) 다시 요청하지 않는다.
  - 지원하지 않는 브라우저, 요청 실패·거절은 조용히 넘어간다. 결과를 기다리지 않고 화면을 막지 않는다.
  - 상태는 화면에 보이지 않는다(설정에 줄 없음). 어머니가 보고 할 수 있는 일이 없고, 할 일(홈 화면에 추가·백업)은 이미 설정에 있다. 허락되기 쉬운 홈 화면 앱에서는 설정 [홈 화면에 추가] 줄을 숨긴다(v2.6 부터 "앱" 묶음은 [연습해 보기]·버전 줄로 늘 있다).

### 홈 화면 추가 (PWA)

- manifest + service worker 로 홈 화면 아이콘, 오프라인 실행을 지원한다.
  - 앱 이름 "우리 장부"(v2.4, SPEC-005. 그 전 "동아리 회계"), 시작 주소·범위 `/dongari/`, 주소창 없는 단독 창(`standalone`). 바탕·주소창 색은 화면 바탕(`--bg` 라이트)과 같다.
  - 아이콘: 청록 바탕에 흰 장부 한 장 (192·512, 동그랗게 잘려도 되는 maskable 512). 장부는 가운데 원 안에 그린다.
  - 화면 파일과 아이콘을 모두 미리 저장해 두어 인터넷 없이도 열린다.
- **새 버전 반영: 묻지 않는다.** 새 버전은 앱을 열 때 뒤에서 받아 바로 바꿔 두고, 화면은 다음에 열 때(또는 새로고침) 새 버전으로 뜬다. 쓰는 중에 저절로 새로고침하지 않는다(적던 내용을 지키려고).
  - 이유: 어머니가 "업데이트" 버튼을 알아서 누를 필요가 없다. 묻는 방식(새 버전이 기다리는 방식)은 앱을 완전히 닫기 전까지 옛 버전이 남아, 아래 "상위 버전 데이터" 안내대로 앱을 다시 열어도 새 버전이 뜨지 않는다.
  - 저장 형식이 바뀌는 새 버전: 새 버전이 데이터를 올려 저장한 뒤 옛 버전 화면이 뜨면 "상위 버전 데이터" 로 저장을 막고 안내한다. 이때 새 버전은 이미 받아 둔 상태라 다시 열면 새 버전이 읽는다. 같은 기기에서 두 창을 동시에 쓰는 경우는 고려하지 않는다.
- **버전 줄 (v2.6, #135)**: 설정 "앱" 묶음 맨 아래 "버전" 줄(ⓘ, 누를 수 없음, 줄 끝 › 없음). 지금 어느 버전을 보고 있는지 알 길이 없어 미리보기 QA 에서 옛 캐시 버전을 알아보지 못했다(사용자 2026-10-16).
  - 값: 본 주소 `2.6.0`(package.json 버전), 미리보기 빌드 `2.6.0 · 미리보기 abc1234`(커밋 번호 7자, 배포 워크플로 미리보기 단계만 넘긴다). 값이 길면 말줄임 없이 줄을 바꾼다.
  - 홈 화면 앱에서도 "앱" 묶음이 보이므로(SPEC-008) 이 줄도 늘 보인다.
  - **새 버전을 받아 두었으면** 줄 보조 줄 "새 버전을 받았어요" + 줄 아래 보조 버튼 [⟳ 지금 바꾸기](누르면 새로 열기). 서비스 워커가 새 버전을 받아 바꿔 두었는데 지금 화면이 옛 버전이면 보인다. 받지 못했으면 값만.
  - 앱을 쓰는 중에는 다른 화면에 아무것도 띄우지 않는다(설정에만). 저절로 새로고침하지 않는 규칙(위 "새 버전 반영")은 그대로 — [지금 바꾸기] 는 설정에서 본인이 누를 때만이다.
- **설정 화면 맨 아래 "앱" 묶음에 [📱 홈 화면에 추가] 줄**(보조 줄 "기록이 더 안전해요")을 둔다. 장부 화면 위 설치 안내 띠는 없다(2026-10-07 미리보기 QA: 첫 화면 위 띠는 없어도 된다, #56). 첫 장부 직후 한 번만 권하는 카드는 아래 "홈 화면에 추가 권하기"(#135). 화면 모양은 SPEC-001 "설정 화면".
  - **홈 화면 앱으로 열었으면(`display-mode: standalone`) 줄을 숨긴다**(묶음째). 이 화면에서 설치를 마쳐도(설치 창 [설치] 또는 브라우저 메뉴로 설치 — `appinstalled`) 바로 숨긴다.
  - 브라우저가 설치를 제안하면(`beforeinstallprompt`, 크롬·삼성 인터넷) 줄을 누를 때 **브라우저 설치 창이 바로 뜬다.** 브라우저 기본 설치 띠는 띄우지 않는다(우리 줄로 연다). 설치 창에서 취소하면 줄은 남고(설치 제안은 한 번만 쓸 수 있다) 다음에 누르면 방법 안내가 뜬다.
  - 설치 제안이 없으면 줄을 누를 때 **방법 안내 선택 창 "홈 화면에 추가하는 방법"** 이 아래에서 올라온다. 큰 글씨 순서: 삼성 인터넷 "화면 아래 오른쪽 [≡] 메뉴 → [현재 페이지 추가] → [홈 화면]", 크롬 "화면 위 오른쪽 [⋮] 메뉴 → [홈 화면에 추가] 또는 [앱 설치] → [설치]". 지금 브라우저 것만 보이고, 둘 다 아니면 둘 다 보인다. 창 아래 [확인] 이나 바깥·뒤로 버튼으로 닫는다(뒤로 버튼은 창만 닫는다, SPEC-001 선택 창 규칙).
  - 방법 안내를 편집 화면이 아닌 선택 창으로 한 이유: 적을 것이 없어 키패드가 뜨지 않고(SPEC-001 "설정 화면" — 고를 것만 있는 연도와 같은 경우), 읽고 바로 닫는 짧은 안내라 설정 목록 위에 잠깐 띄우는 편이 돌아오는 길이 짧다. 큰 글씨로 창이 화면보다 길어지면 창 안을 내려 본다.
  - 띠가 없어졌으므로 30일 [닫기] 규칙도 없앤다. 예전에 닫은 시각(`dongari:install-banner-dismissed-at`)은 더 읽지 않는다(남아 있어도 무시, 백업 파일과 무관).
- **홈 화면에 추가 권하기 (v2.6, #135)**: 설정 맨 아래 줄은 처음 쓰는 분이 찾기 어렵다(사용자 2026-10-16 "pwa 형태로 저장할 수 있게 해줘야할 것 같긴해"). 첫 장부를 만든 직후 장부 화면 위에 조용한 카드 하나:
  - "📱 홈 화면에 추가하면 앱처럼 바로 열려요" + [홈 화면에 추가] [나중에]. 노란 경고 띠가 아니라 흰 카드(같은 자리·반경·안쪽 여백), 화면 읽기가 바로 읽지 않는다(`alert` 아님).
  - 언제: 첫 실행에서 첫 장부를 만든 직후(저장에 성공했을 때) — 연습 끝 → 새 장부 만들기, 또는 [바로 시작] → 새 장부 만들기(SPEC-008). 그 뒤 [나중에] 나 설치 전까지는 앱을 다시 열어도 장부 화면 위에 있다. 이미 쓰던 폰(값 없음)·두 번째 장부·기록 파일이나 복구 코드로 불러와 시작한 폰에는 뜨지 않는다. 연습 장부에는 없다.
  - [홈 화면에 추가]: 설정 줄과 같은 동작(설치 제안이 있으면 브라우저 설치 창, 없으면 방법 안내 선택 창 — 뒤로 버튼은 창만 닫는다).
  - [나중에] 를 누르면 사라지고 다시 뜨지 않는다. 설치를 마쳐도(카드·설정 줄·브라우저 메뉴) 사라지고 다시 뜨지 않는다. 홈 화면 앱(standalone)으로 열었으면 뜨지 않는다.
  - 상태는 이 폰에만(`dongari:install-offer` `{ v: 1, status: 'waiting' | 'done' }`). 장부 데이터·기록 파일·보관본과 따로다. 값이 깨졌거나 읽지 못하면 뜨지 않는다.
  - 장부 위 띠는 하나만: 저장 안내 > 7일 보관 안내 > 30일 기록 파일 안내 > 권하기 카드. 앞 띠가 있으면 카드는 그 띠가 없어질 때까지 미룬다.

### 기록 파일 (설정 > 기록 지키기, 옛 이름 "백업")

> v2.5(SPEC-006)부터 묶음 이름은 "기록 지키기" 이고 자동 보관·복구 코드 칸이 위에 붙는다. v2.6(#120)부터 화면 말은 "기록 파일"(아래 문구는 v2.6 말로 고쳤다)이고, 두 줄은 서버 주소가 있으면 설정 "다른 방법으로 옮기기" 접기 안에, 없으면 설정 맨 위에 있다(SPEC-006 v2.6 보강). 동작은 그대로.

- 설정의 "기록 지키기"(옛 "기록 백업") 자리에 두 줄: [↗ 기록 파일 보내기](보조 줄 마지막으로 보낸 날짜), [📁 기록 파일 불러오기](보조 줄 "받아 둔 파일로 기록 되살리기"). 줄을 누르면 바로 아래 동작을 한다 (화면 모양은 SPEC-001 "설정 화면").
- **[기록 파일 보내기]**: 전체 데이터(모든 장부, SPEC-005)를 `우리장부-기록-YYYY-MM-DD.txt`(앱 이름 기준, SPEC-005. v2.3 까지 `동아리회계-백업-…`, v2.5 까지 `우리장부-백업-…`. 불러오기는 이름을 보지 않아 예전 이름 파일도 열린다, #120) 로 만들어 공유 화면(카톡 나에게 보내기, 드라이브 등)을 연다. 공유를 지원하지 않으면 파일 다운로드.
  - 날짜는 폰의 오늘 날짜. 내용은 JSON 이고 메모 앱으로 열어도 읽히게 줄을 나눈다(두 칸 들여쓰기).
  - 파일 안 마지막 백업 시각(`settings.lastBackupAt`)은 **그 파일을 만든 시각**으로 적는다. 파일에 든 기록은 그 순간까지 모두 백업된 것이므로, 새 폰에서 불러온 직후 30일 백업 안내가 뜨지 않는다. 파일을 만들 때 기기 데이터는 바꾸지 않는다(기기의 마지막 백업 시각은 아래처럼 보내기에 성공했을 때만 기록) (#38, #9 의 열린 질문 결정).
  - 확장자는 `.txt`: 안드로이드 크롬·삼성 인터넷(Chromium)의 공유 허용 목록에 `.json`·`application/json` 이 없어 `.json` 파일은 공유 화면으로 보낼 수 없다. 불러오기는 `.txt`·`.json` 둘 다 받는다.
  - 공유를 마치면 "기록 파일을 보냈어요", 내려받았으면 "기록 파일을 다운로드 폴더에 저장했어요" 알림. 이때 마지막 백업 시각(`settings.lastBackupAt`)을 기록한다(변경 시각은 그대로). 공유 화면을 그냥 닫으면 아무 알림 없이 기록하지 않는다.
- **[기록 파일 불러오기]**: 파일을 고르면 "장부 N개, 기록 M건으로 바꿀까요?" 확인 창([아니요] [불러오기]) 후 교체 (SPEC-005: 파일의 모든 장부로 전체 바꾸기라 장부 수와 모든 장부·연도의 기록 수를 묻는다. v2.3 까지는 "YYYY년 장부(기록 N건)를 불러올까요?").
  - 장부가 없는 파일이면 "장부가 없는 기록 파일이에요. 불러올까요?"
  - 이전 버전(v2, 장부 하나) 앱이 만든 파일도 저장소와 같은 마이그레이션으로 장부 하나(동아리·모임)로 읽는다 (SPEC-005 AC-8)
  - 지금 기록이 있으면 제목 아래 "지금 기록은 불러온 기록으로 바뀌어요" 를 붙이고 [불러오기] 를 위험 색으로. 지금 기록이 없으면(새 폰) 설명 없이 주 버튼.
  - [불러오기] 하면 저장하고 장부로 돌아가 올해 장부의 처음 달(이번 달)을 보여 주고 "불러왔어요" 알림. 불러온 데이터는 변경 시각을 덧붙이지 않고 파일 그대로 저장한다.
  - 저장하지 못하면 지금 기록을 그대로 두고 "불러오지 못했어요 / 기기에 저장하지 못했어요. 지금 기록은 그대로예요" 알림.
  - 장부가 하나도 없는 첫 실행 화면에는 설정으로 갈 수 없으므로 위쪽에 [📁 기록 파일 불러오기] 를 둔다(새 폰으로 옮길 때). 안내 띠에 같은 버튼이 있으면 위쪽 버튼은 숨긴다.
- 마지막 백업 후 30일이 지나고 그 사이 기록이 바뀌었으면, [설정] 버튼에 점 표시와 장부 화면에 "한 달 넘게 기록 파일을 보내지 않았어요" 안내를 보여준다.
  - "그 사이 기록이 바뀌었다": 마지막 변경 시각(`lastChangedAt`)이 마지막 백업 시각(`lastBackupAt`)보다 뒤. 백업과 같은 순간의 변경은 백업에 들어 있는 것으로 본다. 변경 시각이 없으면(한 번도 바꾸지 않음) 안내하지 않는다.
  - **백업한 적이 없으면 처음 기록을 적은 날부터 센다**: 모든 장부 기록 중 가장 이른 입력 시각(`createdAt`). 마지막 변경 시각으로 세면 계속 적는 동안 30일이 영영 차지 않고, 장부를 만든 시각은 따로 남기지 않는다. 기록 없이 장부 정보(이름·이월금)만 있으면 잃을 것이 적어 안내하지 않는다.
  - 30일 = 기준 시각부터 30 × 24시간. 정확히 30일이 되는 순간부터 보인다.
  - 시각 문자열이 깨졌으면: 변경 시각은 "모름"이라 안내하지 않고, 백업 시각은 백업한 적 없는 것으로 본다. 깨진 입력 시각은 처음 기록을 찾을 때 건너뛴다.
  - 장부 화면 위 노란 안내 띠 "한 달 넘게 기록 파일을 보내지 않았어요" + [↗ 기록 파일 보내기](설정의 보내기와 같은 동작). [닫기] 는 없다. 보내기에 성공하면(공유 완료·내려받기) 띠와 점이 바로 사라지고, 공유 화면을 그냥 닫으면 그대로 남는다. 띠는 장부 화면과 **설정 화면(제목 아래)** 에 보인다 — 점 표시를 보고 설정에 온 사람이 왜 점이 있는지 바로 알고 그 자리에서 보낼 수 있게. 월 정리·올해 결산·내역 적기에는 없다.
  - [설정] 점: 장부 화면(새 연도 시작 화면 포함) [⚙ 설정] 오른쪽 위 작은 빨간 점. 색만으로 알리지 않게 화면 읽기 이름도 "설정, 기록 파일 보내기 필요" 가 된다(v2.5 까지 "설정 백업 필요").
  - **장부 위 띠는 하나만**: 저장 안내(시작 안내·저장 실패) > 백업 안내 순으로 앞의 것이 있으면 뒤의 것은 숨긴다. 띠가 여럿 쌓이면 장부가 아래로 밀리고 무엇부터 할지 헷갈린다. 저장 실패 띠에는 같은 [기록 파일 보내기] 가 있고, 저장을 막아 둔 상태에서는 백업보다 그 안내가 먼저다. 점 표시는 띠와 상관없이 남는다. (설치 안내는 설정의 줄이라 이 순서에 없다, #56. v2.6 #135 의 첫 장부 뒤 홈 화면에 추가 권하기 카드는 이 순서의 맨 뒤 — 7일 보관 안내(SPEC-006)까지 넣으면 저장 > 보관 > 백업 > 권하기)
- 설정 [기록 파일 보내기] 줄의 보조 줄에 마지막으로 보낸 날짜를 폰 날짜로 "마지막: 2026년 9월 3일", 보낸 적이 없으면(또는 시각이 깨졌으면) "아직 보내지 않았어요". 보내면 바로 오늘 날짜로 바뀐다. 점 표시를 보고 설정에 온 사람이 왜 점이 있는지 알 수 있게.

### 예외와 경계 상황

- 저장 실패(용량 초과 등) 시 "저장하지 못했어요. 방금 적은 내역은 앱을 닫으면 사라져요. 기록 파일을 보내 두세요" 안내 + [기록 파일 보내기] 버튼. 저장 안 된 장부 줄에는 "저장 안 됨" 알약이 붙는다(v2.6 보강, #121).
- 형식이 다르거나 깨진 파일을 불러오면 아무것도 바꾸지 않고 "이 파일은 열 수 없어요 / 우리 장부에서 보낸 기록 파일인지 확인해 주세요" 알림 창([확인] 하나).
- 앱 시작 시 기기에 저장된 데이터가 깨졌거나 형식이 다르면 원본을 `dongari:v2:broken:<시각>` 키로 옮기고(`dongari:v2` 는 비움) 빈 장부로 시작한다. 다시 열어도 같은 원본을 또 보존하지 않는다. 옮겨 적지 못하면 저장을 막아 원본을 덮어쓰지 않는다.
- 기록 금액은 1원 ~ 999,999,999원 정수만 저장 데이터로 인정한다. 전년도 이월금은 음수(적자)도 된다.
- 기록 날짜(일)는 없거나, 있으면 1 ~ 장부 연도 그 달 마지막 날 정수만 인정한다(4월 31일, 윤년이 아닌 해 2월 29일은 형식이 다른 데이터). 범위 밖이면 위 깨진 데이터·형식이 다른 파일과 같이 처리한다.
- 앱 시작 시 기기에 더 높은 `schemaVersion` 데이터가 있으면 빈 장부로 보여 주되 저장을 막는다(다시 연 새 버전 앱이 다시 읽을 수 있게).
- 위 두 경우는 앱 시작 때 장부 화면 위에 안내를 띄운다 (`load()` 의 시작 상태로 구분).

  | 시작 상태 | 안내 |
  |---|---|
  | 깨진 데이터를 옮기고 빈 장부로 시작 (`recovered`) | "저장된 기록을 읽지 못해 새 장부로 시작해요. 예전 기록은 따로 보관해 두었어요" |
  | 상위 버전 데이터라 저장 막음 (`read-only`, `newer-version`) | "새 버전 앱에서 쓴 기록이 있어요. 앱을 닫았다가 다시 열어 주세요" |
  | 원본을 옮기지 못해 저장 막음 (`read-only`, `unreadable-original`) | "저장된 기록을 읽지 못했어요. 지금 적는 내용은 저장되지 않아요" + [기록 파일 불러오기] 버튼 |
  | 이전 버전 원본을 보관하지 못해 저장 막음 — 새 형식으로 옮긴 기록은 보임 (`read-only`, `old-version-unpreserved`, SPEC-005) | "기록을 새 버전으로 옮기지 못했어요. 지금 적는 내용은 저장되지 않아요" + [기록 파일 보내기] 버튼 |
- 상위 버전 안내는 "새로고침" 대신 "앱을 닫았다가 다시 열어 주세요" 라고 한다. 홈 화면 앱(standalone)에는 주소창·새로고침 버튼이 없고, 새 버전은 묻지 않고 받아 두었다가 다음에 열 때 반영하므로(위 "새 버전 반영") 다시 열면 새 버전이 뜬다 (#8, #10 의 열린 질문 결정).
- 기록 파일을 불러와 저장하면 시작 때의 문제는 풀린 것으로 보고 시작 안내를 거둔다.
  - `unreadable-original`·`old-version-unpreserved`: 사용자가 바꾸기로 했으므로 원본 위에 불러온 기록을 저장하고, 이후 저장 막힘을 푼다. 저장하지 못하면 원본이 그대로이므로 막힘도 그대로.
  - `newer-version`: 다시 연 새 버전 앱이 다시 읽어야 하므로 불러오기도 막는다. 안내 띠에 불러오기 버튼을 두지 않고, 설정에서 불러오면 "불러오지 못했어요 / 새 버전 앱에서 쓴 기록이 있어요. 앱을 닫았다가 다시 열어 주세요".
- 더 높은 `schemaVersion` 파일은 거부하고 "이 파일은 열 수 없어요 / 앱을 닫았다가 다시 연 뒤 불러와 주세요" 알림 창.

### 저장 실패 안내 문구 (시안 ①)

```
┌───────────────────────────────┐
│ 저장하지 못했어요. 방금 적은 내역은 │  ← 노란 안내 띠 (자리·순서는 그대로)
│ 앱을 닫으면 사라져요. 기록 파일을   │
│ 보내 두세요                      │
│ [↗ 기록 파일 보내기]             │
└───────────────────────────────┘
│ (🏢) 대관료                −40,000원 │
│      16일 · 지출                  │
│      (⚠ 저장 안 됨)               │  ← 노란 알약
```

- 저장 실패 띠 문구를 **"저장하지 못했어요. 방금 적은 내역은 앱을 닫으면 사라져요. 기록 파일을 보내 두세요"** 로 바꾼다.
  - 시안 ①안. ②안 "방금 적은 1건이 폰에 저장되지 않았어요…" 는 고르지 않았다.
  - "백업 파일" → "기록 파일" 은 SPEC-006 v2.6 보강 "용어 바꾸기" 를 따른다. 시안 E 모형은 용어 바꾸기 전이라 "백업 파일".
  - 버튼은 [↗ 기록 파일 보내기], 동작은 그대로.
- 내역이 아닌 것(장부 이름·이월금 바꾸기, 장부 만들기·지우기 등)을 저장하지 못했을 때도 같은 띠 하나를 쓴다. 띠를 여러 개 두지 않는다(본문 "장부 위 띠는 하나만").
- 읽기 전용 시작 상태의 시작 안내 문구(표)는 그대로다. 그 상태에서는 지금처럼 시작 안내 하나로만 알린다.

### "저장 안 됨" 표시 (시안 결정 "노란 알약 넣기")

- 장부 화면의 기록 줄 중 **이 폰에 저장되지 않은 줄**에, 보조 줄("16일 · 지출") 아래 노란 알약 **"저장 안 됨"** 을 붙인다.
  - 모양: 안내 띠와 같은 노란 면(`--warn-bg`) + 제목색 SemiBold 보조 크기(14) 글자 + 앞에 경고 아이콘(세모, 글자 크기), 반경 끝까지 둥글게.
  - 색만으로 알리지 않게 글자가 있다. 화면 읽기는 줄 버튼 이름 끝에 "저장 안 됨" 을 붙인다(예: "대관료 16일 · 지출 −40,000원 저장 안 됨"). 보이는 알약은 화면 읽기에서 숨겨 두 번 읽지 않는다.
- 어떤 줄인가: 앱을 연 뒤 **추가하거나 고친 내역** 중, 그 뒤로 저장에 한 번도 성공하지 못한 것.
  - 저장은 전체 데이터를 한 번에 쓰므로, 그 뒤 저장이 한 번이라도 성공하면 모든 알약이 사라진다. 띠도 지금처럼 사라진다.
  - 읽기 전용 시작 상태(`read-only`)에서 적거나 고친 줄에도 붙는다. 그 상태에서는 저장하지 않으므로 모두 저장 안 된 것이다.
  - 지운 내역은 표시할 줄이 없다. 띠 문구로만 알린다.
  - 알약은 이 폰 화면에서만 보이는 표시다. 저장 데이터·기록 파일에는 넣지 않는다. 앱을 닫으면 그 내역과 함께 사라진다.
- 월 정리·올해 결산에는 표시하지 않는다(장부 화면에서 고치는 일이라 장부에만).

### 용어

## 기술 메모

- 저장소 계층: `LedgerRepository` 인터페이스(`load`, `save`) + `LocalStorageRepository` 구현. `load()` 는 데이터와 시작 상태(`ok` / `recovered` / `read-only` + 이유)를 함께 돌려준다 (#11). 테스트는 메모리 구현으로. 나중에 IndexedDB·클라우드로 바꿀 때 이 경계만 교체.
- `load()` 는 깨진 원본을 옮기는 부작용이 있어 진입점(`main.tsx`)에서 앱 시작 때 한 번만 부르고, 그 결과(`LoadResult`)를 `useLedger` 에 넘긴다 (#12).
- 시작 안내·저장 실패 안내는 화면 맨 위 안내 띠로 띄운다. 저장을 막아 둔(`read-only`) 상태의 저장 실패는 시작 안내 하나로만 알린다 (#12). 저장 안 된 줄 표시는 v2.6 기술 메모 (#121).
- 스키마 검증: 불러오기·이전 시 런타임 검증 필요(`as` 금지 규칙). 결정: 외부 라이브러리 없이 수동 타입 가드 (`src/storage/schema.ts`, #7). 날짜(일)는 `isEntry` 가 1~31 정수만, 그 달 마지막 날은 장부 연도를 아는 `isLedger` 가 `domain/entryDate.isDayInMonth` 로 본다 (#77).
- 공유: `navigator.canShare({ files })` → `navigator.share`, 아니면 `<a download>` + Blob URL. 공유 취소(`AbortError`)는 조용히 끝내고, 그 밖의 공유 실패는 내려받기로 대신한다. 공유 화면은 누른 순간에만 열리므로 파일은 클릭 처리 안에서 동기로 만든다 (#8).
- 백업 파일: `src/storage/backup.ts` 의 `createBackup`·`readBackup`. 읽기는 `JSON.parse` 실패(`broken`) / 형식 다름(`not-backup`) / 상위 버전(`newer-version`)을 구분하고, 저장소와 같은 `migrate` 를 거친다. 저장소 교체는 `LedgerRepository.restore` (저장 막힘 해제 규칙 포함) (#8).
- 스키마 v3(장부 여러 개, SPEC-005 #87): `migrate.ts` 의 `MIGRATIONS[2]` 가 v2 → v3(장부 하나로), `LocalStorageRepository.load` 가 이전 버전 원본을 `dongari:v2:schema-<버전>` 에 보관(`OLD_VERSION_KEY_PREFIX`). 가드는 `isBook`(id 빈 문자열·겹침 거부, 종류 `club`/`household`), `settings.lastBookId` 는 선택 문자열(없는 장부를 가리키면 첫 장부). 결정 근거 ADR 001 "v3: 장부 여러 개".
- PWA: `vite-plugin-pwa` (`src/pwa/pwaOptions.ts`). 빌드 경로(`APP_BASE`, 기본 `/dongari/`)를 `vite.config.ts` 가 `base` 와 `pwaOptions(tokens, base)` 에 함께 넘겨 id·scope·start_url 과 서비스 워커 범위를 맞춘다. 릴리스 전 QA 미리보기는 #128 부터 다른 출처 Cloudflare Pages `https://uri-jangbu-preview.pages.dev/`(빌드 경로 `/`, localStorage·서비스 워커가 본 주소와 따로, ADR 008). 배포는 GitHub Actions(`deploy.yml`, #52·#128): main 머지 → 미리보기(Cloudflare Pages), 태그 `v*` → 본 주소(gh-pages 전체 교체). 주의는 `CLAUDE.md` 실행·배포. `registerType: 'autoUpdate'` + `injectRegister: 'script'`(등록만 하는 스크립트, 자동 새로고침 코드 없음), workbox 프리캐시(화면 파일 js·css·html + 아이콘 + manifest), 옛 캐시 정리. 본 주소 빌드에만 `navigateFallbackDenylist`(base 아래 `preview`·`lab` 화면 요청은 본 앱 `index.html` 로 답하지 않음 — 본 주소 서비스 워커가 옛 미리보기·실험 폴더를 덮지 않게, v2.1.0 서비스 워커가 깔린 뒤부터, #54. 경로 `/` 미리보기 빌드에는 없음, #128). manifest 색은 빌드 때 `tokens.css` 에서 읽는다. 아이콘은 `scripts/make-icons.mjs` 로 토큰 색 SVG → PNG (#10).
- 30일 백업 안내: `features/backup/backupReminder.ts` 의 `needsBackupReminder({ lastBackupAt, lastChangedAt, firstRecordedAt, now })`(시각 주입 순수 함수)와 저장 데이터에서 판단하는 `backupReminderFor(data, now)`. 점 표시는 `IconButton` 의 `dotLabel` (#46, 전 `TopTextButton`). 띠 하나만 고르는 순서는 `App.tsx` (#9).
- 홈 화면에 추가 줄: `features/install` (`installRules` 줄 표시 조건 `shouldOfferInstall`·브라우저 구분 `browserKind`, `installPrompt` 설치 제안을 화면 밖에서 받아 둠 — 설정 화면을 떠났다 와도 잃지 않게, `InstallGuide` 브라우저별 순서). 줄과 방법 안내 선택 창은 `SettingsScreen` 이 그린다(선택 창 이름 `settings-install-guide`, #135 부터 누름 동작은 `useInstallAction`·창은 `InstallGuideSheet` 로 권하기 카드와 같이 쓴다). iOS 전용 메타(apple-*)는 두지 않는다 (#10, #56).
- 버전 줄(#135): `features/version/appVersion.ts` — `versionLabel(version, buildSha)`(값), `createUpdateWatcher(navigator.serviceWorker)`(새 버전 받음). 버전은 vite `define` `__APP_VERSION__`(package.json), 커밋 번호는 빌드 환경변수 `VITE_BUILD_SHA`(`deploy.yml` 미리보기 빌드 단계만 `${GITHUB_SHA::7}`, 본 주소 태그 빌드는 안 넘김). 새 버전 판단: 앱 코드는 등록 스크립트(`registerSW.js`)를 건드리지 않고, 모듈을 읽을 때 `navigator.serviceWorker.controller` 가 있었는지(옛 워커가 이 화면을 다룸) 적어 두고 `controllerchange` 를 듣는다. `registerType: 'autoUpdate'` 는 새 워커를 기다리지 않고 바로 활성화(skipWaiting)하고, 활성화되면 그 등록이 다루던 화면의 controller 가 새 워커로 바뀌며 `controllerchange` 가 온다(clients.claim 없이도 — 이미 다루던 화면이라). 처음 연 화면(controller 없음)은 이 알림을 세지 않는다. 받기 시작은 모듈 읽을 때라 `registerSW.js`(페이지 load 뒤 등록)보다 앞선다. `registration.waiting`(설치됐지만 기다리는 새 워커)은 skipWaiting 이라 따로 보지 않는다. 설정 `SettingsScreen` `version` 으로 주입(테스트는 가짜 `EventTarget` + `controller`), [지금 바꾸기] = `location.reload()`.
- 권하기 카드(#135): 조건 `features/install/installOffer.ts` `showsInstallOffer`(상태·standalone·설치됨·연습·다른 띠), 상태 `localInstallOfferStore`(`dongari:install-offer`, `main.tsx` 가 `AppRoot` → `App` `installOfferStore` 로 넘김, 연습 App 에는 없다). [홈 화면에 추가] 동작은 설정 줄과 같은 `useInstallAction`(+ 방법 안내 `InstallGuideSheet`, 장부 선택 창 이름 `ledger-install-guide`), 카드는 `InstallOfferCard`. `App` 이 첫 장부 만들기 성공 때 `waiting` 을 적고, [나중에]·설치 완료 때 `done`.
- 오래 보관 요청: `storage/persist.ts` 의 `requestPersistentStorage(storageManager = navigator.storage)` — `persisted()` 가 false 일 때만 `persist()`, API 없음·예외는 false(테스트는 가짜 storageManager 를 넣는다). 부르는 곳은 둘: 진입점(`main.tsx`, 읽은 데이터에 장부가 있을 때)과 `App` 의 장부 만들기(첫 실행에서 저장 성공 직후). 둘 다 `void` 로 기다리지 않는다 (#93).
