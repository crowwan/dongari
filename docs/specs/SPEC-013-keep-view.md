# SPEC-013 보관본 들여다보기

## 배경과 목표

2026-11-25 사용자: "지금 사본 데이터를 내가 시각적으로 볼 수 있는 페이지도 필요할 것 같아. 어떤 데이터가 어떻게 들어있는지 일종의 데이터베이스 보는 느낌으로".

보관본은 지금 여러 곳에 있다(SPEC-006 최신본, SPEC-011 날짜별·달별 사본과 비공개 백업 레포의 주간 사본). 그런데 개발자가 볼 수 있는 도구는 꺼내기 스크립트뿐이다. 이 스크립트는 사본 목록을 장부 이름·기록 건수로 보여 주거나, 기록 파일을 하나 만들어 줄 뿐이다. 그래서 사본 안에 무엇이 어떻게 들어 있는지, 두 사본이 어떻게 다른지 알려면 기록 파일 JSON 을 직접 읽어야 한다.

이 기능이 끝나면 개발자는 **내 맥에서** 도구를 켜고, 기기별 사본을 DB 를 보듯 본다.
- **복구 코드 없이**: 겉 정보(시각·크기·있는 곳·남는 기간)를 본다.
- **복구 코드가 있으면**: 구조·표·비교까지 본다.

도구는 읽기만 한다. 사용자 화면은 바뀌지 않고, 앱 릴리스도 필요 없다. ADR 005 의 "서버도 개발자도 복구 코드 없이는 내용을 모른다"는 그대로다.

시안: https://claude.ai/artifact/WG8KFKKMwK57vfZQYhVVmC (지어낸 데이터). 고른 것은 네 가지 모두 추천안이다: 왼쪽 사본 목록 + 오른쪽 탭, 복구 코드는 페이지 입력칸에 넣고 페이지 안에서 풀기, 첫 단계에 목록·겉 정보·구조·표·비교를 한 번에, 서버와 백업 레포를 둘 다 출처로.

## 동작 정의

### 기본 흐름

1. **켜기.** dongari 폴더에서 `node scripts/keep-view.mjs` 를 실행하면 `http://127.0.0.1:7788/` 에 페이지가 열리고 주소를 찍는다. 포트는 `--port` 로 바꾼다(1024~65535 — 80 이면 브라우저가 Host 에서 포트를 빼서 Host 검사에 걸린다).
2. **사본 목록 (왼쪽).** 기기마다 사본을 시각·크기와 함께 묶어 보인다.

   | 묶음 | 어디서 | 남는 기간 |
   |---|---|---|
   | 최신본 | 서버 `GET /v1/keep/<id>/history` 의 `latest` | 다음 보관 때 바뀜 |
   | 날짜별 | 같은 목록의 `days` | 31일 |
   | 달별 | 같은 목록의 `months` | 400일 |
   | 주간 | 백업 레포 클론의 커밋 이력(`keep/<id>.json` 이 바뀐 커밋) | 계속 |

   - 기기 목록은 백업 레포 클론의 `index.json` 에서 가져온다.
   - 이름은 `devices.json`(SPEC-012 1절)에서 붙이고, 없으면 "이름 없음"과 id 앞 8자를 보인다.
3. **겉 정보 (코드 없이).** 고른 사본의 다음 항목을 보인다.
   - 기기 이름과 보관 자리 id(64자)
   - 사본 종류, 있는 곳(KV 키 `snap:<id>:<날>` 또는 `<커밋>:keep/<id>.json`)
   - 서버가 받은 때(KST, 주간 사본은 백업 레포에 넣은 커밋 시각), 크기와 1MB 한도의 몇 %인지
   - 남는 기간, 이 기기의 사본 개수
     - 날짜별 사본은 그 날 다음 날 0시(KST) 이후의 첫 보관 때 만들어지므로 "그 날 다음 날 0시 + 31일"까지는 적어도 남는다고 적는다. 달별은 "다음 달 1일 0시 + 400일".
   - 겉봉투(`{ v, savedAt, iv, data }`, `data` 는 앞부분만)
4. **풀기.**
   - 페이지 입력칸에 복구 코드를 넣으면 페이지가 코드에서 id 를 계산한다. 그 기기의 id 와 같으면 이 기기의 사본이 모두 풀린다.
   - 다르면 "이 기기의 코드가 아니에요"와 함께 그 코드의 id 앞 8자를 보인다. 다른 기기의 코드인지 알 수 있게 하려는 것이다.
   - 코드는 그 탭 메모리에만 둔다. 로컬 서버로도 보내지 않는다. [잠그기]를 누르거나 탭을 닫으면 잊는다.
5. **코드로 열기.** 목록에 없는 기기(지난 주간 사본 뒤에 처음 보관한 기기)는 위쪽 입력칸에 코드를 넣어 연다. 페이지가 id 를 계산하면, 로컬 서버가 그 id 의 서버 사본 목록을 받아 온다.
6. **구조 (탭).** 코드로 풀면 이 탭으로 넘어간다. 잠긴 기기의 구조·표·비교 탭은 "잠겨 있어요"만 보인다.
   - 저장 데이터를 나무로 보인다: `StoredData` → `books[]` → 장부마다 `ledgers{해}`(내역 수·이월금·월 회비) / `members[]` / `dues` → `settings`.
   - 마디마다 JSON 크기(줄바꿈·들여쓰기 없이 잰 UTF-8 바이트)를 붙이고, `settings.recoveryCode` 는 가린다.
   - 아래에는 "내역 칸 채움" 표를 둔다. 칸·종류·필수/선택·채운 줄 수·비율을 보여 줘서, 예를 들어 `day` 나 `payers`, `sourceText` 가 몇 줄에 있는지 본다. 칸은 앱의 `Entry` 칸과 같고, 옛 형식 사본에서는 그 형식에 없던 칸(`payers`·`sourceText`) 줄을 뺀다.
7. **표 (탭).**
   - 장부, 해, 내역, 회원, 낸 분 다섯 표를 둔다.
   - 장부·해로 거르고, 글로 찾고, 칸 머리를 눌러 정렬한다. 줄을 누르면 그 줄의 원본 JSON 을 아래에 보인다.
     - 해 칸이 없는 표(장부·회원)는 해로 거르지 않는다(해 고르기가 꺼진다). 해는 `ledgers` 키 글자로 거르고, 숫자가 아닌 키는 그 글자로 보이며 정렬하면 숫자 해 뒤에 온다.
     - 같은 기기의 다른 사본으로 바꾸면, 그 사본에 없는 장부·해는 "모든 장부"·"모든 해"로 되돌린다(고르기 칸과 거르기가 어긋나 표가 0줄이 되지 않게).
     - 찾기는 칸에 보이는 글과 쉼표 없는 숫자에서 대소문자 없이 찾는다(`42,000`·`42000` 둘 다).
     - 정렬은 숫자는 크기 순, 글은 글자 순이고, 빈 칸은 오름·내림 어느 쪽이든 뒤에, 같은 값은 원래 순서대로 둔다.
     - 장부·해 줄의 원본은 안의 해·회원·내역 목록을 줄여(`[… 52줄]`) 보인다. 그 줄은 해·회원·내역 표에서 본다.
   - 한 번에 300줄까지 그리고 "N / 모두 M줄"을 보인다(잘렸으면 "· 앞 300줄만").

   | 표 | 칸 |
   |---|---|
   | 장부 | 이름, 종류, 해 범위, 내역 수, 회원 수, 만든 때 |
   | 해 | 장부, 해, 이월금, 월 회비, 내역 수, 수입, 지출, 남은 돈 |
   | 내역 | 장부, 해, 월, 일, 종류, 이름, 금액, 낸 분(이름), 엑셀 글, 적은 때 |
   | 회원 | 장부, 이름, 들어온 달, 그만둔 달, 쉬는 달, 시작 남은 돈 |
   | 낸 분 | 장부, 해, 월, 내역 이름, 회원, 몫 |

8. **비교 (탭).** 같은 기기의 두 사본(앞·뒤)을 고르면 다음을 보인다.
   - 내역을 `id` 로 맞춰 더해진 줄, 빠진 줄, 바뀐 줄과 그 칸(`앞 → 뒤`)
   - 회원 더해짐·빠짐
   - 해별 남은 돈이 달라진 해
   - 바뀐 줄은 120줄까지 그리고 "모두 N줄"을 보인다. 줄은 빠진 줄 → 바뀐 줄 → 더해진 줄 순이고, 그 안에서는 날짜(해·월·일)가 늦은 것부터다.
   - 처음 앞·뒤는 왼쪽에서 고른 사본을 뒤에, 그보다 먼저 받은 사본 중 가장 가까운 것(받지 못한 사본·같은 때 받은 사본은 뺀다)을 앞에 둔다. 고른 사본이 가장 먼저 받은 것이면 고른 사본을 앞에, 그다음에 받은 사본을 뒤에 둔다.
   - 그렇게 정할 사본이 없으면(다른 사본을 받지 못했거나 같은 때 받은 사본뿐) 앞·뒤를 모두 고른 사본으로 두고 견주지 않으며 "이 사본과 견줄 다른 사본이 없어요" 한 줄을 보인다. 앞·뒤는 직접 고를 수 있고, 둘이 같은 사본이면 견주지 않는다.

### 읽기만 한다

- 보관 서버에는 GET 만 보낸다. 쓰기·지우기·되살리기·기록 파일 만들기는 없다. 되살리기는 지금처럼 `keep-rescue` 로 한다.
- 풀린 내용과 복구 코드는 파일·로그·주소창·브라우저 저장소 어디에도 남기지 않는다.
- `127.0.0.1` 에만 연다. 같은 와이파이의 다른 기기는 들어올 수 없다.

### 예외와 경계 상황

- **출처를 못 쓸 때.** 빠진 출처만 빼고 나머지는 그대로 보인다. 위쪽에 안내를 한 줄 둔다.
  - `KEEP_URL` 이 없으면: 서버 사본 없이 백업 레포만 쓴다.
  - 백업 레포 클론이 없으면(`../dongari-keep-backup`, 다른 곳이면 `KEEP_BACKUP_DIR`): 주간 사본이 없고, 기기 목록은 "코드로 열기"로만 만든다.
- **서버 문제.** 그 기기의 서버 사본 자리에 꺼내기 스크립트와 같은 문구를 보인다.
  - 서버에 닿지 못함
  - 예전 서버라 목록 경로가 없음(404)
  - 목록을 받은 사이 사본이 사라짐(31일이 막 지남, 404)
- **열어 본 사본이 이상할 때**
  - 옛 저장 형식(v3 이하): 있는 그대로 보이고 머리에 형식 번호를 적는다. 옮기기(migrate)는 하지 않는다. v4 칸(회원·낸 분)이 없으면 그 표는 비운다.
  - 풀었는데 JSON 이 아니거나 장부 모양이 아니면: "풀었지만 기록 파일 형식이 아니에요"를 보이고 겉 정보만 남긴다.
- **큰 사본** (이모 장부처럼 내역이 천 줄 넘음): 표는 300줄, 비교는 120줄까지 그리고, 거르기로 좁혀 보게 한다.
- **미리보기 자리**(`preview:`)는 보지 않는다. 서버는 본 주소 출처로만 부른다.
- **클론이 오래됐을 때.** 도구는 백업 레포를 `git pull` 하지 않는다(읽기만). 클론을 마지막으로 받아 온 때가 8일 넘었으면 위에 "백업 레포를 먼저 받아 오세요(`git pull`)"를 한 줄 보인다.
  - 받아 온 때는 `git fetch`·`pull` 이 받을 때마다 다시 쓰는 `.git/FETCH_HEAD` 의 수정 시각이다. 주간 워크플로는 바뀐 게 없으면 커밋하지 않으므로, 마지막 커밋 시각으로 재면 막 `git pull` 한 클론도 오래돼 보인다.
  - 받아 온 적 없는 새 클론(`FETCH_HEAD` 없음)은 마지막 커밋 시각으로 본다.

## 수용 기준

- [ ] AC-1 도구를 켜면 `127.0.0.1` 에만 열리고, `Host` 가 `127.0.0.1:<포트>`·`localhost:<포트>` 가 아닌 요청은 거절한다 (자동)
- [ ] AC-2 사본 목록: 백업 레포 `index.json`·커밋 이력과 서버 사본 목록으로 기기별 최신본·날짜별·달별·주간 사본을 시각·크기와 함께 만든다. `devices.json` 이름을 붙이고, 없으면 "이름 없음"으로 둔다 (자동, 가짜 서버·임시 git 레포)
- [ ] AC-3 `KEEP_URL` 없음·서버 연결 실패·예전 서버·클론 없음·클론이 오래됨이면 그 출처만 빼고 안내 한 줄을 보인다 (자동)
- [ ] AC-4 겉 정보는 코드 없이 보이고, 사본 종류마다 있는 곳·남는 기간·1MB 대비 %가 맞다 (자동)
- [ ] AC-5 코드를 넣으면 페이지 안에서 id 를 계산해 맞는 기기만 풀린다. 틀리면 거절 문구와 그 코드의 id 앞 8자를 보인다. 로컬 서버로 가는 어떤 요청에도 코드가 없다 (자동)
- [ ] AC-6 코드로 열기: 목록에 없는 기기도 코드로 id 를 계산해 서버 사본을 연다 (자동)
- [ ] AC-7 구조: 나무의 개수·크기와 칸 채움 표가 저장 데이터와 맞고, 복구 코드는 가린다 (자동)
- [ ] AC-8 표: 다섯 표의 줄·칸, 장부·해 거르기, 찾기, 정렬, 300줄 제한과 줄 수가 맞다 (자동)
- [ ] AC-9 비교: `id` 로 맞춘 더해진·빠진·바뀐 줄과 바뀐 칸, 회원 변화, 해별 남은 돈 차이가 맞다 (자동)
- [ ] AC-10 옛 저장 형식, 풀었지만 장부가 아닌 사본, 사라진 사본에서 멈추지 않고 문구를 보인다 (자동)
- [ ] AC-11 실제 서버와 백업 레포로 켜서, 코드 없는 기기의 겉 정보와 받은 코드로 연 기기 하나의 표·비교를 본다 (수동 QA — 복구 코드를 받은 뒤)

## 범위 밖

- 쓰기·지우기·되살리기·기록 파일 만들기(`keep-rescue` 그대로)
- 상태 신호(평문) 보기. 지켜보기 요약에서 본다. 요약 토큰을 이 도구에 주지 않는다.
- 미리보기 자리, 복구 코드 저장(키체인 등), 폰에서 보기, 남과 함께 보기
- 그래프 같은 그림, 해별·월별 모아 보기(열린 질문)

## 기술 메모

- **파일**
  - `scripts/keep-view.mjs`: Node 24 로컬 서버. 의존성 없이 `node:http`, `node:child_process`(git), `fetch` 를 쓴다.
  - `scripts/keepView.ts`: 순수 함수(사본 목록 합치기, 겉 정보, 구조 나무·칸 채움, 다섯 표 만들기, 비교). vitest `scripts/keepView.test.ts` 로 시험하고, 루트 `npm test` 에 같이 돈다.
  - `scripts/keep-view/index.html`: 페이지. 디자인은 시안의 개발자 도구 모양을 따른다. 큰 글씨 규칙(`docs/design.md`)은 사용자 화면 기준이라 이 도구에는 적용하지 않는다.
  - `keepWatch.ts`·`keepRescue.ts` 와 같은 제약을 지킨다: 타입 지우기로 없어지는 문법만 쓰고, 다른 패키지나 `src` 를 불러오지 않는다.
- **풀기**
  - `keepRescue.ts` 의 `normalizeRecoveryCode`·`keepIdOf`·`openKeep` 을 그대로 쓴다. 이 함수들은 Web Crypto 라 브라우저에서도 같다.
  - 브라우저는 `127.0.0.1` 을 안전한 출처로 보므로 `crypto.subtle` 을 쓸 수 있다.
- **페이지에 TS 보내기**: 로컬 서버가 `node:module` 의 `stripTypeScriptTypes` 로 `keepView.ts`·`keepRescue.ts` 의 타입을 지워 `text/javascript` 로 보낸다(`GET /keepView.ts`·`/keepRescue.ts`). 빌드는 없다.
  - #205 기술 확인: Node 24.14 에서 지운 두 파일이 브라우저(크롬)에서 ES 모듈로 불리고, 페이지가 `normalizeRecoveryCode`·`keepIdOf`·`openKeep` 으로 앱이 만든 보관본을 푼다.
  - 이 함수는 Node 24 에서 실험 기능이라 처음 부를 때 `ExperimentalWarning` 이 한 번 찍힌다. **그대로 둔다**: 켤 때 두 파일을 한 번만 지워 두므로 켤 때 한 줄뿐이고, 숨기려면 프로세스 경고 처리를 건드려 다른 경고까지 가릴 수 있다. 함수가 바뀌면 켤 때 바로 멈춘다(요청 중이 아니라).
- **로컬 서버 경로**
  - `GET /`: 페이지
  - `GET /api/devices`: 기기와 사본 목록
  - `GET /api/history?id=<64자>`: 코드로 열기
  - `GET /api/copy?id=<64자>&kind=latest|day|month|week&key=<날|달|커밋>`: 겉봉투
  - 모든 응답에 `Cache-Control: no-store` 를 붙이고, `Host` 를 검사한다(DNS rebinding 막기). id·날·달·커밋은 형식을 검사한 뒤에만 쓴다(git 인자에 아무 글자나 넘기지 않음).
  - 페이지가 이 맥 밖으로 아무것도 보내지 못하게 CSP(`connect-src 'self'`, `form-action 'none'`)를 붙인다. 외부 글꼴·스크립트는 쓰지 않는다.
- **서버 부르기**: 꺼내기 스크립트처럼 `Origin: https://crowwan.github.io` 를 붙여 본 자리만 읽는다. 서버 목록에는 크기가 없어서, 사본마다 GET 하나로 크기를 잰다(꺼내기 `--list` 와 같다). 그 GET 이 404 면 그 줄에 "목록을 받은 사이 서버에서 사라졌어요".
- **주간 사본**: `git -C <클론> log --format=%H%x09%cI --diff-filter=AM -- keep/<id>.json` 으로 목록을 만들고(파일이 생기거나 바뀐 커밋만, [지우기]로 지운 커밋은 뺀다), 크기는 `git cat-file --batch-check` 한 번으로, `git -C <클론> show <커밋>:keep/<id>.json` 으로 본문을 읽는다. `index.json`·`devices.json` 도 커밋된 것(`git show HEAD:…`)을 읽고, 클론을 받아 온 때는 `git rev-parse --git-path FETCH_HEAD` 파일의 수정 시각(없으면 `git log -1 --format=%cI`). git 은 `GIT_CEILING_DIRECTORIES` 로 클론 자리 밖의 레포를 읽지 않는다.
- **비교 기준**
  - 내역은 `Entry.id`, 회원은 장부 id + `Member.id` 로 맞춘다. `id` 가 없는 줄은 맞출 수 없어 뺀다.
  - 바뀐 칸으로 보는 것은 `month`·`day`·`type`·`name`·`amount`·`payers`·`sourceText` 다. 값은 JSON 으로 견준다(낸 분은 순서까지). 적은 때(`createdAt`)·사진 묶음(`batchId`)만 바뀐 줄은 바뀐 줄이 아니다.
  - 같은 `id` 의 줄이 다른 장부(장부 id)나 다른 해(`ledgers` 키)로 옮겨 갔으면 바뀐 줄이고, 장부·해도 바뀐 칸(`앞 → 뒤`)으로 보인다. 숫자가 아닌 해 키의 줄은 날짜를 잴 수 없어 같은 무리(빠짐·바뀜·더해짐) 맨 뒤에 둔다.
  - 해별 남은 돈 = 이월금 + 수입 − 지출(그 해 내역). 장부 id + 해로 맞추고, 한쪽 사본에만 있는 해도 보인다(없는 쪽은 —).
- **구조·표·비교 함수** (#206): 나무 `storedTree`·칸 채움 `entryFill`·다섯 표 `buildTables`·거르기·찾기·정렬 `queryTable`·사본을 바꿀 때 거르기 되돌리기 `fitTableFilter`·비교 `compareCopies`·처음 앞뒤 `defaultPair` 는 `keepView.ts` 의 순수 함수이고, 페이지는 그리기만 한다. 저장 데이터는 `src` 의 타입을 불러오지 않고(브라우저로 보내는 파일이라) 칸마다 모양을 봐서 있는 칸만 읽는다.
- **풀린 사본의 메모리** (#206): 비교가 같은 사본을 다시 풀지 않게 풀린 사본을 그 탭 메모리에만 기억하고, [잠그기] 하면 그 기기의 풀린 사본·고른 줄·그린 표·비교를 모두 잊는다. 사본을 받거나 푸는 사이에 [잠그기] 했으면 풀기가 끝나도 그 결과를 버린다. 사본을 고르는 쪽과 비교가 같은 사본을 동시에 받으면 로컬 서버에는 한 번만 묻는다(받는 중인 답만 같이 쓰고, 다 받으면 잊는다 — 고를 때마다 새로 받는다).
- **PR 나눔**

  - ② 구조, 표, 비교 (AC-7~9)
